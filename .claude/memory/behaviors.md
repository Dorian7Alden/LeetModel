# 行为习惯

> 用户在对话中反复体现的行为模式。

---

## 沟通方式

- 用户会频繁与 AI 交流想法、纠正行为，这些纠正中的解释和原因非常关键
- 用户的说明有时不是"最佳实践"，是用户理解下的局部最佳实践
- AI 应一方面遵循用户说明，一方面提出更好方案供参考

**适用场景**：每次对话交互中

---

## 工作节奏

- 单次会话专注一个任务，不并行
- 分步迭代，小步快跑，确认后再推进
- 不接受一次性输出大量未经确认的内容

**适用场景**：任何开发任务的执行过程

---

## 规划偏好

- 先做规划，等用户确认后再执行
- 规划内容要清晰、有结构，方便 review
- 纠正和反馈要立即响应并调整方案

**适用场景**：收到新任务、进入 plan 模式时

---

## 上下文探索：Agent 化五阶段管道

- 上下文加载不是主 Agent 自己手动逐层遍历文档树，而是派发专门的 Context Explorer Agent 来完成
- Context Explorer Agent 按五阶段管道执行：Map → Select → Deep-read → Curate → Output
- **Map**：一次性加载 docs/ 下全部 README.md，建立完整文档地图
- **Select**：根据任务主题从地图中筛选相关文档
- **Deep-read**：深入读取筛选出的文档，按文档类型区分关注重点
- **Curate**：对读取内容进行抉择与剪枝，保留必须的、丢弃无关的、合并重复的
- **Output**：输出结构化上下文摘要，作为 Agent 间传递的信息载体
- 不同职责由不同 Agent 承担，Agent 之间通过结构化摘要传递信息
- 核心原则：以实际目录内容为准，不以索引为准。目录本身才是权威

**原因**：手动逐层遍历效率低且容易遗漏，Agent 化的管道设计让上下文加载更加系统化和可靠。先建立全局视野再精准深入，最后精炼剪枝，确保传递给主 Agent 的上下文既精炼又完整。

**适用场景**：每次收到任务后的上下文加载阶段

---

## 主动性与边界

- Agent 发挥主观能动性的方式：主动遍历上下文、主动思考方案、主动提出建议和澄清问题
- Agent 不主动扩展任务范围——完成用户指定的任务，不擅自执行"额外觉得值得做"的事
- 主动是为了更好地完成用户给定的任务，而非替用户决定做什么

**适用场景**：每次任务协作中

例外：CLAUDE.md 第 3.4 节要求的收尾沉淀是任务的标准闭环步骤，属于任务本身的组成部分，不是额外的任务扩展。任何任务完成后必须执行。

---

## 任务收尾纪律

- 每个任务完成后，必须执行收尾沉淀：检查是否有新设计决策、架构变更、排查记录、学习心得、概念文档或用户偏好需要落库
- 收尾沉淀不是可选步骤，是任务的组成部分 —— 未沉淀的任务不算结束
- 即使是"无需沉淀"的轻量任务，也要在收尾报告中显式声明"本次无需沉淀"，不允许沉默跳过
- 收尾报告是任务完成的唯一标志 —— 在收尾报告输出之前，任务仍在进行中

**原因**：没有收尾沉淀，每次对话的知识产出会丢失。项目文档和 memory 会逐渐与实际代码脱节，后续任务的上下文质量持续下降。
**适用场景**：每个任务会话结束前

---

## 动态规划协作

- 任务规划不是一次性 TODO List，而是一个动态的塑形过程
- 用户确认执行前，描述和需求可持续调整——方案跟随用户输入动态更新
- 完成一个任务需要多少步骤是未知的，由对话过程自然决定，不预设步数
- 用户描述足够清晰时直接开始执行，不增设不必要的确认环节
- 执行中新发现的信息可触发方案回调和调整

**适用场景**：任务规划与执行阶段
