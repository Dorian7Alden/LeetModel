# 题库检索索引启动自举未触发

> 影响范围：problem-service 题库全文检索索引初始化

## 报错现象

索引被删除后重启 problem-service，启动日志没有“题库索引首次创建并完成重建”，Elasticsearch 中也没有对应索引；直接调用管理端重建接口又能正常创建索引并写入文档。

补充启动分支日志后可以看到明确结论：服务认为“索引已存在”，而 `curl -I http://127.0.0.1:9200/leetmodel-problem-v1` 返回 404。

## 根因分析

索引存在性检查使用 Elasticsearch 低层 REST 客户端的 `HEAD /{index}`，并依赖“索引不存在时客户端抛出 `ResponseException`”这一假设。实际上低层客户端在 `RestClient.getIgnoreErrorCodes` 中对 `HEAD` 请求固定忽略 404，`performRequest` 会正常返回一个状态码为 404 的响应而不是抛异常，因此存在性判断恒为“索引存在”，启动自举被跳过。

## 修复方案

索引存在性判断改为显式比较响应状态码：

```java
Response response = client.performRequest(new Request("HEAD", "/" + properties.getIndexName()));
return response.getStatusLine().getStatusCode() != 404;
```

同时把“检查索引是否存在”和“重建索引”的职责拆开：启动阶段只在索引缺失时触发全量重建，管理端重建接口负责删除并按最新映射重建，避免启动时先建后删的重复动作。

## 回归验证

- 删除索引后重启服务：日志出现一次“题库索引已创建”和一次“题库索引首次创建并完成重建: indexed=34”。
- 索引已存在时重启服务：不触发重建，关键词检索仍然可用。
- 重建接口与启动自举使用的索引名、映射完全一致，`GET /leetmodel-problem-v1/_count` 数量与数据库未删除题目数一致。
