# bash 环境下 Windows 反斜杠路径写出字面量文件名

---

## 报错现象

批量生成 `knowledge-base/` 知识库笔记时，部分文件未出现在目标目录树中，而是在仓库根目录下多出一个名为 `C:` 的目录，内部文件名为完整路径字符串的字面量，如：

```text
C:C:\Users\Dan\repo\LeetModel\knowledge-base\common-pitfalls\摘要空话套话.md
```

同时多个目录的 `README.md` 因文件名碰撞被互相覆盖，目标目录树中出现文件错位：`common-pitfalls/` 下混入了本应属于 `review-standard/`、`modeling-methods/`、`writing-quality/` 的笔记。

---

## 根因分析

会话运行在 bash 环境，但写文件时使用了 Windows 风格的绝对路径 `C:\Users\...\knowledge-base\...`。bash 不将反斜杠视为路径分隔符，反斜杠被当作普通字符或转义前缀处理，整段路径退化为一个不含目录层级的字面量文件名，于是文件被创建在当前目录下，路径中的目录结构信息全部丢失。多个不同目录下的同名 `README.md` 因此坍缩为同一个字面量目标，后写的覆盖先写的。

---

## 修复方案

1. 将全部错位文件按文件名中携带的原始路径信息归位到真正的 `knowledge-base/` 目录树下。
2. 重建因碰撞被覆盖的各层 `README.md` 索引，依据笔记现存的摘要字段重写。
3. 删除根目录下残留的 `C:` 字面量目录。

预防措施：在 bash 环境中读写文件一律使用正斜杠路径，优先使用相对于仓库根目录的相对路径；批量写入后用 `find` 校验实际落盘位置与预期目录树一致，再进入下一批。
