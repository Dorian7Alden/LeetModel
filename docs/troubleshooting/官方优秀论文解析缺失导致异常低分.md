## 官方优秀论文解析缺失导致异常低分


### 故障现象

2026 年 9 月 16 日，队伍 `AI评审官网样本-20260915-162620` 的
`submission-01.pdf` 是 31 页官方优秀论文，但首次 V3 正式评审只有 `25.70/100`。
报告大量声称摘要、问题分析、假设、符号说明、核心公式和结果缺失，而原 PDF 明确包含这些内容。


### 根因

故障不是单点问题，而是四层内容丢失叠加：

1. 原 PDF 是纯图片型扫描文档，PDFBox 无法提取任何文本；视觉窗口失败时，本地降级没有内容可用。
2. 首页摘要与目录的双页视觉输出达到旧配置的 `4096` Token 上限，JSON 被截断；旧代码仍允许不完整产物进入后续链路。
3. 视觉模型和仲裁模型会把可选对象写成 `"figure": true/false`。旧反序列化器只接受对象或 `null`，仲裁失败后又无条件回退到前序窗口 A，导致 A 为空、B 有内容时整页被主动丢弃。
4. V3 阶段一和阶段二只用中文关键词匹配章节。英文标题
   `Problem Restatement and Analysis`、`Notations`、`Assumptions` 无法识别；
   规划器返回的 `suggestedSectionIds` 又未进入 Java DTO，Q1 最终退化为固定抓取第 1-4 页，
   没有读取第 9-12 页的 Archard 方程、贝叶斯反演和计算结果。

此外，隔离评审入口错误地把 V3 绑定到 V1 多模态执行配置，曾阻断真实质量复验。


### 修复

- 新增 `MODEL_CFG_PAPER_PARSE_MULTIMODAL_0002`，双页视觉输出预算提升到 `8192` Token；
  幂等键包含执行配置版本，防止新配置命中旧的截断结果。
- 窗口缓存和实时响应统一经过 `PaperParseV2ResponseParser`；
  可选对象字段的布尔值统一规范化为 `null`。
- 仲裁失败时选择信息量更完整的非空版本，不再固定回退版本 A。
- 新增 V2 页级质量门：正文不能为空、首尾页必须覆盖、总体缺页率不得超过 5%；
  历史 `PARTIAL_SUCCESS` 产物复用前也执行同一质量校验。
- 阶段一和上下文装配支持中英文问题分析、假设、符号、灵敏度章节；
  章节切片扫描到同级或更高级标题才结束。
- `SubTaskPlanDTO` 增加 `suggestedSectionIds`，服务端优先校验并转换规划器返回的章节 ID，
  上下文区间按尾块排他规则提取。
- V1、V2、V3 隔离评审分别绑定各自不可变模型执行配置。


### 验收结果

- 修复后 `PAPER_DOCUMENT_V2` 为 `SUCCESS`，31/31 页可读、0 空白页、429 个内容块、77 个章节、
  42 个公式、4 个表格。
- 首页恢复 11 个内容块，目录页恢复 9 个内容块，第 27 页代码块保留。
- 第一轮仅修复解析和阶段一切片后，隔离 V3 从 `25.70` 恢复到 `47.70`。
- 补齐规划章节 ID 和阶段二上下文后，隔离 V3 最终为 `74.00`；
  Q1 证据定位到第 10-11 页的 `B118`、`B130`、`B139`、`B146`。
- 目标样本正式派生结果已更新为 `74.00`，阶段一 `19.50`、阶段二 `54.50`；
  排行榜当前快照同步为 `74.00`，旧 `25.70` 快照仅保留为非当前历史批次。


### 经验

AI 论文评审不能只校验“JSON 可解析”和“内容块非空”。必须同时校验页级覆盖、首尾页、
工作流执行配置、规划锚点是否真正进入 DTO，以及下游切片是否覆盖规划章节。
对于扫描型 PDF，本地文本降级为空时应直接失败，不能把缺失论文证据解释为论文质量问题。


### V4 报告二次排障与修复

#### 故障现象

解析恢复后，V4 评审与建议仍出现以下用户可见问题：

1. 前端或后端说明字段被省略号截断，公式和表格内容无法完整核对。
2. “原文依据”与当前问题错位，部分证据来自其他解析版本或错误的记忆证据。
3. 改进建议漏掉评审问题、重复引用同一问题，或把多个问题混入同一条。
4. 历史建议任务的 `retrieval_workflow_version` 为空，知识检索返回 `40001`。
5. 模型把绑定评审 `ISSUE` 的候选标成可选探索，主观建模问题还会输出指定的替代算法路径。
6. 论文解析产物中的 HTML 表格单元格公式以 `$...$` 原文显示，没有进入 KaTeX。

#### 根因

- V4 报告取证阶段没有严格锁定当前评审对应的 `PAPER_DOCUMENT_V2`，
  原文块与 Finding 之间缺少完整的一一绑定。
- 前端和组装器存在最大长度二次截断；论文块本身虽完整，展示契约仍会丢内容。
- 建议报告先信任模型候选，再检查评审问题覆盖。模型漏项或重复时整份报告失败，
  且候选可以绕过必要的类型校正。
- 历史任务的检索版本列可能为空，知识服务按 `@NotBlank` 拒绝请求。
- 主观建模建议缺少服务端硬约束，模型容易输出具体替代模型、算法或求解路径。
- Markdown 渲染器只处理 Markdown 语法，不会进入解析器直接输出的原始 HTML 表格。

#### 修复

- V4 评审证据固定使用当前任务锁定的解析产物，按真实 `blockId` 生成完整
  Markdown 原文和内容哈希；前后端均取消静默省略号截断。
- 评审与建议共享同一组 Finding 证据规则，修复图片块识别、证据极性、
  原因引用和知识依据主题匹配。
- 建议服务按锁定评审问题建立确定性槽位：每个问题保留至多一个候选，
  漏项生成同主题、同证据的保守兜底，重复引用去重，最终要求一一覆盖。
- 服务端强制“引用 `ISSUE` / `WEAKNESS` 的候选必须为 `REQUIRED_FIX`”。
- 对反演欠定、参数不可辨识、病态或循环依赖等主观建模问题，
  报告只补充未知量、约束、可辨识性和适用边界，不进入模型给出的替代路径。
- 建议任务遇到空检索版本时按工作流选择回退版本，并在检索成功后写回实际版本。
- 前端统一 Markdown 渲染链路增加原始 HTML 表格内联公式处理；
  评审说明中的评分影响与独立评分字段去重。

#### 验收结果

- 官方优秀论文 V4 评审完成，评分 `73.8`，包含 5 个问题和 3 个优点。
- 5 个锁定问题均能在报告中展开对应锁定解析块，原文无省略号截断。
- 最终建议任务包含 9 条建议：5 条 `REQUIRED_FIX` 与 4 条
  `OPTIONAL_EXPLORATION`；5 个评审问题各出现一次，必要修正排在可选探索之前。
- 每条必要修正只绑定一个 Finding，并继承该 Finding 的完整论文证据 ID。
- 真实浏览器中正文公式、公式块和原始 HTML 表格内公式均由 KaTeX 渲染，
  未发现外部图片、获奖承诺、唯一模型要求或跨主题混写。
