## v1 - 鉴权管理



### 模块定位

鉴权管理是 v1 的基础能力模块，负责确认“访问者是谁”与“访问者能做什么”。

该模块为后续用户管理、文件管理、标签管理、题目管理提供统一的身份与权限前置保障。



### 设计目标

1. 提供稳定可用的账号注册与登录能力，保障用户可持续进入平台。
2. 建立基于 JWT 的无状态身份认证机制，降低会话管理复杂度。
3. 建立清晰的授权边界，普通用户仅访问个人数据，管理员可访问全量后台管理数据。
4. 建立统一的异常处理与响应语义，保证前后端联调与后续扩展的一致性。



### 角色与权限边界

#### 访问角色

- 游客：未登录状态，仅可访问公开页面与登录注册入口。
- 普通用户：登录后可访问个人中心、个人资源与业务页面。
- 管理员：在普通用户能力之上，具备后台管理能力。


#### 边界原则

- 默认拒绝：未显式放行的受保护资源默认不可访问。
- 最小权限：角色仅获得完成职责所需的最小权限集。
- 同源一致：同一资源在不同入口下的权限判断结果必须一致。



### 功能描述

#### 账号注册

功能目标：让新用户以可验证身份完成账号创建。

实现要点：

1. 校验注册输入完整性与基础合法性。
2. 校验账号唯一性，避免重复注册。
3. 完成凭证安全处理后创建账号，并初始化默认角色与默认状态。
4. 返回统一成功或失败响应，不暴露内部错误细节。

典型结果：注册成功后，用户可直接进入登录流程。


#### 用户登录

功能目标：在合法凭证通过验证后发放身份令牌。

实现要点：

1. 校验登录输入完整性与基础合法性。
2. 校验账号状态与凭证有效性。
3. 签发令牌并返回必要用户上下文。
4. 对失败场景进行精确区分（参数错误、账号不存在、凭证不正确、账号不可用等）。

典型结果：登录成功后，前端进入已认证会话状态。


#### 身份认证

功能目标：对受保护资源请求进行身份真实性判定。

实现要点：

1. 统一从请求上下文提取身份令牌。
2. 校验令牌完整性、签名合法性、有效期与失效状态。
3. 认证通过后将身份上下文注入当前请求处理链。
4. 认证失败则中断请求并返回统一错误语义。

典型结果：仅合法会话可访问受保护资源。


#### 授权控制

功能目标：确保访问行为与角色权限一致。

实现要点：

1. 在认证通过后执行角色级权限判定。
2. 对个人数据场景执行“资源归属校验”。
3. 对后台管理能力执行管理员权限校验。
4. 对越权访问统一拒绝并记录审计日志。

典型结果：普通用户无法访问管理员能力，管理员可访问全量管理能力。


#### 退出登录与会话失效

功能目标：主动终止会话，降低令牌滥用风险。

实现要点：

1. 接收退出动作后将当前令牌置为失效状态。
2. 采用“短期令牌 + 失效名单”机制处理已签发令牌回收。
3. 失效状态与令牌剩余有效期保持一致，避免长期存储无效记录。

典型结果：用户退出后原令牌不可继续访问受保护资源。



### 实现方法

#### 参数校验策略

- Controller 层使用 ParameterValidator 链式校验完成参数完整性、长度、范围、语义校验。
- Request DTO 不依赖 Bean Validation 注解体系。
- 复杂参数校验失败时聚合错误信息，统一走业务异常与统一响应结构。


#### 凭证与令牌策略

- 令牌类型采用 JWT，载荷仅放必要身份信息与授权判定所需字段。
- 令牌默认短有效期，降低泄露后风险窗口。
- 敏感业务可在后续版本叠加会话风控校验，不影响 v1 主链路。


#### 授权判定模型

- 第一层：身份认证是否通过。
- 第二层：角色权限是否满足目标操作。
- 第三层：资源归属是否匹配当前用户。

三层全部通过才允许访问。


#### 异常与响应策略

- 所有鉴权相关错误统一归入鉴权模块编码段（x01xx）。
- 对外错误语义稳定且可读，对内通过日志保留完整上下文。
- 所有响应统一使用 Result 结构，避免返回结构分裂。


#### 安全与审计策略

- 记录关键审计事件：登录成功、登录失败、认证失败、越权访问、退出登录。
- 日志中不输出完整敏感凭证，仅保留必要追踪信息。
- 对高频失败行为保留后续接入限流与风控能力的扩展点。



### 实现流程

#### 主流程：登录后访问受保护资源

1. 用户提交登录信息。
2. 服务端执行参数校验与凭证校验。
3. 校验通过后签发身份令牌并返回登录结果。
4. 用户携带令牌访问受保护资源。
5. 服务端执行令牌合法性校验并构建身份上下文。
6. 服务端执行角色与资源归属授权判定。
7. 判定通过则返回业务数据。


#### 分支流程：退出登录

1. 用户发起退出动作。
2. 服务端校验当前会话并登记令牌失效状态。
3. 后续请求命中失效状态时直接拒绝访问。


#### 分支流程：鉴权失败回路

1. 任一环节失败（参数、凭证、令牌、权限、归属）立即中断。
2. 返回统一响应结构与对应业务错误码。
3. 记录审计日志，供排障与风控分析使用。



### 验收标准

1. 功能完整：注册、登录、认证、授权、退出登录均可独立验证通过。
2. 边界清晰：普通用户无法访问管理员能力，越权访问均被稳定拒绝。
3. 一致性：鉴权失败场景全部返回统一响应结构与模块内错误码。
4. 可追踪：关键鉴权事件均有可检索日志。
5. 可扩展：后续可平滑增加风控、刷新令牌、细粒度权限，不破坏现有主流程。



### 非目标范围

以下能力不纳入 v1 鉴权管理交付：

1. 第三方登录体系。
2. 多因子认证。
3. 细粒度策略引擎级权限体系。
4. 复杂设备指纹与高级风控模型。
