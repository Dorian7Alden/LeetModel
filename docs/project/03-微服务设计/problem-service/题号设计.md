# 题目题号设计（短顺序编号）

> 创建日期：2026-08-27
> 属于：`problem-service`

## 关键依据（领域特征）

数学建模题目量非常有限：

- 全量历史题目通常不会超过 10000 道。
- 每年全部赛事新增题目合计通常不超过 100 道。
- 年代久远的题目参考价值低，用户实际可练习的题目数量非常有限。

因此题号不需要承担“海量数据”的容量假设。早期实现直接暴露内部雪花主键（19 位数字），导致所有页面展示的“题号”非常长，严重影响使用。

## 设计决策

题目对外展示使用**短顺序编号（`code`）**，而不是内部雪花主键。

| 字段 | 说明 |
|------|------|
| `id` | 内部主键，雪花算法生成，仅作为稳定标识 / URL 参数 / 服务间引用，**不面向用户展示**。 |
| `code` | 面向用户的“题号”，短顺序编号，从 `1001` 起始，上限 `10000`，唯一。 |

### 生成规则

```text
next = max(existing code) + 1，起始 1001
若 next > 10000 → 抛出业务错误 40409（题目题号已达上限）
```

题目量有限（<= 10000），该上限实际不会触发；若未来题目规模大幅增长再重新评估。

### 展示约定

所有“题号”展示都使用 `code`：

- 题目详情：`题号：{problem.code}`
- 队伍详情 / 队伍卡片 / 队伍广场 / 创建队伍：`题号 {team.problemCode}`
- 提交历史 / 提交详情：`题号 {submission.problemCode}`
- 管理端题目列表：`题号` 列展示 `problem.code`

### 跨服务透传

- `problem-service`：`ProblemVO.code`
- 内部契约：`ProblemPracticeDTO.code`、`ProblemOptionDTO.code`
- `team-service`：`TeamVO.problemCode`（来源于 ProblemPracticeDTO）
- `submission-service`：`SubmissionVO.problemCode`（通过 ProblemFeignClient 批量取题号）

### 边界与一致性

- `code` 为整数、唯一，逻辑软删除不释放题号。
- 用户创建题目时由后端自动生成，客户端不可指定。
- 题目更新不允许修改 `code`。
- 历史存量题目通过 `V7__add_problem_code.sql` 迁移按 `id` 升序回填 `1001..`，无需改动跨服务引用（内部主键不变）。
