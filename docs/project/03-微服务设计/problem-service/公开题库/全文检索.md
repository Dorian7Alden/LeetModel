## 全文检索

### 功能目标

在公开题库的关键词查询中提供标题与题面的分词检索和相关度排序，同时保证检索组件不可用时题库查询仍然可用。

### 定位与边界

- `lm_problem` 是题目事实源，Elasticsearch 只保存题目检索副本，不承载任何业务写入的权威结果。
- 关键词查询命中后，返回给调用方的题目字段仍然按命中顺序从数据库读取，检索只决定“召回哪些题目”和“排序如何”。
- 检索不可用、索引缺失或查询超出结果窗口时，退回既有的动态 SQL 查询（标题 `LIKE` 加结构化条件），接口不报错。
- 结构化条件（赛事、年份、语言、难度、标签）既可以在检索侧过滤，也可以在 SQL 侧过滤；未传关键词时始终走 SQL。
- 检索与现有结构化动态筛选共存，不替换筛选规则，也不引入向量语义检索；知识库 RAG 的向量召回仍由 `knowledge-retrieval-service` 与 `ai-assistant-service` 独立负责。

### 索引结构

索引名称由 `problem.search.index-name` 配置，默认 `leetmodel-problem-v1`，与知识库 RAG 索引共用同一个 Elasticsearch 实例但物理隔离。

| 字段 | 类型 | 说明 |
|------|------|------|
| `problemId` | long | 题目主键，同时作为文档 `_id` |
| `code` | integer | 面向用户展示的短题号，用于稳定排序 |
| `problemNumber` | keyword | 赛事内题号 A-F 或 X |
| `title` | text（`cjk` 分词） | 标题，检索权重 2 |
| `content` | text（`cjk` 分词） | Markdown 题面，检索权重 1 |
| `contestId` | long | 赛事过滤 |
| `year` | integer | 年份过滤与次级排序 |
| `difficulty` | integer | 难度过滤 |
| `statementLanguage` | keyword | 题面语言过滤 |
| `tagIds` | long | 标签标识列表，按“同时命中全部标签”过滤 |
| `status` | integer | 发布状态过滤 |
| `updateTime` | date | 文档时间戳，格式 `yyyy-MM-dd HH:mm:ss\|\|strict_date_optional_time\|\|epoch_millis` |

中文分词使用 Elasticsearch 内置 `cjk` 分析器，不需要安装额外插件；英文与数字继续走标准分词。`updateTime` 必须显式声明平台统一时间格式，否则按默认严格格式解析会拒绝写入。

### 查询语义

- 关键词使用 `multi_match`，字段为 `title^2` 和 `content`，匹配类型为 `best_fields`，标题命中优先级高于题面命中。
- 结构化条件使用 `filter` 子句，与关键词评分解耦；多个标签各生成一个 `term` 条件，保持与 SQL 侧一致的 AND 语义。
- 排序为 `_score` 降序、`year` 降序、`code` 升序，保证同分结果顺序稳定。
- `from + size` 超过 `problem.search.max-result-window`（默认 1000）时不做检索，直接降级到 SQL，避免深度分页。
- 检索返回的题目标识按批量查询从数据库取回，保持检索给出的顺序；索引中已过期但数据库已不存在的标识会被过滤掉。
- 关键词查询不进入三级缓存，响应按 `no-store` 处理，避免高频关键词制造高基数缓存 Key。

### 索引同步

| 场景 | 行为 |
|------|------|
| 服务启动且索引不存在 | 读取数据库快照做全量重建，日志记录 `题库索引首次创建并完成重建: indexed=...` |
| 服务启动且索引已存在 | 不做任何写入，直接使用现有索引 |
| 创建题目 | 事务提交后按题目主键写入或覆盖文档 |
| 更新题目或题目标签 | 事务提交后重建该题文档 |
| 删除题目 | 事务提交后按题目主键删除文档 |
| 管理端全量重建 | `POST /api/problems/search-index/rebuild`（管理员权限）删除并按最新映射重建索引，返回成功写入的文档数 |

同步动作统一放在事务提交后执行，避免数据库回滚后留下脏文档。增量同步失败只记录告警并保留数据库事实，由全量重建补偿，不阻断题目写入。

### 配置项

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `problem.search.enabled` | `true` | 关闭后不装配检索组件，全部查询走 SQL 降级 |
| `problem.search.elasticsearch-uri` | `http://127.0.0.1:9200` | Elasticsearch 地址 |
| `problem.search.index-name` | `leetmodel-problem-v1` | 题库索引名 |
| `problem.search.max-result-window` | `1000` | 单次检索最大 `from + size` |

### 降级与异常

- 检索请求抛出 IO 或运行时异常时记录告警 `题库全文检索不可用，降级到数据库查询`，并返回空结果给调用方，由调用方继续执行 SQL 查询。
- 命中为空与检索不可用是两种结果：命中为空返回空分页，检索不可用返回 `null` 触发降级。
- 单条文档写入失败不会中断其余文档写入，全量重建返回的是实际写入成功的文档数。

### 与外部组件的关系

- 复用 `compose.yaml` 中已有的 `leetmodel-elasticsearch`（Elasticsearch 8.14.3），题库索引与 RAG 索引分开命名、互不覆盖。
- 客户端使用低层 REST 客户端 `elasticsearch-rest-client`，版本与平台 Elasticsearch 服务端保持同代。

### 验收要点

- 未创建索引时启动服务，索引自动创建并完成全量重建，数量与数据库中未删除题目数一致。
- 关键词同时命中标题与题面时按相关度返回，标题命中排在题面命中之前。
- 关键词与赛事、年份、难度、标签组合过滤同时生效。
- 创建、更新、删除题目后索引与数据库状态一致，删除的题目不再被关键词命中。
- Elasticsearch 停机、索引缺失或超出结果窗口时，公开题库仍返回 SQL 查询结果，接口状态码不变。

### 已知风险与处理

- 低层客户端对 `HEAD` 请求的 404 不抛异常，索引存在性判断必须显式比较状态码，否则启动时不会触发索引自举。
- 索引结构变更需要重建索引才能生效，映射调整后应调用全量重建接口或删除索引后重启。
- 检索结果包含未发布题目时，过滤条件必须始终携带发布状态，公开接口不允许出现未发布题目。
