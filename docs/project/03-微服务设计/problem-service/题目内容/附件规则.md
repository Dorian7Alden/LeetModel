## 附件规则

### 归属与数量

- 附件是题目的从属数据，每个附件只属于一道题目。
- 一道题目可以没有附件，也可以拥有多个附件。
- 业务上不假设附件只有一个。
- 题目附件可以是数学建模题目配套的大数据文件，其大小无法预先确定。problem-service 不设置固定的业务层单文件大小上限。
- 题目附件不得复用论文 PDF 的 20MB 上限。对象存储容量、协议和部署环境存在的技术边界不得固化为题目附件的业务大小限制。

### 附件信息

problem-service 维护附件的题目归属、原始文件名、对象存储路由、媒体类型、文件大小、附件说明和展示顺序。

对象存储路由只用于服务内部定位附件。公开题目详情返回附件说明和短时效下载地址，不暴露对象存储路由，也不持久化临时访问地址。

### 上传流程

1. 管理员为已存在的题目选择附件，并填写可选说明。
2. problem-service 校验题目存在性和上传规则。
3. problem-service 先将文件写入 MinIO，再持久化附件元数据。
4. 元数据写入失败时，服务尝试删除已上传对象。对象删除失败时记录可定位的错误信息。

### 删除流程

1. problem-service 校验附件存在且属于目标题。
2. problem-service 删除附件元数据。
3. 数据库事务提交后，服务删除 MinIO 对象。
4. MinIO 删除失败不恢复已删除的元数据，但必须记录对象路由以便人工清理。

删除题目时必须处理所有附件。

### 存储桶对象资产与孤儿文件治理规则

1. **全链路对象对账**：
   - 管理端提供统一的对象资产治理控制台（Storage Asset Console），通过扫描 MinIO 存储桶物理对象并与 `problem_attachment` 表等业务引用进行双向对账，标记对象为“使用中”或“孤儿文件（未引用）”；
   - 支持一键筛选和排查无业务引用的孤儿文件。

2. **防误删强依赖校验机制（Dependency Check）**：
   - 管理员在存储控制台执行手动删除前，系统强制检查该对象的业务引用计数；
   - 若对象正被题目附件（`problem_attachment`）引用，系统强行拒绝删除并明确提示被哪道题目引用，杜绝误删导致前台 404；
   - 只有确认引用计数为 0 的孤儿文件，才允许物理执行 MinIO 删除并记录操作审计。

3. **题目创建与编辑联动上传规范**：
   - 编辑模式：直接调用上传接口，即时写入 MinIO 并落库绑定；
   - 创建模式：支持在前端预选并暂存待上传附件，在题目主表成功创建并生成雪花 ID 后，无缝联动并发上传暂存文件完成一体化绑定。
