## 附件规则

### 归属与数量

- 附件是题目的从属数据，每个附件只属于一道题目。
- 一道题目可以没有附件，也可以拥有多个附件。
- 业务上不假设附件只有一个。
- 题目附件支持 ZIP、RAR、7Z、TAR、GZ、BZ2、XZ 等常见压缩包，用于保存包含多个数据文件、代码或补充材料的赛题资源。
- 压缩包只作为普通附件保存和下载，平台不负责解压、内容扫描或在线预览。
- 题目附件可以是数学建模题目配套的大数据文件，其大小无法预先确定。problem-service 不设置固定的业务层单文件大小上限，实际可用上限由 file-service 的上传策略决定。
- 题目附件不得复用论文 PDF 的 20MB 上限。对象存储容量、协议和部署环境存在的技术边界不得固化为题目附件的业务大小限制。

### 附件信息

problem-service 维护附件的题目归属、原始文件名、稳定 fileId、媒体类型、文件大小、附件说明和展示顺序。

对象存储路由由 file-service 持有，problem-service 不再保存 objectKey。公开题目详情返回附件说明和短时效下载地址，下载地址按 fileId 现取现用，不持久化到题目附件表。

### 上传流程

1. 管理员为已存在的题目选择附件，并填写可选说明。
2. 小文件由 problem-service 按 PROBLEM_ATTACHMENT 用途代理登记；大文件由管理端先通过 file-service 预签名分片直传取回 fileId，再调用绑定接口。
3. problem-service 校验题目存在性、文件用途与上传规则。
4. problem-service 在同一本地事务中保存附件关系与绑定 Outbox 事件。
5. file-service 幂等消费绑定事件，维护引用投影并把资产置为已绑定。

### 删除流程

1. problem-service 校验附件存在且属于目标题。
2. problem-service 删除附件元数据，并在同一事务写入解绑 Outbox 事件。
3. file-service 消费解绑事件；最后一个有效引用解除后资产进入 AVAILABLE_UNBOUND。
4. 宽限期结束且引用投影仍为空时，由 file-service 删除物理对象；删除失败进入可重试状态。

删除题目时必须处理所有附件。

### 文件资产边界

1. 题目附件已迁移到 file-service：`problem_attachment` 只保存稳定 fileId，不再保存 objectKey，也不再直连 MinIO。
2. 文件稳定身份、技术元数据、访问策略和物理生命周期归 file-service；problem-service 继续拥有题目归属、附件说明和展示顺序。
3. problem-service 只允许管理题目附件，不负责扫描、手动上传或删除头像、论文和其他服务的存储对象。
4. problem-service 通过本地事务 Outbox 发布绑定或解绑事件。删除附件只解除业务引用，物理删除由 file-service 在宽限期后执行；存在有效引用时不会被物理删除。
5. 管理端文件中心通过 admin-service 代理 file-service，不直接访问 problem-service 或 MinIO 执行全桶治理。
6. 预签名地址只在访问时按 fileId 生成，不持久化到题目附件表，也不能作为长期 Markdown 链接。

跨服务设计与迁移顺序见 [文件资产管理架构](../../../02-架构设计/文件资产管理架构.md) 和 [file-service 迁移与实施边界](../../file-service/文件资产管理/迁移与实施边界.md)。

### 题目创建与编辑联动上传规范
   - 编辑模式：直接调用上传接口，即时登记 file-service 资产并落库绑定；
   - 创建模式：支持在前端预选并暂存待上传附件，在题目主表成功创建并生成雪花 ID 后，无缝联动并发上传暂存文件完成一体化绑定。
