## 附件规则

### 归属与数量

- 附件是题目的从属数据，每个附件只属于一道题目。
- 一道题目可以没有附件，也可以拥有多个附件。
- 业务上不假设附件只有一个。
- 题目附件支持 ZIP、RAR、7Z、TAR、GZ、BZ2、XZ 等常见压缩包，用于保存包含多个数据文件、代码或补充材料的赛题资源。
- 压缩包只作为普通附件保存和下载，平台不负责解压、内容扫描或在线预览。
- 题目附件可以是数学建模题目配套的大数据文件，其大小无法预先确定。problem-service 不设置固定的业务层单文件大小上限。
- 题目附件不得复用论文 PDF 的 20MB 上限。对象存储容量、协议和部署环境存在的技术边界不得固化为题目附件的业务大小限制。

### 附件信息

problem-service 维护附件的题目归属、原始文件名、对象存储路由、媒体类型、文件大小、附件说明和展示顺序。

对象存储路由只用于服务内部定位附件。公开题目详情返回附件说明和短时效下载地址，不暴露对象存储路由，也不持久化临时访问地址。

### 上传流程

1. 管理员为已存在的题目选择附件，并填写可选说明。
2. problem-service 校验题目存在性和上传规则。
3. problem-service 先将文件写入 MinIO，再持久化附件元数据。
4. 元数据写入失败时，服务尝试删除已上传对象。对象删除失败时记录可定位的错误信息。

### 删除流程

1. problem-service 校验附件存在且属于目标题。
2. problem-service 删除附件元数据。
3. 数据库事务提交后，服务删除 MinIO 对象。
4. MinIO 删除失败不恢复已删除的元数据，但必须记录对象路由以便人工清理。

删除题目时必须处理所有附件。

### 文件资产边界

1. 当前实现中，problem-service 直接将题目附件写入 MinIO，并在 `problem_attachment` 保存 objectKey 和必要元数据。该状态是迁移前基线，不代表 problem-service 应拥有整个 Bucket。
2. problem-service 只允许管理题目附件，不负责扫描、手动上传或删除头像、论文和其他服务的存储对象。
3. 目标 file-service 建成后，文件稳定身份、技术元数据、访问策略和物理生命周期归 file-service；problem-service 继续拥有题目归属、附件说明和展示顺序。
4. 迁移后的 `problem_attachment` 保存稳定 fileId，并通过本地事务 Outbox 发布绑定或解绑事件。删除附件只解除业务引用，物理删除由 file-service 在宽限期后执行。
5. 管理端文件中心通过 admin-service 代理 file-service，不直接访问 problem-service 或 MinIO 执行全桶治理。
6. MinIO 预签名地址只在访问时生成，不持久化到题目附件表，也不能作为长期 Markdown 链接。

跨服务设计与迁移顺序见 [文件资产管理架构](../../../02-架构设计/文件资产管理架构.md) 和 [file-service 迁移与实施边界](../../file-service/文件资产管理/迁移与实施边界.md)。

### 题目创建与编辑联动上传规范
   - 编辑模式：直接调用上传接口，即时写入 MinIO 并落库绑定；
   - 创建模式：支持在前端预选并暂存待上传附件，在题目主表成功创建并生成雪花 ID 后，无缝联动并发上传暂存文件完成一体化绑定。
