## 输入输出

### 输入

调用方必须指定 `retrievalWorkflowVersion`，并提供一至多个结构化查询。每个查询表达一个明确的信息需要，例如“优化模型如何验证约束可行性”或“摘要应如何覆盖题目各问”，不能把整篇论文原文直接作为查询。

输入可以包含以下过滤上下文：

- 业务场景，例如客服知识讲解或论文改善建议。
- 题目赛事、年份、题号和语言。
- 题型、模型族、论文板块和评审问题类别。
- 返回数量、总 Token 预算和调用截止时间。
- 调用方要求锁定的物理索引或目录版本。

知识检索服务不接收提交 ID 后自行读取论文，也不接收任意绝对路径。业务服务负责权限、数据最小化和查询构造。

### 输出

一次成功运行返回 `retrievalRunId`、实际检索工作流版本、实际执行分支、适用的 `ragIndexVersion` 或目录版本，以及按稳定顺序排列的来源片段。

每个片段至少包含稳定来源标识、文档标题、受控相对路径、章节标题、片段标识、内容哈希、来源层级、适用性结论和本次用于生成的内容。相关度只能帮助排序，不能作为事实正确性证明。

业务服务可以把必要来源快照保存进用户结果，但不得把检索响应整体复制成自己的知识库。日志和管理列表不得记录查询正文或片段正文。

### 空结果

没有满足阈值与适用性规则的片段时，返回成功的 `NO_CONTEXT` 结果，而不是虚构来源。调用方必须根据自己的工作流决定停止、减少输出或使用已明确版本化的其他分支。
