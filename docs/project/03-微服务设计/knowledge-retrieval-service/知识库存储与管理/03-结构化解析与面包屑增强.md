## 结构化解析与面包屑增强

### 语法树 AST 解析与 Frontmatter 提取

所有知识文档强制采用纯 Markdown 规范。解析流水线采用结构化语法分析器：
1. **YAML Frontmatter 提取**：提取开头的 `title`、`summary`、`tags`、`authorityLevel` 等标准化元数据字段；
2. **标题语法树（Heading AST）构建**：按 `#` (H1)、`##` (H2)、`###` (H3) 构建文档内部大纲层级，防止跨章节盲切破坏推导自洽性。

### 面包屑上下文注入（Breadcrumb Enrichment）

原子文档篇幅精炼（通常 500 到 2000 字），但在拆分为局部小切片时极易丢失宏观上下文。为了以零模型成本显著提升 Dense 向量聚类和 BM25 精准度，分块器必须向每个切片头部注入标准化面包屑前缀：

```text
[目录: 数学建模 > 题型方法 > 规划与优化]
[文档: 线性规划与对偶理论]
[小节: 约束条件松弛与敏感性分析]
----------------------------------------
(此处接切片正文内容，包含公式、推导与代码)
```

### 面包屑详细注入规范与清洗协议

分块器（`ChineseKnowledgeChunker`）在生成每一个切片时，严格执行以下标准化三元组组装与安全清洗：

#### 1. 面包屑三元组与定界符标准格式

```text
[目录: {directory_hierarchy}]
[文档: {document_title}]
[小节: {section_title}]
----------------------------------------
{chunk_content}
```

- **目录层级（`directory_hierarchy`）**：自顶向下由斜杠或层级数组拼接，使用统一分隔符 ` > ` 隔开，如 `数学建模 > 题型方法 > 优化类题型特征`；
- **文档标题（`document_title`）**：原子 Markdown 标题，优先采用 `README.yaml` / Frontmatter 中的 `title`，缺省取文件名（去除 `.md` 后缀）；
- **小节章节（`section_title`）**：切片所属的 Markdown 最近二级或三级标题（H2/H3）。**回退保底策略**：若切片处于文档开头、尚未出现 H2 标题时，统一使用 `[小节: 全局总览]` 作为兜底标识；
- **分界隔离线**：严格采用固定 40 个 ASCII 减号 `----------------------------------------`，尾随单个换行符 `\n`，严禁使用不规则长度或 Markdown `***`，确保检索侧能够用确定性正则精确识别或在需要时无损剥离。

#### 2. 特殊字符转义与语法清洗规则

1. **方括号保留字替换**：若目录名、标题或小节中本身含有中英文方括号（`[`、`]`、`【`、`】`），分块器必须统一转换为中文圆括号 `（` 与 `）`，彻底避免下游正则或代码将标题内容误判为面包屑字段定界符；
2. **Markdown 语法记号剔除**：在提取 H2/H3 标题文本时，必须剥离前导的 `#` 标识符、强调符号（`**`、`*`）、删除线（`~~`）以及行内公式符号（`$`），确保面包屑头部的纯文本高信噪比；
3. **不可见控制字符清洗**：依照工程规范清洗 `\u0000`~`\u001f`、BOM 字符，并将标题内偶发的内部换行与制表符折叠为单空格。

#### 3. 哈希算法与版本幂等性演进

1. **切片内容定义**：注入面包屑头部后的全文字符串即为 `KnowledgeChunk` 的正文字段（`content`），供向量化模型和 ES 索引存储；
2. **Token 与字符硬约束**：Token 预估与字符截断以注入面包屑后的完整文本为准，确保送入 Embedding API 的文本绝对不超长；
3. **切片内容哈希与 ID 幂等**：
   - 切片内容哈希 `contentHash = SHA-256(chunk_full_content)`；
   - 切片全局唯一 ID：由文档 ID、原始源文档哈希、切片序号计算而来；
4. **切片算法版本升级**：`RagIdentityFactory` 中的切片算法标识常量由 `zh-structure-v1` 升级为 `zh-structure-v2-breadcrumb`，保证 ES 物理索引版本 `ragIndexVersion` 能够确定性区分新旧切片格式，实现无缝蓝绿过渡。
