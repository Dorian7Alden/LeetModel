## 低价模型选型与服务端防御性设计

### 商业可行性生死线：为什么必须约束为低价快速模型？

在“AI 目录与标签智能选拔（`AI_DIRECTORY_V1`）”工作流中，AI 的角色只是一个**前置的“知识导购员”**，后续真正负责生成论文深度建议、解题报告的下游业务大模型才是主角。

若在该环节盲目引入昂贵的主力推理模型（如 Claude 3.5 Sonnet、GPT-4o 或 DeepSeek-R1）：
1. **经济成本失控**：一次论文建议需要并发执行 4 个子任务，光是前置挑选文档就要额外烧掉近 0.5~1 元人民币，整个 AI 业务链路的 ROI 将彻底崩塌；
2. **延迟严重累加**：重型推理模型的首字生成慢（通常 2~4 秒），严重拖慢整体端到端交互。

因此，整套架构能够成立的**绝对硬性约束**是：**前置检索模型必须选用超高吞吐、极低单价、结构化遵循能力达标的轻量级 Flash / Turbo 级别模型（如平台的全局默认选型 `gemini-3.8-flash-high` 或同等梯队模型）。**

### 任务降维：轻量模型胜任该任务的理论依据

低价轻量模型是否会导致“选拔不准确”？答案是否定的，因为我们对任务进行了彻底的工程降维：
- **非从零创作**：我们没有要求模型去推导公式或解答赛题；
- **上下文受限的多标签分类（In-context Multi-label Classification）**：模型输入的是一份结构高度规整、富含标签与一句话摘要的 YAML 清单（约 3000 Tokens），模型只需要依据任务语义在已有集合中挑选 2 到 4 个路径选项；
- **实证能力匹配**：现代 7B~14B 以及 Flash 级模型在处理有明确 Schema 约束、结构化上下文的选择任务时，准确率普遍稳定在 **92% 到 96%**，完全满足检索需求。

### 服务端构筑的 4 道确定性防御安全网

低价模型最大的劣势是：**偶尔出现拼写瑕疵、偶尔忽略数量限制、偶尔外带闲聊提示词**。
系统必须秉持“零信任大模型”的严密工程思想，由服务端的 Java 坚固代码构筑 4 道确定性防线，对轻量模型的输出进行兜底纠偏：

```mermaid
flowchart TD
    Raw[低价模型原始返回 Raw Output] --> Gate1[1. 代码防御性解析器<br/>剥离 markdown 围栏 / 截取首尾闭包 / 转义 LaTeX]
    Gate1 --> Gate2[2. 服务端绝对白名单校验<br/>比对内存有效 paths 集合，拼错/臆造一律静默剔除]
    Gate2 --> Gate3[3. 数量与预算代码硬截断<br/>强制 subList(0, maxSelected) 封顶截取]
    Gate3 --> Gate4{有效路径数量 >= 1 ?}
    Gate4 -- 正常 --> Load[全量读取目标 Markdown 装配返回]
    Gate4 -- 异常/被完全过滤 --> Fallback[4. 优雅降级兜底<br/>按 category 提取该分类预设的默认基准文档]
```

1. **防线 1：服务端绝对白名单校验（Path Whitelist Validator）**
   - 检索服务在内存中常驻当前知识库全量合法相对路径的 `Set<String> validPaths`；
   - 模型返回 `paths` 数组后，代码端逐项比对 `validPaths.contains(p)`；
   - 任何不在白名单内的路径（包括拼写变体、虚假幻觉）**直接静默过滤剔除**，严禁使用模型给出的原始字符串直接访问存储或磁盘。
2. **防线 2：数量与预算代码硬截断（Hard Count Truncator）**
   - 提示词中即便写了“最多选 3 篇”，轻量模型偶发可能选出 5 篇；
   - 代码层坚决不依赖模型的自觉性，服务端强制执行 `selected = selected.stream().limit(maxSelected).toList()`，防止下游主模型输入爆炸。
3. **防线 3：防御性 JSON 解析器（Defensive Parser）**
   - 遵照 [提示词管理实践](/home/dorian/repo/LeetModel/docs/learning/提示词管理.md)；
   - 自动剥离 ` ```json ` 或 ` ``` ` Markdown 代码围栏；
   - 贪婪截取字符串首个 `{` 与最后一个 `}` 之间的内容进行反序列化；
   - 容错转义 LaTeX 公式反斜杠（如 `\frac`），防止反序列化解析报错。
4. **防线 4：全流程优雅降级（Graceful Fallback）**
   - 若遇到低价模型外部网关抖动、调用超时或返回被白名单全数过滤的极端情况；
   - 检索服务绝不抛出 500 错误中断业务；
   - 自动回退触发默认保底策略：根据请求中的 `category`（如 `OPTIMIZATION`），直接调取该分类预设的 1~2 篇通用基准文档（如《优化模型与算法分类.md》），保障业务主链 100% 顺畅。
