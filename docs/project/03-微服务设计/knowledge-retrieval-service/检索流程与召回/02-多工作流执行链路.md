## 多工作流执行链路

### 架构执行全景

服务根据入参中的 `workflowVersion` 严格路由至对应的执行分支，禁止在运行时动态拼接非发布规则：

```mermaid
flowchart TD
    Req[接收检索请求 Request] --> CheckVersion{校验工作流版本}
    
    CheckVersion -->|VECTOR_RAG_V1| V_Branch[单路向量 RAG 分支]
    CheckVersion -->|AI_DIRECTORY_V1| D_Branch[受控 AI 目录选文分支]
    CheckVersion -->|HYBRID_RETRIEVAL_V1<br/>SUGGESTION_DEEP_RETRIEVAL_V1| H_Branch[双轨混合检索分支]
    
    V_Branch --> V_Embed[Query 向量化]
    V_Embed --> V_KNN[ES kNN 向量检索]
    
    D_Branch --> D_Manifest[加载受控 Markdown 清单]
    D_Manifest --> D_LLM[LLM 目录选择器]
    D_LLM --> D_Load[白名单受限加载正文]
    
    H_Branch --> H_Par{并发执行}
    H_Par --> H_Vec[向量召回 (Candidate K)]
    H_Par --> H_BM25[BM25 倒排召回 (Candidate K)]
    H_Vec --> H_RRF[RRF 倒数秩融合打分]
    H_BM25 --> H_RRF
    
    V_KNN --> Validate[权威分级校验 & 题目专属过滤]
    D_Load --> Validate
    H_RRF --> Validate
    
    Validate --> Budget[Token 预算裁剪]
    Budget --> Output[返回 KnowledgeRetrievalResultDTO]
```

### 核心分支定义

1. **单路向量分支（VECTOR_RAG_V1）**
   - 调用 `ai-gateway-service` 逻辑模型 `RAG_V1`（固定 `qwen3.7-text-embedding@1024`）；
   - 向 Elasticsearch 发起 kNN 检索，设定 `scoreThreshold`（默认 0.65）；
   - 适合通用语义意图理解。

2. **受控 AI 选文分支（AI_DIRECTORY_V1）**
   - 仅向模型暴露 Markdown 路径、标题和摘要构成的受控清单（Manifest）；
   - 模型仅输出 JSON 格式的受控路径列表（最多 4 个），严禁模型自由遍历文件系统；
   - 服务端二次校验路径白名单并受限读取正文；
   - 适用于评审板块全篇性宏观指引选拔。

3. **双轨混合分支（HYBRID_RETRIEVAL_V1 / SUGGESTION_DEEP_RETRIEVAL_V1）**
   - 结合 Dense 向量语义泛化与 BM25 专有名词高权匹配；
   - 通过 RRF 算法无参融合打分，取 Top K；
   - 为 AI 论文建议 V3 的核心生产工作流。
