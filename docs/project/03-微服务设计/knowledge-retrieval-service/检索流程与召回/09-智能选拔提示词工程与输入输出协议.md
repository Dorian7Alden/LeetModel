## 智能选拔提示词工程与输入输出协议

### 提示词架构总览

在“AI 目录与标签智能选拔（`AI_DIRECTORY_V1` / `AI_CATALOG_TAG_V1`）”工作流中，AI 模型承担“高决策密度知识导购员”角色。
为保障低价轻量模型（如平台全局默认的 `gemini-3.8-flash-high`）高确定性输出，提示词工程严格遵守 [提示词管理实践](/home/dorian/repo/LeetModel/docs/learning/提示词管理.md) 的三层原则：**角色分层（System / User 分离）**、**占位符定界防护（`[[ ]]`）**、**防注入数据与指令隔离**。

### 提示词模板结构与定界符规范

模板统一外置于 `src/main/resources/prompts/` 目录：
- `catalog-selection-system.st`：系统角色、核心原则与输出 Schema 约束；
- `catalog-selection-user.st`：用户任务、动态 Manifest 注入与 Few-shot 示例；
- `catalog-selection.st`：完整端到端模板。

#### 核心占位符字典

| 占位符 | 注入数据源 | 语义说明 |
|:---|:---|:---|
| `[[userQuery]]` | `request.getQuery()` | 下游业务传递的建模任务描述或解题难题 |
| `[[category]]` | `request.getCategory()` | 业务大类（如优化/评价/预测/机理/数据挖掘） |
| `[[minSelection]]` | 常量 / 配置 | 最小选拔文档数（默认 2） |
| `[[maxSelection]]` | `min(topK, limit)` | 最大选拔文档数（默认 4） |
| `[[catalogManifest]]` | `Manifest` 格式化文本 | 经过分类减枝后的受控相对路径、标题与一句话摘要列表 |

### 四大仲裁准则与工程化注入

1. **强相关性原则**：紧密围绕任务的赛题大类与核心难点挑选文档；
2. **代表性去重原则（核心红线）**：
   - 优秀论文与同类分析篇幅巨大，严禁将同类型的多篇优秀论文同时选入；
   - 若命中多篇同类或同题型优秀论文，仅按年份最新或方法最契合挑选 1 篇代表作；
3. **互补搭配原则**：挑选出的 2 到 4 篇文档应构成完整认知闭环（如：1篇算法推导 + 1篇敏感性分析/检验 + 1篇官方评审要点）；
4. **数量与预算硬约束**：严格限制在 2 到 4 篇，严禁超选，严禁留空。

### 严格 JSON 响应协议

模型在服务端约束下必须以 `application/json` 直接返回纯净 JSON 对象：

```json
{
  "reasoning": "简要说明挑选这几篇文档的互补搭配依据与代表性去重考量",
  "selectedPaths": [
    "数学建模/模型方法/优化模型与算法分类.md",
    "数学建模/模型方法/常用模型速查-优化类.md",
    "数学建模/论文评审/评审板块/敏感性分析评审要点.md"
  ]
}
```

### 防御性对接准备

尽管提示词施加了严格约束，低价模型仍可能出现偶发格式漂移。模型输出必须紧接着流经后置的**服务端 4 道确定性防线**（防御性解析器清洗 Markdown 围栏、白名单过滤、数量硬截断、优雅降级兜底），严禁将大模型原始返回值直接用于磁盘或对象存储读取。
