## 方案取舍

- 使用分片上传，避免大文件请求长期占用单次连接。
- 当前论文上限为 20MB，采用前端两路并发、submission-service 中转和 MinIO 对象合并。当论文大小或流量出现实测瓶颈后，再评估预签名直传。
- 不做文件去重与秒传，优先保证提交事实清晰。
- 提交归属队伍，同时记录上传者，兼顾业务归属与审计。
- 上传初始化阶段执行主要权限校验，完成阶段重点校验文件完整性和任务一致性。
- 队伍上传互斥先使用数据库状态保证，性能不足时再优化。
- 本阶段不因预测的峰值流量引入复杂消息队列流程。
- 题目附件由 problem-service 拥有，可能是大数据文件且不设固定业务大小上限。题目附件不复用论文 PDF 的上传会话和 20MB 限制。
