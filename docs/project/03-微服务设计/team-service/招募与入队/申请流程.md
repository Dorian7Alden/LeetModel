## 申请流程

### 主流程

1. 队长在组建中选择至少一个专业职责并发布一个招募位置。
2. 非队伍成员针对组队广场中的具体招募位置提交申请，可以填写申请理由。
3. 队长查看待处理申请并选择通过或拒绝。
4. 审核通过时，team-service 在同一事务内锁定队伍、申请和招募位置，重新校验组建状态、位置开放状态、成员唯一性和三人容量，再按招募位置的职责写入成员关系。
5. 招募位置进入已占用，申请进入已通过；同一位置的其他待处理申请统一关闭。拒绝申请不会关闭招募位置。

### 状态与异常

- 申请状态包括待处理、已通过、已拒绝、已取消和已关闭。
- 同一用户对同一队伍只能有一条待处理申请，历史申请保留。
- 队长不能申请自己的队伍，现有成员不能重复申请。
- 招募位置关闭或已占用、已经开始练习或已经解散时不能提交或通过申请。
- 开始练习或解散队伍时，全部待处理申请统一关闭，并与队长主动拒绝区分。
- 并发审核必须锁定队伍并重新计算容量，不能只依赖申请提交时的结果。

### 列表展示

- 队长查看申请时使用服务端分页，页面默认每页 6 条。
- 默认只展示待处理申请，并提供全部、已通过、已拒绝、已取消和已关闭状态筛选。
- 未指定状态时待处理申请优先，其余记录按申请时间倒序；同一时间按申请 ID 倒序保持稳定。
- 申请列表返回申请时对应招募位置的职责组合。用户公开摘要与招募位置必须批量聚合，不能逐条远程调用或逐条查询。
- 申请提交、取消、审核、开始练习和关闭招募统一按“队伍行 → 申请或招募行”的顺序加锁，避免并发操作越过状态冻结或重复占位。
