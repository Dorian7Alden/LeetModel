## 管理端端到端验收

### 环境与边界

S8 验收使用本地 12 个 LeetModel 服务、MySQL、Redis、MinIO、Elasticsearch、Nacos 和仓库外 new-api 测试 Token。`cli-proxy-api` 是不属于本项目的长期服务，整个过程未停止、重启、改端口或修改配置；submission-service 使用 8092。验收不记录 Token、Prompt、回答、知识片段或论文正文。

ASSISTANT_RAG_V1 仍缺少已构建且带读取别名的固定 `ragIndexVersion`，因此不能作为成功路径。无 RAG 客服版本不依赖该配置并已完成成功验收；缺失索引只用于验证显式环境失败和失败项重试，不作为功能降级或成功结论。

### REVIEW 成功路径

固定单样本 REVIEW 数据集以 `BASIC_REVIEW_V1`、锁定模型执行配置、活动权重方案和重复次数 2 运行完成。两次运行均成功，运行槽位、网关调用事实和队列记录的 `callId` 一一对应；任务聚合 Token 等于两条调用 Token 之和，费用因没有可追溯价格快照而保持缺失。

初始选择指数产生 `SCORE_RESULT_V1`，使用另一活动权重方案后追加 `SCORE_RESULT_V2`。两版的贡献值之和分别精确等于各自选择指数，指标口径均为 `METRIC_SET_V2`，原始指标没有被覆盖。页面可以展开两版权重贡献并追踪每次调用。

### ASSISTANT 成功路径与任务控制

固定单问题 ASSISTANT 数据集使用 `ASSISTANT_NO_RAG_V1`。五重复任务创建后立即暂停，保持 `PAUSED` 且终态槽位为 0；恢复后五个槽位全部完成，最后操作审计为 `RESUME`，调用审计为 5/5 完整。检索指标显示不适用，其余缺少标准来源、格式规则、标准要点或人工量表的指标显示未评价，没有宣称准确率。

验收中发现并修复了客服运行成功但旧兼容 `successRate` 为 0 的口径错误。修复后新增单槽位任务的摘要成功率、有效率、可信原始成功率和结构有效率均为 100%，客服不适用的分数稳定性保持空值。评价模块及直接依赖共 94 项测试通过，其中评价模块 85 项。

### 失败重试与优先级

使用不存在的固定 RAG 索引运行两个槽位，二者以 `ENVIRONMENT` 显式失败且没有伪造 `callId`。点击重试后任务从 `FAILED` 回到 `WAITING`，`retryCount` 增至 1，只生成第二次失败尝试；由于外部索引仍不存在，最终继续明确失败。这证明重试不会把环境错误伪装成功，也不会改写第一次尝试。

在五重复 P3 客服评价恢复运行期间，同时发送正式客服消息。网关审计显示正式 `CHAT_REPLY` 为 P0 且成功，评价 `EXPERIMENT_ASSISTANT` 均为 P3；P0 调用先于随后批次槽位完成，后台实验没有占用客服保留优先级。

### 权限与一致性

普通 VIP 演示账号访问评价读入口和重试写入口均返回 HTTP 403/业务码 40104；管理员可以执行任务控制与重算。REVIEW 验收中运行数、原始指标观察调用数、调用表数和队列表数均为 2，全部运行 `callId` 可匹配；两版贡献和等于对应指数，原始 Token 合计等于调用 Token 合计。

页面刷新后从服务端恢复任务状态、进度、结果版本和调用事实。历史 REVIEW 任务仍能查看，缺少权重结果或旧网关审计时明确显示不可用/未找到。
