## 管理端体验设计

### 设计目标

管理端应围绕管理员要完成的任务组织界面，而不是把每个后端资源机械地映射为一个一级菜单。重构保留现有后端契约与数据边界，只调整前端信息架构、操作层级和数据表达。

### 信息架构

| 工作域 | 主任务 | 整合的既有入口 |
|------|------|------|
| 概览 | 判断平台是否健康并快速进入异常区域 | 首页概览 |
| 访问控制 | 查找用户、控制账号状态、配置角色与权限 | 用户、角色、权限、授权 |
| 内容中心 | 维护题目及其分类语境 | 题目、标签、赛事 |
| 业务运营 | 观察从组队到提交、评审、建议和排行的业务链 | 队伍、提交、评审、建议、排行 |
| AI 中枢 | 观察调用质量、执行评价并治理生产版本 | AI 调用、质量评价、生产版本 |

旧路由继续保留并重定向到对应工作域。这样可以兼容已有书签和文档链接，同时只向管理员呈现五个稳定入口。

### 交互层级

访问控制以用户列表为默认工作面。账号状态和角色分配保留为行内操作；角色定义、权限目录和角色授权属于低频配置，通过页面头部按钮打开抽屉，不再占用一级导航。

内容中心以题目列表为默认工作面。标签是题目的检索与分类元数据，通过内容中心内的辅助操作层维护；赛事作为题目归属的只读基础数据放在同一区域。题目预览使用详情接口读取完整 Markdown，并经过现有安全渲染函数净化后展示。

业务运营和 AI 中枢使用工作域内视图切换。切换只改变当前观察面，不制造新的一级导航层级。页面头部先表达核心状态和统计，再呈现可筛选明细，避免所有数据都退化为独立表格。

### 视觉与布局

- 侧栏固定为视口高度，品牌区、导航区和底部状态区分层，导航区独立滚动。
- 桌面端使用清晰的工作域标题、说明和状态提示；侧栏收起后保留图标与提示。
- 主内容区限制舒适阅读宽度并保留横向数据表的可用空间。
- 小于桌面宽度时侧栏默认压缩，头部隐藏低优先信息，工具栏允许换行。
- 数据表达组合使用指标卡、状态标签、进度或占比、图表与明细表，不用单一表格承担所有判断。

### 边界与取舍

本轮不增加后端聚合接口，不改变 user-service、problem-service、AI 相关服务的数据所有权。工作域摘要只消费已有接口；部分服务不可用时沿用明确的不可用提示，不用零值伪装成功。旧页面实现暂时作为工作域内部组件复用，待交互稳定后再决定是否进行纯结构性拆分。

### 验收重点

1. 常见桌面高度下不再出现无法访问的侧栏条目，极小高度仍可滚动。
2. 用户角色授权和题目标签维护不需要离开所属工作域。
3. 题目 Markdown 能安全渲染，空题面和详情接口失败均有明确状态。
4. 旧管理地址可以稳定落到新的工作域和正确内部视图。
5. 管理端生产构建通过，并在桌面和窄视口完成关键路径浏览器复验。
