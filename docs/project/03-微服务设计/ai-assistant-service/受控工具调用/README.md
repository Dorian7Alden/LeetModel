## 受控工具调用

> 实现状态：公共 `tool_calls` 协议、模型门禁、题目事实查询、版本化工具注册表、受控执行循环、两个题目工具、终止式知识讲解工具和 `assistant_tool_call` 审计表已实现。生产工具工作流与消息级工具集快照尚未发布；现有生产配置仍运行关键词预取方案，不会提前获得工具权限。

### 目标

让 LeetModel AI 客服能够在服务端控制下调用业务工具。首版只提供题目查询、题目推荐和数学建模知识点讲解，使客服基于平台事实回答题目问题，并使用专用 Prompt 生成简洁、专业的知识讲解。

该能力升级现有客服工作流，不新建通用 Agent 平台。模型负责表达调用意图，`ai-assistant-service` 负责工具白名单、参数校验、权限、执行、结果注入、失败处理和调用记录。

### 确认记录

开发者已确认以下首版设计取舍：

- 使用供应商无关的原生 `tool_calls` 契约，不使用模型输出 JSON 模拟工具路由。
- 使用独立 `toolsetVersion` 锁定工具名称、Schema、版本和执行限制。
- `explain_modeling_knowledge` 是终止式工具，工具内部专用模型调用直接产生客服最终回答，外层模型不再改写。

2026-08-31 已使用真实 Relay Token 验证 `deepseek-v4-flash` 经 new-api 的 `tool_choice=auto` 能返回标准工具调用；强制指定工具对象不受当前渠道支持，因此生产编排只使用已验证的 `AUTO`，不静默退化为 JSON 路由。

### 范围

- 为统一 AI 调用协议增加供应商无关的工具定义、工具选择、工具调用和工具结果契约。
- 在 `ai-assistant-service` 建立只读 `ToolRegistry` 和受控工具执行循环。
- 实现 `search_problem`、`recommend_problem` 和 `explain_modeling_knowledge` 三个示例工具。
- 题目事实只通过 problem-service 内部接口读取，只返回已发布题目。
- 知识点讲解使用独立、版本化的专家 Prompt，并受当前生产 RAG 快照约束。
- 保存工具调用状态、版本、参数、结果摘要、耗时和关联的 AI `callId`。
- 保留当前会话、消息幂等、失败回复、重试和生产工作流版本治理能力。

### 非目标

- 不实现任意代码、SQL、HTTP 地址或 MCP 工具执行。
- 不实现创建队伍、修改题目、提交论文等写操作。
- 不开放用户自定义工具，不动态扫描 Spring Bean 作为工具。
- 不建立多 Agent 协作、长期自主规划或无限工具循环。
- 不让 ai-gateway-service 执行业务工具或理解题目语义。
- 不把数学建模之外的通用百科问答纳入客服范围。
- 首版不实现流式工具事件和前端工具执行过程展示。
