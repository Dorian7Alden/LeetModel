## RAG V2 实施门槛

### 进入实现评估的前置条件

以下条件必须同时成立，才可以在 knowledge-retrieval-service 中发布 `AI_DIRECTORY_V1`；本设计本身不授权写运行时代码：

1. RAG V1 已在目标环境建立可查询固定索引，完成至少 40 题、每候选每题 3 次的召回、答案支持、延迟、Token、费用和失败基线。
2. 数据集、标准来源和答案支持要点完成双人标注与裁决，人工覆盖率达到 100%。
3. V1 与 V1+V2 使用同一数据集、索引、目录、Chat 配置和指标口径，调用审计完整率达到 100%。
4. manifest 生成无缺失 summary、无越界文件，完整输入不超过 12,000 `cl100k_base` Token；选择器结构校验和路径白名单测试全部通过。
5. 固定实验至少重复两次且结论方向一致。

### 增益门槛

在全部前置条件满足后，候选还必须同时满足：

- 答案支持率相对 V1 提升至少 5 个百分点，题目级配对差的 95% bootstrap 置信区间下界大于 0。
- 有标准来源问题的 Recall@K 提升至少 5 个百分点，Precision@K 不下降超过 2 个百分点。
- 无依据陈述率不高于 V1，`NO_KB_ANSWER` 问题的错误引用率不增加。
- 总耗时 P95 增幅不超过 20%，总 Token P95 增幅不超过 30%；费用缺失时该项视为未满足，而不是按零通过。
- 候选失败率不高于 V1 超过 1 个百分点，路径安全事件为 0。

未达到门槛时保持 RAG V1，不通过调低阈值、删除失败样本、改换数据集或只报告平均值制造增益。需要改变流程或指标时先产生新版本并完整重跑。

### 即使通过后的实施边界

通过实验只允许评估在 knowledge-retrieval-service 中实现受控目录选择、加载、裁剪和审计。上线仍需独立完成威胁建模、容量压测、Prompt/模型配置版本、关闭开关、灰度、回滚、告警和真实费用配置；默认关闭，不能自动替换任何已发布调用方工作流。

以下能力仍不因门槛通过而获得授权：

- 在线文件上传、编辑、审核、发布或删除。
- 多租户知识库、公开通用检索 API 或不受业务契约限制的消费者接入。
- 模型自主遍历文件系统、构造路径、执行代码或写知识内容。
- 为论文评审接入客服知识库。
- 自动根据评价结果激活生产版本。

论文建议已构成第二个真实知识消费者，独立服务决策已确认。该架构决策不等于 V2 检索增益已经被证明；`AI_DIRECTORY_V1` 仍必须单独满足本文的实验门槛。
