## 轻量知识目录

### 目标与事实源

manifest 只帮助选择候选文档，不保存正文、分块、Embedding、用户问题或业务数据。事实源仍是 Git 管理的 `rag_kb/数学建模/` 内容 Markdown；生成器复用 V1 的确定性文件清单，只包含该前缀下非 `README.md` 的内容文件，并继续排除 `.kb/`、`data/`、原始 PDF、脚本和所有未声明顶层目录。

### 结构

```json
{
  "manifestVersion": "RAG_DIRECTORY_MANIFEST_V1",
  "sourceVersion": "sha256:<完整清单与内容的确定性哈希>",
  "allowedPathPrefixes": ["数学建模/"],
  "directories": [
    {
      "path": "数学建模/模型方法",
      "documents": [
        {
          "name": "常用模型速查-评价类.md",
          "tags": ["数学建模", "评价模型"],
          "summary": "受长度限制的维护摘要"
        }
      ]
    }
  ]
}
```

`manifestVersion` 只表示结构口径；`sourceVersion` 对按 UTF-8 相对路径排序的文件依次拼接“相对路径 UTF-8 字节、单个 NUL、完整文件字节、单个 NUL”并计算 SHA-256，表示这次目录内容快照。NUL 分隔用于消除路径和正文连接歧义。文档不重复保存哈希，避免把机器校验字段大量注入模型上下文。目录按路径、文档按文件名排序，JSON 使用 UTF-8、稳定键顺序、无缩进和无多余空白生成，相同内容必须得到逐字节相同结果。

每条文档只包含目录、文件名、`tags` 和 `summary`。标题不另存，文件名就是稳定文档名；正文中的其他 frontmatter、README 文本、绝对路径、Git 工作区路径和文件系统时间不进入 manifest。

### summary 失败策略

`summary` 必须是非空单行纯文本，规范化后最长 240 个 Unicode 字符；`tags` 最多 12 个，每项最长 32 个字符。缺少、超长或解析失败时生成诊断中的精确相对路径，但整版 manifest 不发布，线上继续使用上一份已验证版本或完全关闭 V2 并使用 V1。不得用正文开头、模型临时摘要或空字符串补位，也不得只静默跳过该文档造成目录不完整。

当前受控清单的 73 篇文档均有 summary，因此缺失数为 0。

### 路径白名单

`allowedPathPrefixes` 是声明边界，真正授权还要求目标路径同时满足：

1. 模型输出只包含 manifest 中出现过的“目录 path + 文档 name”精确组合。
2. 服务端以知识库根目录解析并规范化路径，拒绝绝对路径、空段、`.`、`..`、符号链接和规范化后越界。
3. 规范化相对路径以 `数学建模/` 开头，扩展名严格为 `.md`，文件不是任何层级的 `README.md`。
4. 运行时重新核对普通文件和当前 `sourceVersion`；目录变化后不沿用旧选择结果。

模型给出的未知路径、大小写变体、URL、glob 或路径片段全部丢弃并记录不含问题正文的原因码。模型不能扩大白名单。

### 完整 manifest Token 实测

2026-08-30 对当前 V1 同一受控清单进行只读生成测量：73 篇文档、12 个目录、311 个标签、0 个缺失 summary。使用上述目录分组结构、顶层 `sourceVersion`、UTF-8 紧凑 JSON 后，完整 manifest 为 29,145 字节、13,419 个 Unicode 字符；`cl100k_base` 为 10,848 Token，`o200k_base` 为 8,396 Token。该次 `sourceVersion` 为 `sha256:b27f9e83bd65201dbe194b889e86fa7beecdf6bd522621688f2b7b8a5aacc855`，用于复核测量而不是线上固定常量。

设计预算采用较大的 10,848 Token，并为选择指令、用户问题和结构化输出预留至少 3,152 Token，因此选择模型必须支持至少 16k 上下文。知识增长使完整 manifest 超过 12,000 `cl100k_base` Token 时，V2 不得继续扩大单次输入；应先重新评估分层目录摘要或分支 manifest，并重新完成固定实验，不能静默截断目录。
