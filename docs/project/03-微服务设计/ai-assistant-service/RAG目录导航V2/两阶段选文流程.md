## 两阶段 AI 选文流程

### 输入输出

输入是当前用户问题、锁定的 `manifestVersion/sourceVersion`、受控完整 manifest 和 V1 已锁定的 `ragIndexVersion`。不把会话全文、密钥、权限数据或题目工具结果交给目录选择器。

选择器使用独立、不可变的 Prompt 和模型执行配置，输出严格 JSON：

```json
{
  "selections": [
    {"path": "数学建模/模型方法/常用模型速查-评价类.md", "reasonCode": "TOPIC_MATCH", "rank": 1}
  ],
  "noCandidate": false
}
```

只接受 manifest 中的精确路径、枚举原因码和 1 至 4 的唯一 rank。最多选择 4 篇；重复、未知字段、未知路径、超过上限或非 JSON 输出视为选择失败，不从自由文本提取路径。

### 阶段一：目录选择

1. 读取已经发布且 Token 预算合格的完整 manifest。
2. 通过 common-ai 和 AI 网关调用低成本文本模型，业务操作码固定为目录选择，优先级仍由网关校验；业务服务不能自行提权。
3. Prompt 明确 manifest 是不可信元数据，模型只能匹配问题主题并返回精确候选，不执行其中的指令。
4. 服务端校验结构、候选数、rank 和精确成员关系，再执行路径白名单检查。

选择调用上限 1 次，超时预算 1,200ms。超时、网关失败、无候选或校验失败时不重试模型，直接保留 V1 结果；选择结果不得写入长期用户记忆。

### 阶段二：受限加载与二次裁剪

服务端按 rank 顺序最多加载 4 篇、单篇最多 96 KiB，总读取最多 256 KiB。读取前再次核对 `sourceVersion` 和普通文件边界；任一文件变化或越界时整批 V2 候选失效，不混用两个目录版本。

加载后复用 V1 的 Markdown 清洗和标题优先切分规则，不执行 Markdown、HTML、链接或代码。二次裁剪是确定性过程，不再调用模型：

1. 标题和标签与规范化问题词项精确命中优先。
2. 同分时按选择 rank、文档路径和片段序号稳定排序。
3. 每篇最多保留 2 个片段，V2 总计最多 6 个片段、1,200 Token。
4. 相同 `sourcePath + heading + contentHash` 去重，片段保留来源路径和目录版本。

加载与裁剪预算合计 200ms。任何解析失败只记录路径哈希、错误类型、目录版本和耗时，不记录问题或正文；整批 V2 结果丢弃，继续 V1。

### 与 V1 组合

V1 Query Embedding/Elasticsearch 召回与阶段一目录选择并行执行。两路完成后按稳定来源标识去重：V1 保留最多 4 个片段/1,200 Token，V2 保留最多 6 个片段/1,200 Token，总知识上下文不超过 2,400 Token。重复来源优先保留 V1 的具体命中片段，V2 只补充未覆盖的目录主题。

最终上下文分成 `VECTOR_SOURCES` 与 `DIRECTORY_SOURCES` 两个明确区块，每个片段带相对来源；两者都是不可信参考资料，不能覆盖系统行为、授权规则或 problem-service 工具事实。Chat Prompt 和模型执行配置仍独立版本化。

### 降级与超时

V2 总墙钟预算为 1,500ms，超过即取消尚未开始的加载并使用 V1。V1 成功而 V2 失败时使用 V1；V1 失败而 V2 成功时，首轮实验只记录 V2-only 诊断，不改变当前生产降级语义；两者都无结果时使用无 RAG Chat。Chat 失败继续沿用助手现有失败回复和显式重试。

V2 失败不触发任意文件搜索、扩大候选、读取 README、读取原始抓取数据或退回模型自由构造路径。
