## 建议范围与优先级

### 建议范围

建议覆盖完整的数学建模解题链和论文交付质量。

| 类别 | 重点检查与建议内容 |
|------|--------------------|
| 题目覆盖 | 每一问、必交结果、约束和指定图表是否回答完整 |
| 问题分析 | 是否提炼目标、数据、难点和逐问建模路线，是否与正文一致 |
| 模型假设 | 假设是否服务模型、依据是否充分、是否说明失效场景和误差方向 |
| 数据处理 | 数据来源、清洗、异常值、缺失值、量纲和划分方式是否可解释 |
| 模型选择 | 方法是否匹配题型，是否存在模板套用、模型堆砌或缺少基线 |
| 模型建立 | 变量、目标函数、约束、方程、推导、单位和题目适配是否完整 |
| 模型求解 | 算法、工具、参数、收敛、复杂度和复现信息是否充分 |
| 结果与结论 | 数值是否回答题目、前后一致、量级合理并具有业务解释 |
| 模型检验 | 是否使用与题型匹配的误差、残差、回代、基准或实测对比 |
| 敏感性与稳健性 | 是否分析关键参数扰动、结论翻转边界和模型适用范围 |
| 摘要与结构 | 摘要是否覆盖方法和关键数值，各章节是否与题目和结果对应 |
| 表达与规范 | 公式、符号、图表、单位、引用、附录和身份信息是否规范 |
| 评价与推广 | 优缺点是否真实，改进和推广是否指向具体场景与适配条件 |

类别编码属于建议工作流输出契约。新增、合并或改变类别语义必须发布新建议工作流或结果 schema，不能修改历史报告解释。

### 优先级

优先级依据“对题目完成和结论可信度的影响”排序，不按模型认为哪条文字更醒目排序。

| 优先级 | 语义 | 典型问题 |
|--------|------|----------|
| P0 阻断 | 不修正就无法认为论文完整或结论成立 | 漏答、目标或约束错误、结果自相矛盾、关键数据来源不明 |
| P1 高 | 直接影响模型与结果可信度 | 强假设无依据、缺少关键检验、求解不可复现、数据泄漏 |
| P2 中 | 影响论文档次和方法说服力 | 缺少敏感性、基线比较、题目适配、结果解释或局限讨论 |
| P3 低 | 主要改善阅读与交付质量 | 摘要措辞、图表标注、公式编号、结构和引用格式 |

排序先比较优先级，再比较题目要求顺序、评审影响程度和论文页码。相同问题不得拆成多条重复建议制造数量感。

### 数量控制

一份报告目标输出 3 至 12 项建议。论文确实只有少量可靠问题时可以少于 3 项，但至少要有 1 项完整有据建议才能成功。系统优先保留 P0 和 P1，不为了凑满数量加入缺乏依据或价值过低的建议。

报告首页只突出最多 3 项当前最值得修改的事项。完整列表仍保留中低优先级，避免用户被十几条同等醒目的建议淹没。
