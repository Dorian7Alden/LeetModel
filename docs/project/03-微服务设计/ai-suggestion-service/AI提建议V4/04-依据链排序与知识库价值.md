## 依据链、排序与知识库价值

> 设计状态：已完成实现并经验收。


### 一、依据链

| 建议类型 | 论文依据 | 评审依据 | 知识依据 |
|----------|----------|----------|----------|
| `REQUIRED_FIX` | 必须 | 必须 | 强相关时展示 |
| `COMPLETENESS_ENHANCEMENT` | 必须 | 推荐，若来自评审问题则必须 | 强相关时展示 |
| `OPTIONAL_EXPLORATION` | 必须 | 可为空 | 强相关时展示 |

论文依据证明“当前论文是什么状态”，知识依据证明“为什么这个补充方向有价值”。


### 二、知识检索

检索 Query 由以下内容组成：

- 赛题小问要求；
- 当前论文方法与证据摘要；
- 关联评审问题；
- 建议类别；
- 需要核验的专业主题。

知识库不用于机械匹配算法名。召回内容必须通过赛事适用性、题型适用性和层级校验。


### 三、专业价值展示

前端展开知识依据时显示：

- 来源标题与章节；
- 资料层级和稳定路径；
- 支撑结论；
- 为什么适用于当前论文；
- 版本信息。

不展示向量相似度作为权威度，不显示内部检索调试字段。


### 四、排序

建议按以下顺序：

1. `P0 -> P1 -> P2 -> P3`
2. `REQUIRED_FIX -> COMPLETENESS_ENHANCEMENT -> OPTIONAL_EXPLORATION`
3. 是否影响题目覆盖或主结论
4. 评审影响程度
5. 小问编号
6. 物理页码
7. 建议 ID

顶部优先事项从完整排序后的前 1 至 3 条生成，不由模型另写一份可能不一致的列表。

排序发生在评审问题槽位补齐、同一 finding 去重和主观建模安全改写之后；
所有 `REQUIRED_FIX` 必须进入最终报告，不能因数量上限被裁掉。


### 五、去重

建议指纹包括：

- `guidanceType`
- 类别
- 小问
- 排序后的论文证据 ID
- 评审问题 ID
- 规范化标题

同一问题不得拆成“补公式、补解释、补代码”三条，除非三者具有独立证据、独立影响和独立验收标准。


### 六、数量

- 报告目标为 3 至 10 条。
- P0/P1 全部保留。
- P2/P3 按价值和证据完整性截取。
- 不为达到数量下限生成泛化建议。
- 没有可靠建议时任务失败，不返回模板化空壳报告。


### 七、锁定评审问题一一覆盖

- 服务端以锁定评审中的每个 `ISSUE` / `WEAKNESS` 建立确定性槽位；
- 同一 finding 只保留一个合格候选，重复引用直接去重；
- 模型漏项时生成只引用该 finding 完整论文证据的同主题兜底；
- 缺少可用论文块时任务失败，不得删除覆盖校验或跨问题借证据；
- 最终校验要求每个 finding 恰好出现一次，且 `paperEvidenceIds` 与评审快照完全一致。
