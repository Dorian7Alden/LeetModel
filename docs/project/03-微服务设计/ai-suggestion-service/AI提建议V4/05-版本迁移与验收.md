## 版本迁移与验收

> 设计状态：已完成实现并经验收。


### 一、迁移

- 新增 `GROUNDED_SUGGESTION_V4` 版本目录和 Prompt。
- V4 输入优先使用 `DEEP_EVIDENCE_REVIEW_V4`。
- 历史评审需要生成 V4 建议时，必须先产生独立 V4 评审，不覆盖旧评审。
- V1-V3 建议报告继续按原 Schema 展示。
- 正式入口切换必须在真实链路验收后进行。
- 历史任务 `retrieval_workflow_version` 为空时，V3/V4 回退到
  `SUGGESTION_DEEP_RETRIEVAL_V1`，旧工作流回退到 `VECTOR_RAG_V1`；
  检索成功后把实际版本写回任务，避免知识服务因空版本参数拒绝请求。


### 二、自动化测试

- 三类 `guidanceType` 正负路径。
- 主观建议禁用措辞检测与单项丢弃。
- `REQUIRED_FIX` 缺评审依据时拒绝。
- 原文 Markdown 由真实解析块生成。
- 知识引用适用性和版本校验。
- P0-P3 与三类语义的稳定排序。
- 公式、代码、表格、引用块和 XSS 清洗。
- V3 历史报告兼容。
- 锁定评审问题一一覆盖、重复引用去重、漏项同主题兜底和证据一致性测试。
- 引用 `ISSUE` 的候选强制升级为 `REQUIRED_FIX` 的测试。
- 反演欠定、参数不可辨识等主观建模问题的替代路径屏蔽测试。
- 可选探索直接指令措辞改写测试。


### 三、真实验收

1. 官方优秀论文：不得要求替换合理模型，应以保留亮点和完善方向为主。
2. 明确错误论文：确定性错误应形成 `REQUIRED_FIX`。
3. 方法简单但自洽论文：只能提供 `OPTIONAL_EXPLORATION`，不得说当前方法错误。
4. 要素缺失论文：明确使用“补充……说明”。
5. 中英文论文：Markdown、公式和知识依据均可读。
6. 官方优秀论文：5 个锁定问题均形成独立必要修正，建议不混入其他问题内容。


### 四、产品验收

- 用户能清楚区分“必须修正”和“可选探索”。
- 每条建议独立说明原因、依据和边界。
- 不出现强迫替换模型、指定唯一参数或结果承诺。
- 资料库来源对用户可见且与建议有关。
- 建议比通用聊天回答更具体，但不越界成为代写或唯一解。
- 用户能展开每个问题的原文依据，表格内公式正常渲染，正文没有省略号截断。
