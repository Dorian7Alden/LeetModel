## 工具调用契约

> 实现状态：S11-01 已于 2026-08-31 落地公共 DTO、兼容构造器、Bean Validation 与序列化测试；业务工具注册和执行仍归后续任务。

### 目标

在不让公共模块理解业务工具的前提下，为所有 AI 业务服务提供供应商无关的工具调用协议。首个消费者是 ai-assistant-service，后续业务服务只有出现真实需求时才复用。

### 请求契约

`AiChatRequest` 新增可空字段：

| 字段 | 类型 | 语义 |
|------|------|------|
| `tools` | `List<AiToolDefinition>` | 当前调用允许模型选择的工具定义；空集合表示不提供工具 |
| `toolChoice` | `AiToolChoice` | `AUTO`、`NONE`、`REQUIRED` 或指定工具名称 |

`AiToolDefinition` 包含 `name`、`description` 和 `inputSchema`。首版只支持 `FUNCTION` 类型，名称必须符合 `^[a-z][a-z0-9_]{0,63}$`，Schema 必须是 JSON Object 且禁止远程引用。

工具定义只描述模型可以提出的调用，不携带执行地址、Java 类名、用户身份或权限信息。

### 消息契约

`AiMessage` 在现有 `role` 和 `content` 之外新增可空字段：

- `toolCalls`：仅 `ASSISTANT` 消息使用，保存模型提出的一个或多个结构化调用。
- `toolCallId`：仅 `TOOL` 消息使用，关联对应的供应商工具调用标识。
- `toolName`：仅 `TOOL` 消息使用，用于诊断和供应商协议映射。

`AiToolCall` 包含 `id`、`name` 和 `argumentsJson`。`argumentsJson` 保持模型返回的原始 JSON 字符串，公共模块不把它绑定到业务 DTO。

消息合法性规则如下：

- 普通 `SYSTEM` 和 `USER` 消息仍需要非空文本内容。
- 带 `toolCalls` 的 `ASSISTANT` 消息允许文本内容为空。
- `TOOL` 消息必须包含非空 `toolCallId` 和工具结果文本内容。
- `toolCallId` 必须与当前对话中最近一条助手工具调用对应，业务服务负责执行前校验。
- 同一消息不能同时作为工具调用发起消息和工具结果消息。

### 响应契约

`AiChatResponse` 新增 `toolCalls`。以下两种响应均合法：

- 最终回答：`content` 非空，`toolCalls` 为空。
- 工具请求：`toolCalls` 非空，`content` 可以为空，停止原因通常为 `tool_calls`。

响应不能同时缺少 `content` 和 `toolCalls`。AI 网关只保证结构合法，不校验工具名称是否属于某个业务工具集。

### 模型能力

请求的 `tools` 非空时，AI 网关必须验证锁定模型配置的 `tools=true`。模型执行配置还要锁定工具调用是否允许，避免只修改模型能力目录就让历史工作流获得新能力。

`toolChoice=REQUIRED` 只表示模型必须选择请求中某个工具，不代表 AI 网关授权执行。真正的工具白名单和权限仍由业务服务校验。

### OpenAI 兼容映射

| 统一字段 | OpenAI 兼容字段 |
|----------|-----------------|
| `AiToolDefinition` | `tools[].type=function` 和 `tools[].function` |
| `AiToolChoice.AUTO` | `tool_choice=auto` |
| `AiToolChoice.NONE` | `tool_choice=none` |
| 指定工具 | `tool_choice.function.name` |
| `AiToolCall` | `choices[].message.tool_calls[]` |
| `AiMessage.toolCalls` | `messages[].tool_calls` |
| `AiMessage.toolCallId` | `messages[].tool_call_id` |

首版只在 new-api 的 OpenAI Completions 协议启用工具映射。其他协议在完成独立契约测试前返回能力不支持，不做有损转换。

### 兼容性

- 所有新增字段可空，旧 JSON 请求和响应继续有效。
- Java record 增加字段时保留现有构造器重载，避免已有业务调用方一次性编译失败。
- 不修改现有不带工具请求的供应商 JSON。
- 旧工作流的模型执行配置保持 `tools=false`，不会因公共协议升级获得工具能力。
- 工具协议字段发布后只能增加可选字段，不能原位改变现有枚举和消息关联语义。

### 边界

common-ai 不负责以下事项：

- 不解析业务参数，不执行工具。
- 不维护工具注册表和工具集版本。
- 不记录完整工具参数和结果。
- 不实现工具调用次数、超时、权限和重试策略。
- 不把供应商工具 SDK 暴露给业务服务。
