## 迁移与实施边界

> 设计状态：目标迁移路线，尚未开始实施。每个阶段都必须形成独立任务卡并单独验收。

### 当前基线

当前文件能力分散在多个服务：

- common-core 提供通用 StorageService 和 MinIO 实现。
- user-service 保存 avatarPath 并直接生成访问地址。
- problem-service 保存 problem_attachment.objectKey 和附件元数据。
- submission-service 拥有论文分片、合并和正式提交文件。
- ai-review-service 等内部消费者根据业务链路读取论文对象。
- admin-service 保持无状态，只代理下游管理接口。

当前共享 Bucket 的对象路径可以帮助识别来源，但不是完整、可靠的文件资产台账。

### 迁移原则

- 不做一次性切换，按文件类型逐个迁移。
- 不在 file-service 尚未稳定时删除业务表中的 objectKey。
- 不把历史对象自动判断为孤儿文件。
- 不要求所有二进制流量经 file-service 中转。
- 不让两个服务同时成为同一文件关系的权威写入者。
- 每个阶段都保留可验证的回退路径和对账报告。

### 第一阶段

第一阶段建立文件资产控制面的最小闭环：

1. 创建 file-service Maven 模块、独立 lm_file 数据库和基础配置。
2. 建立 file_asset、上传会话、基础生命周期和管理查询。
3. admin-service 新增 file-service 管理代理，不直连 lm_file。
4. 管理员只能向 manual namespace 上传和分组。
5. 支持文件列表、下载、复制临时链接、逻辑删除和延迟物理清理。
6. 扫描现有 MinIO 对象并登记为 DISCOVERED。
7. DISCOVERED 对象默认只读，完成归属确认前不能从控制台物理删除。

这一阶段不宣称已经完成跨服务引用治理。

### 第二阶段

先迁移题目附件，原因是当前需求明确、关系结构简单、管理入口已经存在：

1. problem_attachment 增加 fileId，迁移期保留 objectKey。
2. 新附件通过 file-service 创建资产。
3. problem-service 在本地事务写入附件关系和绑定 Outbox。
4. 附件删除改为解绑事件，物理清理由 file-service 完成。
5. 历史题目附件按 objectKey 关联已登记资产。
6. 对账无差异后再评估移除 problem-service 的 MinIO 写权限。

压缩包上传策略按 PROBLEM_ATTACHMENT 用途配置，不扩大头像等其他用途白名单。

### 第三阶段

迁移用户头像和正式论文：

- user-service 使用 fileId 保存当前头像关系，并通过绑定事件更新投影。
- submission-service 将合并完成的正式论文登记为文件资产。
- 论文版本和最终提交仍由 submission-service 管理。
- ai-review-service 通过提交服务或 file-service 的受控临时能力读取正式论文。
- 业务迁移完成并通过对账后，回收对应服务对正式资产 Bucket 的宽权限凭证。

### 临时分片边界

论文上传分片首期不进入通用 file_asset。它具有高频、短生命周期、合并与批量清理语义，继续由 submission-service 管理更符合数据所有权。

可以为分片使用独立临时 Bucket、受限凭证和 MinIO 生命周期过期策略。file-service 只在分片合并完成后登记正式论文资产。

### 旧对象状态

历史扫描对象统一进入 DISCOVERED，并区分：

- 已通过业务 objectKey 找到明确所有者。
- 只能根据前缀推测来源，尚未确认。
- 完全未知来源。
- 数据库存在引用但物理对象缺失。

路径前缀只用于候选分类，不直接产生绑定，也不作为删除依据。归属确认应来自业务数据快照或业务所有者事件。

### 验收门槛

每种文件完成迁移前至少验证：

- 上传成功、上传失败和重复请求幂等。
- 同名文件不会覆盖。
- 预签名地址按访问策略和有效期生成。
- 业务绑定和解绑事件可重试、可去重。
- 引用存在时删除被阻断。
- 最后引用解除后只进入宽限期，不立即物理删除。
- MinIO 删除失败可以定位和重试。
- MinIO、file_asset 与业务关系对账无未解释差异。
- 下游服务不可用时不会将未知引用误判为零引用。

### 暂缓事项

- 服务端静态资源动态替换。
- Markdown 外链自动下载和本地化。
- 文件内容安全扫描和压缩包解压。
- 自动内容去重和多个业务共享同一物理对象。
- 面向公网的永久资产 CDN 路由。
- 管理员强制删除仍有引用的文件。
