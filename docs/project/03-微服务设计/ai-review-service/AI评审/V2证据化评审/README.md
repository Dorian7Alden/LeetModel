## V2 证据化 AI 评审

> 实现状态：S12 已发布 `EVIDENCE_REVIEW_V2`，新提交显式创建该版本；V1 代码、结果表和历史展示保持不变。

`EVIDENCE_REVIEW_V2` 在完整题面和版本化 PDF 解析产物基础上执行评审。它不仅产生总分，还保存题目覆盖、评分理由、结构化发现和页码证据，为用户理解评分和后续 AI 建议提供可引用事实。

### 范围

- PDF 解析是执行评审前的强制步骤。
- 评审读取完整题面，逐项核对题目要求。
- 评分理由必须引用结构化论文证据。
- 输出区分评审发现和修改建议，评审不负责检索资料或生成完整辅导方案。
- V2 结果使用独立 schema 和结果存储，不修改 V1。

### 非目标

- 不覆盖 `BASIC_REVIEW_V1` 的 Prompt、流程或历史结果。
- 不在本版本中接入知识检索服务。
- 不替用户验证未写入论文的代码、数据或实验结果。
- 不把平台训练分数宣传为赛事官方分数。

### 用户展示

评审详情页不再只展示总分。页面先展示“平台训练评分”声明、总分和整体说明，再展示六项分项得分与扣分理由、题目要求覆盖情况，以及可按严重程度和类别筛选的优点 / 问题发现。

用户点开某个要求、评分理由或发现时，能查看物理 PDF 页码、章节、简短证据和解析风险。历史 V1 评审仍按 V1 结构展示，不用空字段伪造 V2 说明。

### 实现入口

- 工作流：`EvidenceReviewV2Workflow`，固定六项量表并由服务端确定性汇总总分。
- 结果：Flyway V4 新建 `review_v2_result`，与 `review_v1_result` 分表保存。
- 创建：submission-service 对新论文调用版本化内部接口；旧 `/internal/reviews/tasks` 继续保持 V1 语义。
- 展示：队伍详情页按 `workflowVersion` 分别渲染 V1 与 V2，V2 展示评分理由、要求覆盖、发现和页码证据。
