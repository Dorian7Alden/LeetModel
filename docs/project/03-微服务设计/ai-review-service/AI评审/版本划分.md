## 版本划分

本文的 V1、V2 是评审 `workflowVersion` 的展示简称，正式标识使用带领域含义的稳定编码，不能写成 HTTP 路径 `/v1`。各类版本的统一字段、所有权和不可变规则见 [AI版本标识.md](../../../02-架构设计/AI版本标识.md)。

评审版本代表一套完整工作流，不只代表模型名称或 Prompt。

工作流版本与模型执行配置相互独立。工作流版本固定步骤、依赖、处理逻辑和业务输出语义；模型执行配置将工作流中的每个 AI 步骤绑定到精确模型、Prompt 版本和参数快照。

| 版本 | 定位 | 设计目标 | 状态 |
|------|------|----------|------|
| `BASIC_REVIEW_V1` | 基础评审 | 提示词与 PDF 页面图像一次性交给多模态模型，直接产生最终得分和 V1 评语 | 已实现 |
| `EVIDENCE_REVIEW_V2` | 证据化评审 | 强制结构化解析，先检查题目要求覆盖和论文证据，再按平台训练规则分项打分并输出稳定发现 | 已实现 |
| 后续版本 | 待设计 | 只在有新业务步骤、依赖、校验或输出语义时新建，不用“过度”作为无法验收的设计目标 | 未设计 |

所有版本共享相同公共输入，并在结束时产生同名、同类型和同语义的 `score`。版本专属过程 JSON 不要求一致，版本差异可以体现在 PDF 预处理、模型调用次数、小任务拆分、多轮对话、步骤编排、校验和仲裁等中间流程。

同一工作流版本可以使用不同 `modelExecutionConfigVersion` 进行实验，不需要复制工作流代码或创建新的评审版本。每次正式评审或实验运行创建时必须同时锁定 `workflowVersion`、各步骤 `promptVersion` 和 `modelExecutionConfigVersion`；运行过程中不得切换成另一模型或 Prompt。评价结果保留这些标识，避免把流程、提示词与模型能力差异混为一谈。

工作流步骤、依赖关系、程序处理逻辑或业务输出语义发生变化时必须建立新评审版本。可以复用旧代码或重新实现，但不得覆盖已发布版本。只修改某一步骤使用的模型、模型参数或账号资源池，且不改变业务语义时，创建新 `modelExecutionConfigVersion` 而不改工作流版本。

V1 不执行文本提取、章节拆分或独立 PDF 解析，只把 PDF 渲染为模型支持的有序页面图像。页面渲染是输入协议适配，不产生可复用的解析产物。V2 必须使用达到质量门的版本化 PDF 解析产物。

版本特征只是设计目标，最终表现必须使用相同测试集重复运行，并以 ai-evaluation-service 的评价结果为准。
