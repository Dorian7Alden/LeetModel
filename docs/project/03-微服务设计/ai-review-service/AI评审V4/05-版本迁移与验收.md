## 版本迁移与验收

> 设计状态：已完成实现并经验收。


### 一、迁移原则

- Flyway 新增 V4 版本目录和结果表，不修改 V3 迁移。
- 正式生产入口切换到 V4 前，V3 继续可创建和读取。
- V4 上线后，历史 V1-V3 结果仍按原 Schema 展示。
- 排行榜继续只消费 `score` 和工作流版本，不读取 Markdown 正文。
- 建议服务只有在兼容 V4 投影完成后才使用 V4 评审作为原生依据。


### 二、前端兼容

| 版本 | 展示策略 |
|------|----------|
| V1 | 历史基础评审布局 |
| V2 | 历史证据化布局 |
| V3 | 当前五维评分布局 |
| V4 | 专业 Markdown、问题/亮点分组和可展开证据 |

禁止把 V3 普通字符串字段按 V4 Markdown 语义重新解释。


### 三、自动化测试

- DTO JSON 往返，覆盖 `$`、`\`、引号、代码围栏、HTML 表格和中文。
- 原文证据补全覆盖段落、公式、表格、代码和图像描述。
- 无效 `blockId`、页码、知识引用和外部图片 URL 拒绝。
- 问题 P0-P3 和亮点重要度排序稳定。
- 重复 Finding 去重。
- V3 历史结果读取回归。
- Markdown 前端公式、表格、代码和 XSS 清洗测试。


### 四、真实验收样本

至少使用：

1. 英文官方优秀论文：验证优点充分、公式摘录和主观建议克制。
2. 中文普通论文：验证问题排序和知识依据针对性。
3. 明确漏答样本：验证 P0。
4. 公式密集样本：验证 LaTeX 转义与 KaTeX。
5. 图表密集样本：验证图像描述，不生成外链。


### 五、完成标准

- 每条问题和亮点都能展开真实原文。
- 综合评语、维度说明、覆盖说明和 Findings 公式均能渲染。
- 问题顺序符合服务端排序。
- 不出现模型编造原文、页码或知识来源。
- V4 与 V3 并存，历史报告无语义变化。
- 真实用户能够从报告中理解“为什么得到这个判断”，而不是只看到标签和分数。
