## 版本目标与业务边界

> 设计状态：已完成实现并经验收。


### 一、用户最终获得什么

V4 评审报告不再只展示总分、简短结论和问题列表。用户应能在一个报告中快速回答：

- 论文做得好的地方是什么，为什么值得保留；
- 当前最重要的问题是什么，为什么影响可信度或完整性；
- 判断引用了论文哪一页、哪一段、哪个公式或表格；
- 该判断属于赛事要求、数学逻辑、结果验证还是表达规范；
- 哪些结论是确定性硬伤，哪些只是可以继续完善的空间。


### 二、评审职责

V4 负责：

- 保持五维训练评分和题目覆盖判断；
- 输出详细 Markdown 综合评语和维度说明；
- 同时生成 `STRENGTH` 和 `ISSUE`；
- 为 Findings 补充真实原文 Markdown 证据；
- 根据影响程度确定性排序问题；
- 展示相关知识依据及其适用性；
- 保留物理页码、解析块和版本快照。

V4 不负责：

- 给出完整的论文修改方案；
- 指定唯一正确的模型或算法；
- 根据知识库内容重新解释论文中不存在的事实；
- 代写摘要、公式推导、代码或结论；
- 覆盖 V3 历史结果。


### 三、评分与解释的关系

分数仍由服务端按版本化量表确定性计算。Markdown 说明用于解释分数，不参与前端二次计分。

每个维度的说明必须覆盖：

1. **当前表现**：该维度整体处于什么水平。
2. **主要依据**：哪些优点和问题共同支持该判断。
3. **影响解释**：为什么这些事实会影响该维度，而不是泛泛评价。
4. **边界声明**：不能从现有证据确定的内容必须明确写为“无法核实”，不能按缺失直接扣分。


### 四、专业与克制

评审可以明确指出数学错误、量纲错误、漏答、前后矛盾和证据缺失。
对于合理但不唯一的建模选择，只评价其自洽性、适用性、证据和局限，不因为没有使用某个更复杂方法而直接判错。

专业性来自证据和适用性判断，不来自堆砌算法名、拉长文本或使用夸张的“国奖标准”措辞。
