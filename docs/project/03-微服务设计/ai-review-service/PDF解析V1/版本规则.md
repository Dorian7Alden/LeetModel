## 版本规则

### 解析工作流版本

`paperParsingWorkflowVersion` 属于统一的 `workflowVersion` 类型，用于锁定一套 PDF 解析步骤、依赖、质量规则和业务输出语义。目标首版设计编码为 `PAPER_PARSE_V1`，产物 schema 为 `PAPER_DOCUMENT_V1`；只有实现后进入版本目录并发布，它们才成为运行事实。

解析步骤、分支、确定性规则、质量语义或产物结构发生变化时必须发布新版本。只替换 OCR 或多模态步骤的精确模型和参数时更新对应 `modelExecutionConfigVersion`；Prompt 内容变化更新 `promptVersion`。

### 产物 schema

解析产物使用独立 schema 编码，例如 `PAPER_DOCUMENT_V1`。工作流版本声明产生的 schema，评审版本声明接受的 schema。字段语义或必填性不兼容时升级 schema，并通过新解析工作流产生新产物。

### 复用键

只有提交标识、原始文件摘要、解析工作流版本和产物 schema 全部一致时才可以复用解析产物。复用返回具体产物标识，不返回可漂移的“当前解析结果”。

### 不可覆盖

新解析版本、新模型配置或重新解析都产生新运行事实。历史解析任务、产物、质量风险和被哪些评审引用的关系永久保留；已引用产物只能标记不可用于新任务，不能原地修正正文或质量结果。

### 版本展示

用户页面重点展示评审版本，不强迫普通用户理解全部解析技术。评审详情的“运行依据”区域应提供解析版本与质量摘要；管理端和问题排查接口同时展示解析工作流、产物 schema、Prompt、模型执行配置和调用标识。
