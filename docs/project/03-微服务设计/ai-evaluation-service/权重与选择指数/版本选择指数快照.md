## 版本选择指数快照

S8-03 把版本化权重方案应用到可信原始指标，生成首版 `versionSelectionIndex`。该结果只表达“在锁定数据集、指标口径、执行配置和权重偏好下的版本选择适配度”，不能称为准确率、客观质量分、综合质量分或自动上线结论。

### 任务启动快照

新任务必须提供 `weightSchemeId`。评价服务只允许锁定 `ACTIVE` 且与任务 `featureCode`、`metricSetVersion` 一致的方案，并在 `evaluation_task` 保存：

- `weightSchemeId` 与 `weightSchemeVersion`；
- 包含全部指标、归一化参数、权重和创建审计的 `weightSchemeSnapshotJson`。

任务执行后不回查当前方案。即使方案随后停用，任务仍使用启动快照完成，避免一次实验在途改变偏好。V8 新列对历史任务保持可空，旧任务无需伪造方案即可继续读取。

### 原始指标证据门禁

指数只消费任务终态的 `rawMetricsJson`：

- 成功率与结构有效率直接读取任务层可信事实。
- Token 只有全部调用 usage 完整时可用。
- 费用只有全部调用都是同一币种的供应商实际费用、没有估算或缺失时可用。
- 排队、执行和总耗时只有全部调用耗时完整时可用。
- REVIEW 均值按完整样本统计取平均；方差、标准差和极差要求每个样本都达到 `COMPLETE`。
- 客服指标只有证据覆盖状态为 `AVAILABLE` 时可用；`PARTIAL`、`NOT_EVALUATED` 和 `NOT_APPLICABLE` 保持原状态。

资源或证据不完整时不能使用已知部分制造可比指数。原始状态与空值会进入逐项结果，不转换成零。

### 结果版本与公式

任务首次完成生成 `SCORE_RESULT_V1`。`evaluation_score_result` 同时快照完整权重方案 JSON 和原始指标 JSON；`evaluation_score_result_item` 对每个指标保存：

- 指标/归一化版本；
- `rawAvailability` 与可选 `rawValue`；
- `normalizationAvailability` 与可选 `normalizedValue`；
- `weightPercent` 与可选 `contributionValue`。

单项贡献为 `normalizedValue × weightPercent / 100`，结果统一保留六位小数。全部权重项可用时，`versionSelectionIndex = Σ contributionValue`，状态为 `CALCULATED`；任一项不可用时，状态为 `UNAVAILABLE`、指数为空，并列出缺失指标。其他可用项的原值和贡献仍保留用于诊断。

任务完成状态、可信原始指标和首版结果在同一数据库事务保存。任务完成条件更新只接受 `WAITING/RUNNING`，并发第二次完成不能创建重复 `SCORE_RESULT_V1`。旧 `overallScore` 仍按历史兼容逻辑保存，但不参与新指数，也不会被覆盖或改名。

### 验收基线

- 确定性用例使用成功率 `80`、总耗时 `2500ms`，固定边界归一化得到 `80`、`75`，按 `60%/40%` 贡献 `48 + 30 = 78`。
- 缺失耗时用例保留成功率贡献，但整体指数为空且耗时原值、归一化值、贡献值均为空。
- 评价模块 79 项、admin-service 8 项测试零失败，两个模块的直接依赖测试同步通过。
- MySQL 8.0.33 临时库真实执行 V1→V8，结果指数和贡献和均为 `78.000000`、权重和为 `100.0000`，方案/原始指标 JSON 有效且结果版本唯一索引生效；验收库随后删除。
