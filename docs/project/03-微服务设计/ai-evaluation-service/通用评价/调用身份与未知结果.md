# 调用身份与未知结果

## 三层身份

评价调度使用三层稳定身份，所有字段都只用于关联和幂等，不携带样本正文：

| 层级 | 形式 | 生命周期 |
|------|------|----------|
| task | 评价任务 ID | 一次评价任务 |
| slot | `taskId:sampleId:repetitionNo` | 一个逻辑统计槽位 |
| attempt | `evaluation:taskId:slotKey:attempt:attemptNo` | 一次物理派发尝试 |

`experimentRunId` 绑定逻辑槽位，恢复尝试不改变；`idempotencyKey` 绑定物理 attempt，同一 attempt 因同步等待超时再次查询时复用，明确可恢复失败创建新 attempt 时才生成新键。`evaluationTaskId`、slotKey、attemptNo 和 idempotencyKey 从评价 Runner 传给业务 owner，再进入 AI 网关的 `AiCallContext`。成功或失败响应携带 callId 时，评价尝试必须保存该关联。

## 优先级

评价请求在评价服务和业务 owner 两侧都固定校验 P3，AI 网关仍以自身优先级策略作为最终裁决。正式客服交互保持 P0，因此可在评价积压时优先执行；公平调度仍为 P3/P4 保留执行机会，避免后台任务永久饥饿。

## 结果不确定性

- `PENDING`：同步等待窗口结束，但网关任务仍在处理。评价 attempt 回到 WAITING，后续使用同一个幂等键查询，不创建第二个上游任务。
- `UNKNOWN`：上游已确认接收后发生异常，是否完成不可判定。网关返回专用错误码 51213；owner 和评价服务保留 UNKNOWN，不折叠成普通依赖失败。
- `ENVIRONMENT` / `CONFIGURATION`：只有明确知道上游没有产生不可判定副作用时才允许管理员创建新 attempt。
- `OUTPUT`：调用已得到结果但不符合业务输出契约，属于可比较的业务失败，不进行环境重试。

评价进程重启后只领取 WAITING attempt，SUCCEEDED 槽位不会重复派发。进程中断遗留的 RUNNING attempt 因无法证明上游未执行，一律转为 UNKNOWN，不自动创建恢复 attempt；UNKNOWN 也不允许通过普通重试入口盲目重试。

## 任务控制

- 暂停只把任务转为 PAUSED；领取 SQL 同时校验任务状态，因此暂停完成后不会再派发 WAITING 槽位。已经运行的调用可以完成，结果仍写入原 attempt，回调不得覆盖 PAUSED。
- 恢复把 PAUSED 转回 WAITING，并从尚未终态的槽位继续；成功、失败和未知历史不重建。
- 取消把任务转为 CANCELLED，把未派发槽位标记为 CANCELLED，并按 evaluationTaskId 查询网关活动调用、请求取消仍可取消的队列项。已经派发且无法取消的结果仍可留痕，但不得覆盖任务终态。
- 暂停、恢复和取消都由 admin-service 从登录上下文取得操作者 ID，评价任务保存最近操作者、动作与时间。控制接口不能接受浏览器自行声明的操作者。
- CANCELLED 不删除任务、槽位或 attempt；COMPLETED 和 CANCELLED 均不能再次暂停、恢复或取消。
