# 口径快照与可比性

## 不可变快照

评价任务创建时保存以下条件，后续注册表、展示或默认配置改变不回写历史任务：

- `featureCode` 与 `workflowSnapshotJson`；
- `datasetId` 与不可变 `datasetVersion`；
- `modelExecutionConfigVersion` 和适用时的 `ragIndexVersion`；
- `metricSetVersion` 与完整 `metricDefinitionSnapshotJson`；
- `repeatCount`、任务槽位和各次尝试事实。

`metricDefinitionSnapshotJson` 不只保存版本号，还保存当前功能适用的每个指标定义，以及百分比精度、统计精度、总体方差分母、缺失值策略、标准要点匹配、来源匹配和格式规则集版本。比较时 JSON 对象按结构语义比较，不依赖字段序列化顺序。

S7-03 的基础注册表为 `METRIC_SET_V1`。S7-12 新增标准要点文本覆盖指标后，S7-13 将新任务口径提升为 `METRIC_SET_V2`；历史 V1 结果继续可读，但不得与 V2 混合排名。

## 比较门禁

比较请求先固定同一个 `datasetId` 和 `repeatCount`，再逐个校验：

| 条件 | 判定 |
|------|------|
| `featureCode` | 必须与数据集功能一致 |
| `datasetVersion` | 每个任务快照必须与当前锁定数据集版本一致 |
| `metricSetVersion` | 所有候选必须相同且非空 |
| 指标定义和参数快照 | 所有候选必须结构语义相同且非空 |
| `modelExecutionConfigVersion` | 所有候选必须相同且非空 |

候选身份由 `workflowVersion + modelExecutionConfigVersion + ragIndexVersion` 组成，每个身份只取最近一个已完成任务。

只有至少两个候选且全部条件相同时，响应 `comparable=true`、`rankingApplied=true`，才允许按旧兼容分数字段排序。任一条件不同则：

- `comparable=false`、`rankingApplied=false`；
- 返回具体 `incompatibilityReasons`；
- 候选保持查询的最近顺序，仅供并排审阅；
- 管理页面显示黄色“仅并排展示，不执行排名”提示。

这项门禁只解决实验条件是否一致，不表示旧 `overallScore` 已成为正式质量指标。版本选择指数仍由后续权重与归一化阶段实现。

## 数据迁移与验收

V6 迁移从锁定数据集回填历史任务的 `dataset_version`，随后改为非空并建立比较条件联合索引。真实 MySQL 8.0.33 已验证 V1→V6 连续迁移，`dataset_version` 为非空 `VARCHAR(64)`，联合索引包含四列。

测试覆盖同口径排名、不同 metricSet/参数快照拒绝排名、JSON 字段顺序不影响语义比较，以及任务创建时保存数据集版本和完整参数快照。评价及公共依赖 58 项测试和管理端生产构建通过。
