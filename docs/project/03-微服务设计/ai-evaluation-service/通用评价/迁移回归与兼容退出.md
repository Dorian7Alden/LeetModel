## 兼容策略

历史任务继续通过现有 `/internal/evaluations/**` 和 `/admin/ai/evaluations/**` 路径读取，不建立第二套 legacy API。兼容投影遵守：

- `LEGACY_REVIEW_METRICS_V1` 与 `METRIC_SET_V1/V2` 原样返回，不伪装成同一口径；
- 历史 `overallScore` 只显示为“旧口径分”，不命名为综合质量分；
- 历史 `rawMetrics` 缺失返回 `null`，不回算、不补零；
- legacy 任务可以详情查看，但与新口径比较时 `comparable=false`；
- 所有新任务只写通用字段和版本化快照。

## 兼容退出条件

旧字段和旧 DTO 投影不能凭时间自动删除。必须同时满足以下门槛，才允许在单独迁移阶段提出删除：

1. 所有环境的 Flyway schema 至少到 V6，且数据审计确认 task 的 feature、datasetVersion、执行配置、metricSet 和定义快照均符合对应迁移规则。
2. S8/S9 的原始指标视图与 `versionSelectionIndex` 已替代管理端对 `validityScore`、`stabilityScore`、`latencyScore` 和 `overallScore` 的读取。
3. API 调用审计连续两个正式发布周期没有旧字段专用消费者；内部 Feign 与前端契约测试也不再引用它们。
4. 已提供历史结果导出或等价只读路径，并完成一次生产备份恢复演练。
5. 删除方案使用新的 Flyway 迁移和 API 主版本变更，经过单独评审；不得在普通功能提交中顺带删除。

在五项全部满足前，旧列只读保留、旧分数明确标记、比较门禁持续生效。这给出了可验证的结束条件，同时不承诺提前删除历史数据。
