# 批次规模预估

评价任务创建前必须调用 `POST /api/admin/ai/evaluations/estimates`，由服务端使用与创建任务相同的版本校验和规模限制返回预估结果。管理端入口受 `admin` 角色保护；创建接口还会重新执行同一校验，前端确认不能替代服务端约束。

## 计算口径

- 总槽位数：`样本数 × 候选版本数 × 重复次数`。
- REVIEW 与无 RAG 客服：每个槽位预计一次模型调用。
- RAG 客服：每个槽位预计两次模型调用，分别为向量检索前的 embedding 和回答生成。
- 所有评价调用固定为 P3，不允许评价流量占用交互请求的优先级。
- 创建前没有真实 Token 用量和可追溯价格快照，因此费用状态固定为 `UNAVAILABLE`，金额和币种为空。系统不得用虚构单价给出伪精确成本；运行后再按 callId 聚合实际或明确标记为估算的费用。

## 默认限制

| 维度 | 默认上限 | 配置项 |
|------|---------:|--------|
| 单数据集样本数 | 100 | `evaluation.limits.max-samples` |
| 单批候选版本数 | 8 | `evaluation.limits.max-versions` |
| 重复次数 | 20 | `evaluation.limits.max-repeat-count` |
| 总槽位数 | 2000 | `evaluation.limits.max-total-slots` |
| 预计模型调用数 | 3000 | `evaluation.limits.max-estimated-calls` |

公共请求契约保留 100 次重复和 20 个候选的协议安全上限，实际放行值由评价服务配置决定。任一维度超限时，预估响应返回全部违规原因且 `withinLimits=false`；创建任务返回 `SCALE_LIMIT_EXCEEDED`，避免绕过预估接口。

候选项由工作流版本、模型执行配置版本和可选 RAG 索引版本共同标识，同一批次不得重复。REVIEW 只能使用固定多模态配置且不能携带 RAG；客服 RAG 版本必须锁定物理索引，无 RAG 版本不得携带索引。
