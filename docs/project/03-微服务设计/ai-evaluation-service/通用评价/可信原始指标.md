# 可信原始指标

## 边界与口径

S7-11 最初使用 `METRIC_SET_V1` 作为原始指标集版本；新增指标会创建新的 metricSetVersion，不改变历史快照。原始指标只保存可复算的运行、资源和稳定性事实，不执行归一化、不应用权重，也不产出准确率或客观质量结论。

- `ai-gateway-service` 以 `evaluationTaskId` 聚合模型调用日志，不返回请求或响应正文。
- `ai-evaluation-service` 聚合槽位结果，将网关事实和按样本统计保存到 `evaluation_task.raw_metrics_json`。
- `admin-service` 仅转发；管理页面原样展示指标、单位和完整性。

任务每次刷新终态指标时生成完整 JSON 快照。历史快照不会因后续价格、权重或展示规则改变而被重新解释。

## 运行和资源事实

任务层记录总槽位、成功槽位、成功率和失败分类。失败优先按 `failureType` 分类；没有分类时保留槽位状态，不能归入成功。

网关层记录：

- 调用总数、成功数和失败数；
- 输入、输出、推理、缓存命中、缓存创建、缓存未命中和总 Token；
- 按币种分组的费用合计、供应商实际费用数、估算费用数和缺失费用数；
- 平均排队、执行、总耗时和耗时缺失数。

Token 某字段没有任何观测值时返回 `null`，费用没有完整金额和币种时不进入合计。页面显示“未提供”，不得将缺失解释为零消耗或免费。部分调用缺失 usage、费用或耗时时，已知值仍可聚合，同时必须展示缺失计数。

调用审计完整性按期望调用数与实际网关日志数判断：无日志为 `MISSING`，少于期望为 `PARTIAL`，达到期望为 `COMPLETE`。REVIEW 和无 RAG 客服每槽位期望一次调用，`ASSISTANT_RAG_V1` 每槽位期望检索与回答两次调用。

## REVIEW 描述统计

REVIEW 只对状态为 `SUCCEEDED` 且存在分数的重复结果按样本计算。设有效分数为 `x₁...xₙ`：

- 均值：`μ = Σxᵢ / n`；
- 总体方差：`σ² = Σ(xᵢ - μ)² / n`；
- 标准差：`σ = √σ²`；
- 极差：`max(x) - min(x)`。

这里使用总体方差，因为固定重复次数覆盖的是本次实验总体，不以样本方差估计外部总体。均值保留 6 位小数；方差、标准差和极差仅在至少两个有效结果时计算。完整性状态为：

| 状态 | 含义 |
|------|------|
| `MISSING` | 没有有效结果，全部统计量为空 |
| `INSUFFICIENT` | 只有一个有效结果且已达到预期重复数，只提供均值 |
| `PARTIAL` | 有有效结果但少于预期重复数；不足两个时离散统计量为空 |
| `COMPLETE` | 达到预期重复数且可计算全部统计量 |

结构有效率当前等于成功产出符合 owner 契约结构的槽位比例。结构解析失败进入 `OUTPUT` 失败，因此它描述格式可用性，不证明内容正确。

## 验收基线

- 确定性单测以分数 80、90 验证均值 85、总体方差 25、标准差 5、极差 10。
- 单次和部分缺失重复明确返回不可计算的离散统计量。
- 缺失 usage 和费用保持 `null` 并累计缺失数。
- 真实 MySQL 8.0.33 已验证评价库 V1→V5 连续迁移，快照列为可空 `LONGTEXT`。
- 评价、网关及公共依赖共 146 项测试通过，管理端生产构建通过。
