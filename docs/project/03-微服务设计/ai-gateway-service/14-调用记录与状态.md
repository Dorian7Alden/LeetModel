## 调用记录与状态

> 实施状态：S2 已完成调用审计与计量，S5 已增加持久化原子调用任务、attempt、租约、恢复与 UNKNOWN 状态。new-api 内部渠道尝试仍不复制到 LeetModel。

### S2 当前实现

`ai_call_log` 仍是一行对应一次 LeetModel 原子调用，不复制 new-api 渠道尝试。V2 以兼容扩列迁移保存：

- `call_id`、`provider_response_id` 与可空 `new_api_request_id`，三者不混用。
- `modality`、`caller_service`、`feature_code`、`operation_code`、业务/评价任务 ID、五类版本中当前调用适用的引用、优先级、幂等键和 UTC deadline。
- 输入、输出、推理、缓存命中/创建/未命中、总 Token 及 usage 完整性。
- `queue_ms`、`execution_ms`、`total_ms`；当前调度链记录实际排队、执行和总耗时。
- Decimal 费用、币种、来源、价格快照版本及费用完整性。
- 状态、统一错误和创建/更新时间。

V1 的 `scene`、`prompt_tokens`、`completion_tokens`、`usage_complete` 和 `duration_ms` 暂时保留并回填到新列，保证历史行和旧查询可读；新写入同时维护必要兼容列。迁移把无法归因的历史来源明确标为 `LEGACY/LEGACY_CHAT`，不会伪装成客服或评审调用。

索引覆盖唯一 `callId`、状态加时间、业务任务、评价任务、业务操作、输入模态和时间。表中没有 Prompt/回答/论文/知识正文列。

### 设计目标

记录从原子调用创建到最终完成的可审计事实，使排队、执行、重试、失败、用量和成本能够关联且不互相覆盖。

### 保留的复杂版本设计边界

- 一个逻辑 AI 调用可以包含多次供应商尝试。
- 每次尝试独立记录实际账号引用、端点、模型、状态、用量和成本。
- AI 网关不保存论文、评审结果或完整业务对话作为业务事实。

### 后续复杂版本待逐项确认

- 原子任务、逻辑调用、供应商尝试和业务任务之间的标识关系。
- 调用与尝试的状态集合、转换条件、终态和结果未知状态。
- 创建记录、入队、领取、外部调用和完成记录的持久化顺序。
- 重试、账号切换、取消、截止时间和服务崩溃时的状态变化。
- 原始供应商响应、错误详情和统一结果保存到什么粒度。
- 乐观锁、唯一约束、并发更新和卡死状态修复方式。
- 数据保留期限、归档、删除和统计数据之间的关系。

### 与主流程的关系

调用记录贯穿原子任务、调度和供应商尝试全过程，并为价格计量、追踪、统计和故障恢复提供事实基础。
