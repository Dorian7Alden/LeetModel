# 业务调用上下文

> 实施状态：S2 业务来源、输入模态、消费者迁移与存储已落地；MQ6 已将同一调用上下文延伸到消息链路的 trace 传播。

## 目标

同一次 AI 调用必须同时回答两个互不替代的问题：输入需要什么模型能力，以及调用来自哪个业务操作。模型路由只读取 `modality`，审计、调度和统计读取 `featureCode`、`operationCode` 及后续 `AiCallContext`。网关不根据业务来源猜测输入模态，也不解释业务 ID 对应的实体。

## 正交字段

| 字段 | 含义 | 所有者 | 是否参与模型路由 |
|------|------|--------|------------------|
| `modality` | 本次输入所需能力：`TEXT`、`MULTIMODAL`，后续 Embedding 使用独立接口 | 发起调用的业务工作流 | 是 |
| `featureCode` | 稳定的业务能力域 | 业务服务 | 否 |
| `operationCode` | 能力域内的具体原子操作 | 业务服务 | 否 |

字段使用大写 ASCII 枚举式编码，已发布值不改变语义。展示名称由管理端映射，不能把中文名称写入调用事实。

## 首批编码

| 调用来源 | featureCode | operationCode | modality |
|----------|-------------|---------------|----------|
| AI 客服回复 | `AI_ASSISTANT` | `CHAT_REPLY` | `TEXT` |
| 正式论文评审 | `PAPER_REVIEW` | `FORMAL_REVIEW` | `MULTIMODAL` |
| 评价实验中的隔离评审 | `PAPER_REVIEW` | `EXPERIMENT_REVIEW` | `MULTIMODAL` |
| 论文改进建议 | `PAPER_SUGGESTION` | `GENERATE_SUGGESTION` | `TEXT` |
| RAG 文档索引 | `RAG` | `INDEX_DOCUMENTS` | Embedding 接口，不走 Chat 路由 |
| RAG 查询向量化 | `RAG` | `RETRIEVE_CONTEXT` | Embedding 接口，不走 Chat 路由 |

正式评审和实验评审可以复用同一工作流实现，但调用入口必须显式传入不同 `operationCode`。是否属于评价实验不能从 Prompt、模型名或 `workflowVersion` 反推。

## 兼容迁移

旧 `AiScene.GENERAL_TEXT` 映射为 `modality=TEXT`，`AiScene.MULTIMODAL` 映射为 `modality=MULTIMODAL`。该映射只保证迁移期间旧请求仍能选择模型，不生成虚假的业务来源：旧请求缺少上下文时以明确的 `LEGACY/LEGACY_CHAT` 记录，不能归入客服或评审统计。

S2-03 完成全部现有生产消费者迁移后，新 Java 调用必须显式提供 `modality` 和 `AiCallContext`。旧 JSON 字段 `scene` 在一个兼容窗口内只读接受，并在日志中以低基数告警计数；不允许新代码继续构造只有 `scene` 的请求。移除兼容字段属于后续 API 破坏性版本变更，不在 S2 范围内。

## AiCallContext 契约

| 字段 | 必填 | 最大长度/格式 | 边界 |
|------|------|---------------|------|
| `callerService` | 是 | 64 | Spring 服务名，不接受用户显示名 |
| `featureCode`、`operationCode` | 是 | 受控枚举且组合必须匹配 | 业务来源，不参与模型选择 |
| `businessTaskId` | 否 | 128 | 调用方业务任务的不透明引用 |
| `workflowVersion` | 否 | 64 | 业务服务拥有的不可变工作流版本 |
| `promptVersion` | 否 | 100 | 业务服务拥有的不可变 Prompt 版本 |
| `modelExecutionConfigVersion` | 否 | 100 | AI 网关拥有的不可变模型执行配置版本 |
| `evaluationTaskId` | 否 | 128 | 评价任务的不透明引用；非评价调用为空 |
| `priority` | 是 | `P0` 至 `P4` | 调用方声明值；网关必须按来源重新校验，不能任意提权 |
| `idempotencyKey` | 是 | 128 | 单次业务意图的稳定键；不等于允许自动重放上游请求 |
| `deadline` | 是 | 未来 UTC Instant | 最晚允许开始/等待到的时间，不延长调用方超时 |

上下文禁止包含用户名、手机号、对话正文、Prompt 正文、论文内容、知识片段、文件路径、Token 或密钥。日志只输出受控编码和不透明 ID；网关不连接业务数据库解释这些 ID。版本字段确实不适用时为空，不能用模型名或 `/v1` 填充。

## 查询边界

- 路由配置按 `modality` 查询，不能按 `featureCode` 复制一组模型配置。
- 调用明细可分别按 `featureCode`、`operationCode`、`modality` 查询。
- 聚合至少支持业务来源与输入模态两个独立维度；二者组合统计只作为交叉分析。
- 不从消息正文、文件内容或 Prompt 推断来源，避免敏感数据解析和不可复算分类。

## 非目标

- 本文不定义优先级数值、排队策略或业务任务 ID 格式；它们由 S2-02 和 S5 负责。
- 本文不把 RAG 检索结果、论文、对话正文写入调用上下文。
- 本文不使用 new-api 渠道、供应商或模型名表示业务来源。

## 面试说明

这里采用正交维度而不是单一 `scene` 枚举：单一枚举会形成“客服文本、建议文本、正式多模态、实验多模态”等组合爆炸，也会让路由配置与统计口径耦合。拆分后新增业务来源通常不需要修改模型能力枚举，新增输入能力也不需要重命名历史统计维度。
