## 限流与容量治理

> 设计状态：D-02 已重划。当前代码没有单实例并发保护。供应商渠道的并发、RPM、TPM、额度、动态收缩和恢复归 new-api；LeetModel 仅负责不同业务优先级之间的调度、队列、deadline、背压和整体派发速率，具体方案由 S5 设计实现。

### 0-1 当前取舍

- LeetModel 为客服、正式评审、管理员单测、批量评价和 RAG 索引建立受控业务调度。
- 队列满、deadline 到期或调用方取消时返回明确错误，不无限等待。
- new-api 返回最终限流时记录并降低 LeetModel 派发速度，但不复制渠道容量模型。
- Chat 与 Embedding 是否共享容量由 S5 按真实基线决定。

### 设计目标

在不复制 new-api 渠道治理的前提下，控制 LeetModel 各业务来源的公平性和总派发压力，避免后台实验阻塞实时业务。

### 被 new-api 取代的边界

- 供应商账号并发、RPM、TPM 和配额由 new-api 解释。
- 渠道响应头、容量探测、收缩和恢复由 new-api 管理。
- LeetModel 不保存供应商账号级计数或健康状态。
- 当前不使用成本预算和余额作为调用准入上限。

### 待逐项确认

- 并发、RPM、输入 TPM、输出 TPM、流式连接和模型独立限额的表达方式。
- 单实例与多实例部署下的共享计数和原子准入算法。
- 请求前 Token 估算、容量预占、调用后实际用量修正和失败释放规则。
- 多个限制维度同时存在时的检查顺序和等待时间计算。
- 供应商响应头、限流错误和本地统计如何共同调整可用容量。
- 动态收缩、探测恢复、缓慢放量和人工调整的状态转换。
- 限流器或共享存储不可用时的安全降级边界。

### 与主流程的关系

资源池选出候选通道后，容量治理负责执行最终准入。未获得容量的任务继续等待或延迟重试，不得跨模型执行。
