## 测试与验收

> 设计状态：Chat、Embedding、调用计量与单实例持久化调度已经落地。多账号资源池、流式、多实例全局许可和自动供应商治理仍不在当前实现范围。

### 设计目标

验证 AI 网关不仅能够调用供应商，还能在并发、限流、超时、重试、计量和故障恢复场景下保持已确认的职责边界。

### 已确认边界

- 适配器单元测试只能证明协议转换，不能代替真实供应商和完整调度链路验收。
- 固定模型、同模型账号切换、失败尝试计费和未知结果必须能够被验证。
- 自动化测试与真实冒烟承担不同证据职责；阶段完成必须同时满足任务卡约定的契约、状态与真实链路证据。

### 本地真实冒烟环境

- 真实冒烟由 `ai-gateway-service` 的运行环境提供 Relay Token；项目不约定其本地存储和加载方式。
- 不得将 Token 内容写入仓库文件、配置、日志、测试夹具或提交记录；输出必须脱敏且不能包含 Prompt、回答、知识片段或论文内容。
- 2026-08-28 已核验 DeepSeek、Kimi 相关 Chat 模型和 `qwen3.7-text-embedding` 可用。模型目录属于运行时事实，每次冒烟前仍需通过 `/v1/models` 与最小请求重新确认。
- 真实测试先使用合成文本、合成图片和受控知识内容；论文评审数据必须遵循仓库 `data/README.md` 的对应关系与限制。

### 待逐项确认

- 公共契约、模型能力、协议适配和错误映射的契约测试。
- 原子任务、状态机、幂等、取消、重试和崩溃恢复测试。
- 单实例与多实例下的并发、RPM、TPM 和公平调度测试。
- 供应商限流、鉴权失败、超时、部分输出和未知结果故障注入。
- 静态价格、实际用量、接口金额、汇率和完整性状态计算样例。
- 流式、多模态、密钥脱敏、URL 安全和权限边界测试。
- 真实供应商小流量验证、测试账号隔离和费用风险控制。
- 设计完成后开发阶段的验收环境、观测证据和完成定义。

### 与主流程的关系

测试矩阵应覆盖 README 宏观流程中的每个阶段及阶段之间的交接，尤其覆盖异常分支和恢复路径。
