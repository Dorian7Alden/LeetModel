## 配置与密钥

> 设计状态：0-1 仅使用静态配置和环境变量。供应商、单账号、官方端点、模型能力与价格随应用配置发布，API Key 通过环境变量注入。数据库配置管理、Nacos 动态刷新、在线发布和密钥轮换暂缓。

### 设计目标

明确数据库、Nacos、运行环境和专用密钥服务各自保存什么，以及配置怎样安全发布并形成可追溯快照。

### 保留的复杂版本设计边界

- 数据库保存可审计的供应商、模型、能力、静态价格和路由类业务配置。
- Nacos 可以发布可动态刷新的运行快照和密钥引用，不作为历史事实源。
- 真实 API Key 不进入数据库、Nacos 明文、代码仓库和日志。
- 配置变化只影响后续新任务，历史调用保留执行时快照。

### 待逐项确认

- 各类配置的唯一真实来源、加载优先级和启动校验。
- 配置草稿、校验、发布、启用、停用、回滚和审计流程。
- 多项关联配置如何原子发布，避免模型、价格和账号快照不一致。
- API Key 新增、引用、轮换、失效、连接测试和权限控制。
- 密钥服务不可用、配置刷新失败和旧快照继续使用的边界。
- 配置版本、发布时间、操作人和历史快照的保存方式。
- 开发、测试和生产环境的配置隔离规则。

### 与主流程的关系

配置与密钥为模型目录、资源池、供应商适配和计量提供运行输入，但不应在单次调用中读取互相不一致的配置版本。
