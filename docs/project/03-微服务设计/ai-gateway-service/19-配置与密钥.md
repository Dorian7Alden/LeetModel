## 配置与密钥

> 设计状态：D-02 已重划。LeetModel 静态配置只保存 new-api Base URL、Relay Token 引用、超时、逻辑模型、能力档案和 new-api 模型名绑定。供应商渠道、账号、端点、API Key、渠道价格和密钥轮换归 new-api。

### 设计目标

明确 LeetModel 逻辑绑定和 Relay Token 的安全边界，并避免复制 new-api 的渠道配置与密钥管理。

### 保留的复杂版本设计边界

- 数据库保存可审计的供应商、模型、能力、静态价格和路由类业务配置。
- Nacos 可以发布可动态刷新的运行快照和密钥引用，不作为历史事实源。
- 真实 API Key 不进入数据库、Nacos 明文、代码仓库和日志。
- 配置变化只影响后续新任务，历史调用保留执行时快照。

### 待逐项确认

- 各类配置的唯一真实来源、加载优先级和启动校验。
- 配置草稿、校验、发布、启用、停用、回滚和审计流程。
- 多项关联配置如何原子发布，避免模型、价格和账号快照不一致。
- API Key 新增、引用、轮换、失效、连接测试和权限控制。
- 密钥服务不可用、配置刷新失败和旧快照继续使用的边界。
- 配置版本、发布时间、操作人和历史快照的保存方式。
- 开发、测试和生产环境的配置隔离规则。

### 与主流程的关系

LeetModel 配置为逻辑模型绑定、new-api 适配和业务计量提供运行输入；new-api 渠道配置与密钥不进入 LeetModel 配置源。
