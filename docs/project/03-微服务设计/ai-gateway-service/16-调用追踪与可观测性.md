## 调用追踪与可观测性

> 实施状态：业务调用上下文、计量事实、任务只读状态、AI 专项 Micrometer 指标、中央结构化日志、同步 Agent Trace 和有界 AI provider/recovery attempt Trace 已落地；`traceId` 已持久化到调度任务和调用事实并支持管理端关联查询。Prometheus 已抓取指标，Grafana 已预置 AI 资源与稳定性看板，P0 等待、队列容量、UNKNOWN 与过期租约告警已进入主动告警闭环。

### 设计目标

让一次业务任务、工作流步骤、原子调用和供应商尝试能够被追踪，并使用稳定指标观察容量、性能、成本和错误趋势。

### 已确认边界

- 明细记录用于按调用标识追查，实时指标只使用低基数标签。
- 用户标识、调用标识和原始错误不能直接作为监控指标标签。
- Prompt、PDF、密钥和完整模型输出不得写入普通指标和非受控日志。

### 实时指标契约

| 指标 | 维度与语义 |
|------|------------|
| `leetmodel.ai.queue.tasks` | 固定 `P0-P4` 与 `QUEUED/LEASED/RUNNING` 在途量 |
| `leetmodel.ai.queue.oldest.seconds` | 各固定优先级最老排队时间 |
| `leetmodel.ai.queue.expired.leases` | 已过期但尚未恢复的 AI 租约 |
| `leetmodel.ai.admission` / `dispatch` / `recovery` | 准入、条件领取、执行器拒绝、安全重排与结果不确定分类 |
| `leetmodel.ai.queue.duration` / `execution.duration` / `end_to_end.duration` | 按调用类型、优先级和结果聚合的直方图耗时 |
| `leetmodel.ai.tokens` | `input/output/reasoning/cache_hit/cache_creation/cache_miss` Token 总量 |
| `leetmodel.ai.cost` | 按调用类型、货币与固定费用来源聚合的费用分布 |
| `leetmodel.ai.usage.completeness` / `cost.completeness` | `complete/partial/unknown` 计量完整性 |
| `leetmodel.ai.cost.enrichment` | 异步价格快照补录的 `completed/retry/final_unknown` |
| `leetmodel.ai.results.unknown` | 已持久化 `AI_UPSTREAM_RESULT_UNKNOWN` 任务存量 |

调用事实首次写入时记录调用、分段耗时、Token 与当时可用的费用。费用来源仍为 `UNKNOWN` 时，由价格快照补录成功后单独累计最终费用，避免重复累计调用与 Token。调度 attempt 已进入 `DISPATCHING/ACKNOWLEDGED` 后租约过期，只能进入 `AI_UPSTREAM_RESULT_UNKNOWN`，不得自动重发。

实时标签只允许固定优先级、调用类型、状态、结果、完整性、Token 类型、ISO 货币和固定费用来源。供应商、模型、调用方、原始错误以及 `taskId/aiCallId/traceId/operationId` 不进入实时标签；这些明细继续由数据库事实与后续 Trace/日志按标识查询。

### Provider attempt Trace 契约

队列准入和等待只持久化事实、更新指标，不保持 Trace。任务条件领取成功后，调度器把 `traceId + taskId + attemptNo + aiCallId` 恢复到结构化日志上下文，并打开独立的 `AI/ProviderAttempt`。Span 覆盖 attempt 准备、真实 Chat/Embedding 上游执行、确认与 fencing 持久化，然后始终关闭。后续租约接管使用递增 attempt 和新 Trace。

Span 只暴露固定 `attempt.kind`、`ai.call_type`、`ai.priority`、`outcome` 和 `error.kind`。确定失败使用 `execution_failure` 或 `rate_limited` 等有界分类；上游确认后持久化失败，或恢复过期 `DISPATCHING/ACKNOWLEDGED` 租约时，使用 `upstream_result_unknown/result_unknown`。两条路径都不把模型输入输出、请求 Payload、Provider 响应标识、原始异常、taskId 或 aiCallId 写为 tag。Span 内生成的调用事实仍在数据库和结构化日志保存关联标识。

### 主动告警

P0 最老等待在 8 秒进入 warning、达到 10 秒最大排队时间进入 critical；P1-P4 在各自 60 秒、30 秒、5 分钟、10 分钟 deadline 的 80% 进入 warning。总在途任务达到容量 500 的 80% 时预警，已持久化 `AI_UPSTREAM_RESULT_UNKNOWN` 立即 critical；AI 或领域过期租约持续不收敛会升级。处置与恢复规则见 [AI 队列与未知结果 Runbook](../../../runbooks/observability/ai-queue-and-unknown.md)，UNKNOWN 始终先只读对账，禁止自动重排。
