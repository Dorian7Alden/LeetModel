## 多模态输入

> 设计状态：0-1 仅保留文本和当前 AI 评审需要的图片输入。PDF 解析、页面转换和顺序由 `ai-review-service` 负责；音频、视频、完整 PDF 和通用文件输入暂缓，原有问题继续保留。

### 设计目标

定义文本、图像、PDF 和后续文件类型如何通过统一契约进入网关，完成能力校验并转换为供应商支持的协议格式。

### 已确认边界

- 模型能力使用可组合能力项表达，不把模型强制划分为互斥类型。
- 输入模态不受支持时应在调用前失败，不自动删除图片或改写业务输入。
- 上下文 Token 限制与文件数量、格式和体积限制分别校验。

### 待逐项确认

- 图片、PDF 和文件使用对象存储引用、受控 URL 还是请求内数据传递。
- 文件读取由业务服务还是网关负责，以及临时访问权限如何授予。
- 媒体类型、单项大小、总大小、数量和有效期限制。
- URL 获取的协议白名单、地址校验、重定向和 SSRF 防护。
- PDF 原文件、解析文本和页面图片分别属于哪个服务的处理职责。
- 供应商文件上传、文件 ID 复用和过期清理的适配方式。
- 多模态用量、失败记录和敏感内容日志边界。

### 与主流程的关系

多模态规则参与统一契约和模型能力校验，校验通过后的内容由供应商协议适配器转换并发送。
