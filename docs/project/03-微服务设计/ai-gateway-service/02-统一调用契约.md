## 统一调用契约

> 实现状态：同步 Chat 主链与供应商无关工具调用扩展已实现。工具扩展当前只在 new-api 的 OpenAI Completions 协议启用；异步任务控制、取消和流式事件字段继续暂缓。

### 设计目标

定义 AI 业务服务通过 `common-ai` 调用 AI 网关时使用的供应商无关契约，使业务语义、模型执行要求、任务控制信息和调用结果能够被稳定传递。

### 已确认边界

- `common-ai` 只维护公共调用契约和客户端能力，不负责供应商选择、限流和计量。
- 业务服务负责构建 Prompt 和业务上下文，并在任务开始前锁定精确模型与参数。
- AI 网关返回统一结果和统一错误，不向业务服务暴露 API Key。
- 工具定义和调用结构属于公共 AI 契约，业务工具的注册、参数校验、权限和执行属于调用方业务服务。

### 工具调用扩展

工具扩展由 [common-ai 工具调用契约](../common/common-ai/工具调用契约.md) 维护唯一字段定义。AI 网关只承担以下职责：

- 请求包含工具定义时，校验模型能力目录和不可变模型执行配置都允许工具调用。
- 将统一工具定义和工具选择映射到 new-api 的 OpenAI 兼容字段。
- 解析供应商返回的 `tool_calls`，保留调用标识、名称和原始参数 JSON。
- 接受业务服务回传的 `TOOL` 消息，并保持调用标识关联。
- 对工具规划调用和最终回答调用分别生成 AI `callId`、Token、费用和状态记录。

AI 网关不得执行工具、修复业务参数、查询题目服务，也不得在调用审计中保存完整工具参数和结果正文。供应商返回的工具名是否合法由 ai-assistant-service 等业务服务判断。

### 待逐项确认

- 请求标识、业务任务标识、工作流步骤标识、场景和追踪信息。
- 模型执行配置快照的引用方式、完整性校验和版本兼容。
- 幂等键、优先级、截止时间、取消标识和调用模式。
- 文本、多模态、结构化输出和供应商受控扩展的契约边界。
- 同步、异步和流式响应的统一表达。
- 错误码、结果未知、用量完整性和成本完整性的返回结构。
- 契约演进、向后兼容、字段废弃和请求大小限制。

### 与主流程的关系

该契约是 README 宏观流程中的统一 AI 调用入口。契约校验通过后，调用才进入模型绑定、原子任务和资源调度阶段。
