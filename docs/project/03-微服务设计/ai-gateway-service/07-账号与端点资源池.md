## 账号与端点资源池

> 设计状态：暂缓。0-1 首版每个供应商只使用一个账号、一个 API Key 和一个官方端点，不建设资源池或自动切换账号。本文完整保留；单账号容量成为真实瓶颈后，再恢复设计。

### 设计目标

定义供应商账号、API Key 引用、接入端点和精确模型之间的关系，并在不改变模型的前提下选择实际执行通道。

### 已确认边界

- 供应商、账号、API Key、接入端点和模型是不同层次的对象。
- 网关只能在能够执行同一精确模型的账号和端点之间切换。
- API Key 最好由本项目独占；无法独占时，本地容量可能受到外部项目消耗影响。

### 待逐项确认

- 账号、密钥引用、端点和模型可用关系的数据结构。
- 一个账号包含多个密钥或多个端点时的配额归属判断。
- 同模型候选通道的硬性过滤条件和选择顺序。
- 权重、在途请求、历史成功率和延迟是否参与通道选择。
- 账号启用、停用、隔离、恢复和人工强制下线的状态。
- 供应商条款不允许多账号聚合时的配置限制。
- 所有同模型通道不可用时进入等待、延迟重试或失败的条件。

### 与主流程的关系

调度器决定某个原子任务可以执行后，资源池为其选择同模型的具体账号和端点，再进入限流、健康和稳定性治理。
