## 熔断与健康评估

> 设计状态：渠道健康设计已由 new-api 取代。供应商账号、端点、渠道探测、熔断和半开恢复归 new-api；LeetModel 只检查 new-api 可达性、Relay Token 可用性和模型绑定有效性，并根据最终错误执行整体派发背压。

### 设计目标

识别 LeetModel 到 new-api 的依赖状态，避免把 new-api 不可达或绑定错误误报为业务失败。渠道级异常与恢复由 new-api 解释。

### 已确认边界

- 配置启用、主动探测、真实流量、供应商限流和熔断状态不能合并成一个简单健康标记。
- 单个渠道的隔离和同模型渠道切换由 new-api 执行，LeetModel 不感知账号。
- 健康治理不能触发跨模型自动降级。

### 待逐项确认

- 健康评估对象、状态集合和各状态的事实来源。
- 主动探测接口、探测频率、探测成本和不支持探测的供应商处理。
- 真实调用成功率、错误类型、延迟和样本窗口的计算方式。
- 熔断开启、半开探测、关闭和人工隔离的转换条件。
- 鉴权失败、额度问题、限流、服务故障和内容拒绝是否影响健康。
- new-api 可达性、Relay Token 和逻辑模型绑定的状态来源与检查频率。
- 健康数据持久化、实时指标和管理端展示边界。

### 与主流程的关系

健康评估参与同模型候选通道过滤和稳定性保护。通过限流与健康检查的请求才会进入供应商协议适配器。
