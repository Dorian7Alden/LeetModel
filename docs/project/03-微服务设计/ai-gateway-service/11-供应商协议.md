## 供应商协议

> 设计状态：D-02 已重划。目标实现只适配 new-api 暴露的 OpenAI 兼容 Chat、Responses 和 Embedding 接口。供应商鉴权、协议转换和品牌差异归 new-api。当前多供应商适配器是迁移前代码，将由 S1 收口。

### 通用供应商结构

以下通用供应商结构已转交 new-api 管理，LeetModel 不建立对应配置表单或数据表。

| 属性 | 语义 |
|------|------|
| Provider ID | 小写字母开头的不可变唯一标识，用于请求、路由和派生凭据名 |
| 显示名称 | 面向管理者展示的名称，可修改，不参与业务关联 |
| API 地址 | 供应商或兼容网关的服务根地址，不包含具体调用路径 |
| API 协议 | 选择请求、鉴权、响应和用量解析规则 |
| 密钥引用 | 指向运行环境或密钥服务，不保存和回显明文密钥 |
| 模型目录 | 供应商可调用模型、能力档案和限制；支持从官方目录同步和手工添加模型 ID |

Provider ID 与模型 ID 分开管理。模型目录接口没有返回任何模型时，仍允许维护者手工添加供应商文档确认可用的模型 ID。

每个目录模型至少维护模型 ID、显示名称、启用状态、支持协议、输入模态、输出模态、JSON 输出、思考模式、工具调用、上下文长度和最大输出。图像数量、单图大小、总体积、支持格式等限制放入模型能力档案。官方模型列表通常只能证明“模型存在”，不能自动证明多模态等能力；无法从接口可靠获取的字段必须由维护者依据官方文档确认。

### 支持的协议

| 协议标识 | 调用端点 | 典型请求结构 | 鉴权默认值 |
|----------|----------|--------------|------------|
| `openai-completions` | `/chat/completions` | `messages` 与 `text`、`image_url` 内容块 | `Authorization: Bearer` |
| `openai-responses` | `/responses` | `input` 与 `input_text`、`input_image` 内容块 | `Authorization: Bearer` |
| `anthropic-messages` | `/messages` | `messages` 与 `text`、`image` source 内容块 | `x-api-key` 和 `anthropic-version` |

三种协议是传输协议，不等同于供应商品牌。一个第三方兼容网关可以使用 `openai-completions` 或 `openai-responses`；同一供应商存在多个协议端点时，应建立不同接入端点，不能在单次调用中猜测协议。

协议抽象不等于供应商接入范围。当前只接入国内大模型供应商的官方服务，不因为已经支持某种请求协议就接入对应的国外供应商或非官方中转站。供应商地域范围见 [03-供应商与模型.md](03-供应商与模型.md)。

协议支持也不等同于模型能力。使用同一协议的两个模型可能分别只支持文本和支持图像；路由必须先检查端点协议能表达请求，再检查目标模型的能力和限制，二者任一不满足都不得调用。

协议适配器分别负责请求内容块映射、鉴权头、端点路径、结构化输出参数、停止原因、错误和用量解析。供应商适配器只补充模型限制和确有必要的兼容差异。业务服务和评审版本不得直接判断协议。

当前代码已经实现三种协议的非流式调用：模型能力档案锁定本次协议，统一请求随后映射到对应端点和内容块，供应商响应再收敛为 `AiChatResponse` 与 `AiUsage`。协议契约测试覆盖文本、Base64 图像、JSON 结构化输出、鉴权头、停止原因、缓存和思考用量；这代表网关传输层可用，不代表任意供应商账号或任意模型天然支持全部模态与参数。

### 当前 V1 选择

DeepSeek V1 端点使用 `openai-completions`，模型为 `deepseek-v4-flash-vision-exp`。论文页图像按顺序映射为 `image_url` 内容块。`openai-responses` 和 `anthropic-messages` 纳入供应商维护的固定协议集合，但不能因为它们支持文件输入就改变 `BASIC_REVIEW_V1` 已锁定的输入流程。

### 校验规则

- Provider ID 必须满足 `^[a-z][a-z0-9-]{1,63}$`，创建后不可修改。
- API 地址必须是 HTTPS；仅本地开发环境允许显式配置 HTTP。
- 协议必须从三种固定标识中选择，不接受任意字符串拼接端点。
- 保存或测试连接时不返回明文密钥；编辑时空密钥表示沿用现有密钥引用。
- 获取模型目录失败不自动禁用现有模型；应返回可理解错误并保留手工配置能力。
- 模型不能仅凭协议名称推断多模态能力；输入模态和限制必须存在明确能力档案。
- 上下文 Token、最大输出 Token、文件类型、图片数量、单项大小、模态总体积和最终 HTTP 请求体分别配置、分别报错。
- 调用前使用可确定的信息进行保守预算；图像 Token 等供应商专属计量无法精确预估时，供应商返回的上下文超限必须映射为统一上下文错误。
- 每个模型调用锁定供应商、端点、协议和模型快照，配置变化只影响后续调用。
