## 安全与数据保护

> 设计状态：0-1 保留必要安全边界。首版重点保护 API Key、限制内部调用、避免日志保存 Prompt 和完整模型输出，并限制国内供应商出站端点；复杂审计和合规治理继续保留但不一次完成。

### 设计目标

保护 API Key、业务输入、模型输出和调用元数据，限制只有受信任服务能够发起调用或读取治理信息。

### 已确认边界

- 业务服务不能直接获得供应商 API Key。
- AI 网关不保存论文、评审结果和完整业务对话作为业务事实。
- 普通日志、指标和管理接口不能泄漏密钥或未经控制的业务内容。
- 服务器部署在国内，当前只接入国内供应商的官方服务，不设计国外供应商网络代理。

### 待逐项确认

- 业务调用接口和管理接口的内部身份认证与权限模型。
- Prompt、模型输出、推理内容和供应商原始响应的最小保存范围。
- 敏感字段识别、日志脱敏、加密存储、访问审计和保留期限。
- 国内供应商外部端点白名单、TLS 校验和出站网络限制。
- 多模态 URL、文件下载、重定向和 SSRF 防护。
- 供应商数据保留条款、地域要求和业务内容发送前的合规检查。
- 密钥泄漏、异常调用和高风险配置变更后的处置流程。

### 与主流程的关系

安全校验从统一调用入口开始，并贯穿配置加载、文件获取、供应商请求、调用记录、日志和管理查询。
