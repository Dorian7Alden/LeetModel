## 流式调用

> 实施状态：AI 客服所需的 OpenAI Completions 文本流与工具调用聚合已落地；取消传播、慢消费者背压、多实例流式容量治理和其他供应商协议仍暂缓。

### 设计目标

定义业务服务、AI 网关和外部供应商之间的流式传输、连接控制、取消传播和最终计量方式。

### 已确认边界

- 流式内容已经对业务可见后，不自动切换账号或重新调用供应商。
- 运行时用量以供应商最终计量帧为准，中间字符数不替代官方 Token。
- 没有最终计量帧时，用量和成本可以保持未知。

### 当前实现

- `common-ai` 提供 `AiClient.streamChat` 与 `AiChatStreamChunk`，业务服务可在最终聚合响应返回前收到文本增量。
- `ai-gateway-service` 的 `/internal/ai/chat/stream` 直接透传 new-api SSE 文本增量，结束时返回带统一 `callId` 的完整响应。
- OpenAI 兼容适配器按 `index` 聚合跨帧拆分的 `tool_calls` 标识、函数名和参数，供业务服务在流结束后继续受控工具循环。
- 每个供应商文本增量只向上游转发一次；完整响应只发送一个完成帧，不能把完整回答再次切片回放。
- 当前流式入口不进入同步持久化调度队列；仍执行模型能力校验并记录最终调用审计与供应商用量。

### 暂缓范围

- 首帧超时、帧间超时、总连接时长和调用截止时间。
- 客户端断开后的取消传播、供应商取消能力和继续计费风险。
- 背压、缓冲区、慢消费者和网关流式连接上限。
- OpenAI Completions 之外的供应商流式协议映射。
- 流式调用的任务状态、调用记录和结果保留方式。
- 网关重启或网络中断后无法恢复原连接时的最终状态。

### 与主流程的关系

流式调用使用相同的模型绑定、调度和资源准入流程，但在供应商适配、响应返回和计量完成阶段具有独立规则。
