## 用例分析过程

> 创建日期：2026-07-25
> 最后更新：2026-08-23

本文档记录当前需求下的用例识别与合并过程。用例只表达参与者的业务目标和系统触发的业务结果，不提前确定微服务、数据库或工作流实现。

---

### 参与者识别

| 需求来源 | 参与者 | 判定 |
|----------|----------|------|
| 账号、题库、队伍、提交、结果 | 普通用户 | 主要参与者 |
| 招募、职责分配、开始练习 | 队长 | 普通用户在特定队伍中的业务身份 |
| 后台管理 | 管理员 | 与普通用户平行的系统身份 |
| AI 客服与评审 | AI 系统 | 支持业务结果的次要参与者 |
| 充值 | 支付能力 | 为评审特权次数提供外部事实 |
| 练习截止 | 定时触发器 | 在到达截止时间时触发系统处理 |


### 候选能力

从需求中提取以下候选能力：

- 注册与登录
- 浏览、筛选与随机获取题目
- 在题目下创建队伍
- 发布招募与组建队伍
- 为成员分配职责
- 开始限时练习
- 多次提交论文版本
- 截止时结束练习并锁定最终版本
- 充值获得评审特权
- 消耗特权提前加入评审队列
- 执行版本化 AI 评审
- 查看提交、评审和练习结果
- 查看个人统计和题目排行
- 与 AI 客服对话
- 管理基础数据和系统运行数据


### 合并与保留

| 候选能力 | 结论 | 原因 |
|----------|------|------|
| 浏览列表、筛选、查看详情、随机题目 | 合并为浏览题库 | 共同服务于找到练习题目的目标 |
| 发布招募、管理成员、分配职责 | 合并为组建题目队伍 | 共同服务于达到可开始练习的队伍条件 |
| 创建队伍 | 单独保留 | 创建时形成题目绑定和固定队长两项不可变业务事实 |
| 开始限时练习 | 单独保留 | 触发职责完整性校验和题目倒计时 |
| 结束限时练习 | 单独保留 | 关闭提交并锁定最终版本，可由时间事件触发 |
| 上传 PDF 与保留版本 | 合并为提交论文版本 | 上传是形成不可变提交版本的子步骤 |
| 充值与特权入账 | 合并为兑换评审特权 | 共同产生可消耗特权次数 |
| 消耗次数与提前排队 | 合并为提前加入评审队列 | 消耗特权是获得提前排队结果的必要条件 |
| 查看提交历史、评审状态和评审结果 | 合并为查看练习结果 | 三者是同一次练习的连续查询场景 |
| AI 评审 | 单独保留 | 它是系统核心能力，且会按完整工作流版本独立演进 |


### 排除的候选用例

| 候选 | 排除原因 |
|--------|----------|
| 报名赛事 | 平台只用于练习，不模拟真实参赛 |
| 浏览赛事专栏 | 赛事只是题目归属和题库分类 |
| 选择题目编程语言 | 编程语言属于队伍自由选择，不是题目属性 |
| 打卡 | 不符合数学建模低频练习的使用特征 |
| 发布讨论或笔记 | 系统不建设社区、讨论与笔记能力 |
| 请求 VIP 改进建议 | 当前付费权益已改为可消耗的评审特权次数 |


### 分析结论

用例模型从原来的独立组队与提交后立即评审，调整为题目绑定队伍、组建队伍、限时练习、多版本提交与版本化 AI 评审。最终用例清单以用例分析结论为准。
