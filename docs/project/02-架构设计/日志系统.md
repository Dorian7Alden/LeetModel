## 日志系统

> 设计状态：14 个 Java 服务已统一使用 `leetmodel.log.v1` JSON schema、stdout 与有界本地轮转，并完成集中脱敏、日志注入防护、字段限长、危险调用点门禁、重复故障限频，以及 SkyWalking 有界 Reporter、OAP LAL、BanyanDB 保留和中央查询。


### 目标与分类

日志系统负责解释技术执行，不担任业务主数据、领域历史或不可变操作审计。

| 日志类型 | 内容 | 主要用途 |
|----------|------|----------|
| Access | 路由模板、HTTP 方法、状态码、耗时、响应错误码 | 流量与失败入口排查 |
| Application | 关键状态转换、依赖调用、降级、重试、异常 | 技术根因定位 |
| Async task | Outbox/MQ/Inbox、任务领取、租约、heartbeat、attempt、fencing | 长耗时异步链路解释 |
| Security event | 登录失败、鉴权拒绝、非法 Token、输入校验攻击特征 | 安全监测；高风险事件同时生成操作审计 |
| Infrastructure | MySQL、Redis、RocketMQ、Nacos、MinIO、ES、OAP 自身日志 | 依赖和采集链路排查 |


### 统一结构

所有 Java 服务使用同一份可版本化 JSON 字段规范。稳定字段为：

| 字段组 | 字段 |
|--------|------|
| 时间与级别 | `schemaVersion`、`timestamp` UTC ISO-8601、`level`、`eventCode`、`message` |
| 资源 | `service`、`environment`、`serviceVersion`、`instance`、`logger`、`thread` |
| 调用关联 | `traceId`、`swTraceId`、`swSpanId`、`requestId`、`operationId` |
| HTTP | `httpMethod`、`routeTemplate`、`statusCode`、`durationMs`、`errorCode` |
| 业务关联 | `businessType`、`businessId`、`domainTaskId`、`attemptNo`、`eventId`、`aiCallId` |
| 异步阶段 | `messageTopic`、`consumerGroup`、`retryCount`、`suppressedCount`、`taskState`、`claimType`、`aiPriority`、`aiCallType`、`outcome` |
| 异常 | `exceptionType`、`failureCategory`、仅含代码位置的 `stackTrace` |

`eventCode` 是稳定机器可查字段，不使用 message 当聚合维度。当前关键编码包括 `HTTP_REQUEST_COMPLETED/FAILED`、`OUTBOX_PUBLISH_BLOCKED/RETRY`、`INBOX_MESSAGE_CONSUMED/DUPLICATE/FAILED`、`DOMAIN_TASK_CLAIMED/COMPLETED/FAILED` 和 `AI_CALL_COMPLETED/FAILED/RESULT_UNKNOWN`；尚未语义化的框架或旧应用日志使用固定 `UNCLASSIFIED`，不能把自由文本提升为编码。`routeTemplate` 记录 `/api/users/{id}`，Gateway 记录固定 `route:<routeId>`，未匹配请求记录 `UNMATCHED`，均不回退到带真实主键的 URL。`service`、`environment`、`serviceVersion` 和 `instance` 在进程启动时确定，不允许 MDC 或请求字段覆盖。

`LeetModelJsonLayout` 只读取固定字段白名单，忽略任意 MDC/SLF4J key-value；数值字段保持 JSON number。异常只输出类型和最多 64 个代码位置，不复制 `Throwable.message`。最终编码前，`LogSanitizer` 对 message、资源字段、关联标识和代码位置分别执行不可逆脱敏、控制字符清理和长度限制，因此业务调用方与框架日志共用同一条安全边界。


### 输出、采集与查询

```mermaid
flowchart LR
    APP["14 个服务 / Logback leetmodel.log.v1"] --> STDOUT["stdout + 本地可轮转兜底"]
    APP --> REPORTER["SkyWalking 兼容日志 Reporter"]
    REPORTER --> OAP["SkyWalking OAP Log Receiver"]
    OAP --> LAL["LAL 解析、字段校验、Trace 关联"]
    LAL --> STORE["独立遥测存储"]
    STORE --> UI["SkyWalking UI"]
    REPORTER -. "上报失败/丢弃指标" .-> PROM["Prometheus"]
```

首期复用 SkyWalking 的日志接收、LAL 和 Trace 关联，不同时引入 Loki/ELK 建第二套业务日志主存储。如果后续的全文检索、保留或多数据源需求超出 SkyWalking 边界，再以同一 JSON 契约接入专用日志平台。

日志上报必须异步且有界：OAP 不可用时不阻塞请求、MQ Consumer 或 AI Worker。本地 stdout 始终保留，开发脚本继续可将其重定向到文件。队列溢出时先丢弃 DEBUG/INFO 且递增 Prometheus 丢弃指标，不允许无界内存缓冲。

当前每个服务在 `application.yml` 显式导入 `leetmodel-logging.yml`，由公共 `leetmodel-logback-spring.xml` 同时写 stdout、`${LEETMODEL_LOG_DIR:-logs}/<service>.json.log` 和可选的 `SKYWALKING_REPORTER`。本地文件按日期与 100 MB 分片，默认保留 7 天且总量上限 1 GB；环境可缩小这些有界参数。Reporter 默认关闭；`start-mvp.sh` 在 Java Agent 开启时默认同时开启 Reporter，也允许分别用 `LEETMODEL_SKYWALKING_LOG_ENABLED` 覆盖。上报端点固定使用 OAP 原生 HTTP `/v3/logs`，不重复采集 stdout。

Reporter 在业务线程仅完成安全 JSON 编码和有界队列 `offer`，网络 I/O 由单个 daemon 线程批量执行。默认队列 2048、批量 64、刷新 500 ms、连接超时 500 ms、请求超时 1500 ms、最多 2 次尝试、重试退避 100 ms；配置非法时仅停用 Reporter，不阻止应用启动。队列满时 DEBUG/INFO 直接丢弃，WARN/ERROR 可淘汰一条低优先级记录；传输耗尽和关机未排空也明确计数。Reporter 第一次成功不算恢复，只有失败后的成功才递增恢复计数。

OAP 11.0.0 只为 `GENERAL` 层启用 `leetmodel` LAL，不加载会无条件落库的默认 GENERAL 规则。LAL 以 `abortOnFailure=true` 拒绝畸形 JSON，以 `dropper` 拒绝非 `leetmodel.log.v1` schema，并抽取 `service/instance`、事件码和关联标签。`swTraceId` 同时写入 SkyWalking 原生 `traceId` 字段以支持 Trace/日志跳转；业务 `traceId` 使用 `business_trace_id` 搜索标签，另有 `sw_trace_id/domain_task_id/ai_call_id`，四者都可由 GraphQL/UI 直接过滤。所有数字仍保留在 JSON content 中，不被字符串化。

BanyanDB 使用 `leetmodel-observability` 独立 namespace，Record/Metrics 首期保留 7 天。OAP 保留 stdout，并额外写 100 MB 分片、7 天的有界基础设施文件；只读 `ghcr.io/google/mtail:3.0.8` sidecar 将上游未原生暴露的 LAL `invalid_json/schema_or_policy/evaluation` 结果转换为低基数 Prometheus 计数，不保存第二份业务日志。


### 级别与事件规则

| 级别 | 使用条件 |
|------|----------|
| ERROR | 未知系统异常、数据一致性风险、无法自动恢复、AI UNKNOWN、审计可能丢失 |
| WARN | 已知降级、依赖短故障、有界重试、租约过期、鉴权/校验拒绝 |
| INFO | 服务启停、脱敏配置摘要、关键领域终态和人工恢复结果 |
| DEBUG | 本地开发与短时受控排障，生产默认关闭 |
| TRACE | 默认关闭，不对全服务开启 |

预期业务拒绝不打 ERROR 堆栈。同一任务的心跳成功不每次打 INFO；只在领取、丢失、过期、终态和超阈值时记录。重复依赖故障由 `FailureLogLimiter` 按代码内固定 key 聚合：首条立即输出，默认每分钟最多输出一次周期摘要，恢复时输出一次恢复事件；窗口内抑制量进入 `leetmodel.logging.suppressed{event_code}`，日志摘要使用 `suppressedCount`。key 只接受有界稳定编码，不能使用任务、请求或异常文本。


### AI 与异步链路必需日志

| 阶段 | 必需标识和状态 |
|------|------------------|
| 任务创建 | `traceId`、`domainTaskId`、工作流版本、排队结果 |
| Outbox Relay | `eventId`、事件类型、attempt、发布结果、耗时；无 Payload |
| Inbox Consumer | `eventId`、消费组、首次/重复、事务结果；不在消费线程写 AI 详细 |
| Worker 领取 | `domainTaskId`、`attemptNo`、`normal/takeover`；不记录租约 owner 或 fencing token |
| 依赖阶段 | PDF 版本、RAG/工作流/模型配置版本、状态、耗时；无内容 |
| AI 调用 | `aiCallId`、功能/操作编码、优先级、排队/执行/总耗时、结果类型 |
| 任务终态 | 终态、failure category、本次耗时、是否等待人工处置 |


### 脱敏与注入防护

以下内容不得记录：Authorization/Cookie/JWT/Session、密码与验证码、数据库/对象存储/模型渠道凭据、完整请求与响应体、论文与 PDF 解析正文、Prompt、AI 回答、RAG 知识片段、Embedding 向量、RocketMQ Payload、幂等键和完整第三方 URL 查询参数。

日志安全策略按以下类别执行：

| 类别 | 策略 |
|------|------|
| 密码、验证码、Authorization、Cookie、JWT、Session、数据库/对象存储/模型渠道凭据 | 仅保留字段名或认证方案，值不可逆替换为 `[REDACTED]` |
| HTTP/JDBC 第三方 URL | 保留 scheme、host 和 path；userinfo 与完整 query 不输出 |
| 请求/响应体、论文、Prompt、回答、RAG、Embedding、消息 Payload、上传令牌和对象路径 | 调用点拒绝进入日志；布局对带固定敏感字段名的误传再拒绝值 |
| 技术 message 与白名单结构字段 | 移除 CR/LF、ESC、NUL、Unicode 行分隔符等控制字符，再执行脱敏与限长 |
| 异常 | 只保留异常类和最多 64 个、单项最多 512 字符的代码位置，不保存异常 message |

message 最多 1024 字符，普通字段最多 256 字符，关联标识最多 128 字符；截断使用固定 `[TRUNCATED]` 后缀。脱敏不保留可逆秘密，也不自动对敏感正文生成哈希。确需证明内容一致性时，由领域在正文进入日志前计算经过设计确认的 SHA-256 事实。

`GlobalExceptionHandler` 对客户端继续返回既有稳定错误，运行日志仅保存事件码、错误码、异常类型和固定失败类别。Gateway、MinIO、上传分片、缓存、消息运维、领域 Worker 与 AI/new-api 调用点不再输出自由异常文本、对象路径、上传令牌、Prompt 或业务正文。源代码门禁会拒绝这些变量重新进入日志调用。


### 查询、保留与权限

- SkyWalking UI、OAP 查询端口不经公网 Gateway 暴露，只供内部运维角色访问。
- 运行日志、Trace 和审计使用分离的保留策略；日志与 Trace 保留期根据写入量和排障窗口配置，不因审计长期要求无限保留。
- 生产 SkyWalking 遥测存储与 LeetModel RAG Elasticsearch 隔离；本地开发如复用单机资源也必须用独立 namespace/数据目录且不对外推导生产容量。
- 日志导出、日志级别修改、保留策略修改和遥测管理权限变更进操作审计。


### 可观测性与验收

Prometheus 监测 `leetmodel_logging_reporter_events_total{outcome,cause}`、Reporter 队列深度/容量和连接状态、OAP `log_in_latency`、`leetmodel_oap_lal_events_total{outcome,cause}` 以及 BanyanDB 健康。应用指标只携带固定 `service/outcome/cause`，解析指标只携带固定结果和原因，不把四类关联 ID 变成 Prometheus label。关键 ERROR 不仅依赖日志文本告警；AI UNKNOWN、DLQ、审计归档缺口和数据一致性风险必须同时有结构化指标。

基础 JSON 与安全边界由 `scripts/verify-logging-contract.sh` 验证。中央链路由 `scripts/verify-skywalking-logging.sh` 静态校验有界参数、Compose、LAL、mtail 和 Prometheus 配置；`--runtime` 仅使用 18096 临时 knowledge-retrieval-service 与 18098 假 OAP，验证真实 OAP/BanyanDB/GraphQL、四类关联过滤、数字类型、非法输入拒绝及解析指标，并演练慢消费、队列溢出、断开和恢复。脚本退出时只停止自身临时进程。

完整验收覆盖：

1. 已完成：全部业务服务输出同 schema JSON，并保留可用的业务 `traceId` 与 SkyWalking MDC 字段。
2. 已完成：环境与 SQL 日志策略受静态门禁约束，默认不输出 DEBUG 和 SQL 参数。
3. 已完成：密码、Token、Prompt、论文、消息 Payload、第三方 URL、CR/LF 注入与长度上限具有集中负面测试和真实运行门禁；周期故障具有抑制计数、摘要和恢复语义。
4. 已完成：OAP 断开或变慢时业务主链继续，本地日志可读，上报队列有界，并产生失败、丢弃和恢复指标。
5. 待联合验收：租约接管、重复消费、AI UNKNOWN 和 DLQ 重放时日志不风暴，且能按业务 `traceId`、任务 attempt 和 `aiCallId` 还原过程。
