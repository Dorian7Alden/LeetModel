## REST API 版本化触发评估

### 结论

截至 2026-08-30，没有出现需要对外并行提供 REST `/v1`、`/v2` 的真实不兼容变更，S10-05 按完成标准保持未开始。当前不增加全局版本前缀、不复制 Controller 和 Gateway 路由，也不把 `workflowVersion` 当作 REST API 版本。

本结论只说明当前触发条件未成立，不表示项目永远不做 API 版本化。出现不能通过向后兼容字段演进解决的外部契约变更时，必须重新领取该条件任务并用当时的调用方证据设计迁移周期。


### 当前证据

| 检查面 | 当前事实 | 判断 |
|--------|----------|------|
| Gateway | 以 `/api/auth/**`、`/api/users/**`、`/api/assistant/**`、`/api/admin/**` 等稳定领域路径转发，没有全局 `/api/v1` 或 `/api/v2` 路由 | 无并行外部版本 |
| Controller | 对外 Controller 使用领域资源路径；当前改动只新增兼容字段和管理资源，没有替换既有字段语义 | 可继续兼容演进 |
| Feign | 内部契约以 `/internal/**` 管理；评审隔离实验保留一个局部 `/experiments/v2` 兼容入口，不是对外全局 REST 版本 | 不构成外部触发条件 |
| OpenAPI | `/v3/api-docs` 是 Springdoc 的 OpenAPI 3 规范端点，不是业务 API v3 | 不计入业务版本 |
| 前端 | 唯一请求客户端基址为 `/api`，当前生产页面没有版本前缀，真实构建与浏览器联调通过 | 没有待迁移的活跃调用 |

`LeetModel-frontend/src/views/admin/pages/LoginPage.vue` 中仍有一个硬编码 `/api/v1/auth/login` 的未路由旧组件；全仓库没有导入或路由引用，实际登录使用 `views/auth/LoginPage.vue` 和 `/api/auth/login`。它是非运行时残留，不证明系统存在 v1 外部契约，也不能据此启动全局版本化。

AI 工作流的 `ASSISTANT_NO_RAG_V1`、`ASSISTANT_RAG_V1`，Prompt、模型执行配置和 RAG 索引版本描述的是同一 REST 契约下的执行语义与可复现快照。它们必须继续通过请求或生产配置字段表达，不能搬到 URL `/v1`、`/v2`。


### 重新触发条件

只有同时满足以下条件才开始设计：

1. 已有外部调用方正在使用当前接口，并且计划变更请求、响应、状态码、鉴权或资源语义中的至少一项不兼容内容。
2. 无法通过新增可选字段、新增资源路径、服务端默认值或明确弃用字段实现向后兼容。
3. 能列出需要迁移的真实调用方、流量或发布版本，并能定义旧版退出的业务时点。

触发后才制定 Gateway 双路由、Controller 契约隔离、Feign 是否受影响、OpenAPI 分组、前端灰度迁移、弃用响应头、观测指标和下线周期。没有这些证据时预建空 `/v2` 只会增加永久维护面。
