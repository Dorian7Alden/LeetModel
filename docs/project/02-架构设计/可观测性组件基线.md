> 基线日期：2026-09-01。本文固化 OBS-01 的可执行结果；总体语义和后续边界仍以 [可观测性与系统保障](可观测性与系统保障.md) 为准。

## 开发环境部署

配置入口为 `LeetModel-backend/docker-compose.observability.yml`，与业务 Compose 分开。所有宿主机端口只绑定 `127.0.0.1`。

| 组件 | 本机端口 | 开发内存上限 | 持久化 / 限制 |
|------|----------|---------------|----------------|
| BanyanDB | 不暴露 | 1 GiB | 独立 stream、measure 命名卷 |
| OAP | `11800` gRPC、`12800` GraphQL/HTTP、`17128` Admin、`11234` Prometheus telemetry | 1400 MiB，JVM `512–1024 MiB` | 只写 BanyanDB；全部只绑定 loopback |
| OAP LAL 指标出口 | `13903` Prometheus（仅 host network loopback） | 64 MiB | 只读 OAP 7 天/100 MB 分片基础设施日志，不存业务日志副本 |
| Horizon UI | `18080` | 512 MiB | 独立 UI 数据卷 |
| Prometheus | `19090` | 512 MiB | 7 天或 1 GB，先到为准 |
| Alertmanager | `19093` | 256 MiB | 独立数据卷；生产规则默认进入本地空接收器，隔离演练才进入 loopback webhook |
| Grafana | `13000` | 512 MiB | 独立数据卷，预置 Prometheus 数据源和六类只读看板 |

本地上限合计约 4.2 GiB，仅用于开发冒烟，不是生产容量承诺。生产 OAP/BanyanDB 必须使用独立集群、卷、账号和容量基线，不得复用 RAG 的 Elasticsearch 实例、索引或凭据。

```bash
cd LeetModel-backend

# 启动固定版本的本地可观测栈
./scripts/start-observability.sh

# 下载/校验 Agent，激活 Gateway 4、WebFlux 6、MVC 6 和 RestTemplate 6 可选插件，校验 Toolkit activation
./scripts/prepare-skywalking-agent.sh

# 按需为 13 个业务服务附加 Agent；默认值 false 不改变旧启动语义
LEETMODEL_SKYWALKING_ENABLED=true ./scripts/start-mvp.sh

# 停止可观测容器，保留命名卷
docker compose -f docker-compose.observability.yml down
```

Horizon 不在仓库中提供默认用户或密码。需要登录时，在运行环境用 `HORIZON_AUTH_LOCAL_USERS` 注入用户和 Argon2 密码哈希。Grafana 本地基线只开放匿名 Viewer；生产必须关闭匿名访问并在反向代理层启用 TLS 和组织身份源。OAP、Prometheus、Grafana 和管理端点都不经公网 Gateway 暴露。

本地业务服务是宿主 JVM，Prometheus、Alertmanager 和 Grafana 使用 host network 直连，并分别显式监听 `127.0.0.1:19090`、`127.0.0.1:19093` 与 `127.0.0.1:13000`；不能删除 loopback 绑定。`start-observability.sh` 在 `.observability-runtime/management-token` 生成或复用 64 字符十六进制管理 Token，文件不进入 Git，并以宿主用户组只读方式提供给非 root Prometheus 进程。随后运行 `start-mvp.sh` 会自动读取同一文件并设置业务进程的 `MANAGEMENT_TOKEN`；显式环境变量仍可覆盖这一行为。

Prometheus 的 file-SD 固定列出 13 个服务，不通过 Gateway 抓取；基础设施目标包括 Prometheus 自身、OAP、OAP LAL 指标出口、Alertmanager 和 Grafana。Grafana provisioning 固定加载系统总览、MVP 主链、AI 资源与稳定性、异步任务、可靠消息和遥测管道六类看板；遥测管道看板同时显示 Reporter 结果/队列、OAP 接收延迟和 LAL 拒绝。Prometheus 加载 22 条版本化主动告警规则；Alertmanager 按 `alertname + service` 分组，critical 抑制同服务同告警的 warning。仓库默认把生产规则路由到本地空接收器，不保存 Pager/IM 凭据；仅带 `drill="true"` 的隔离演练告警进入 `127.0.0.1:19094` 临时 webhook，并发送恢复通知。所有规则链接 `docs/runbooks/observability/` 下的版本化 Runbook。


## Agent 兼容结论

| 能力 | 项目版本 | 官方声明 | 项目真实协议验收 | 结论 |
|------|-----------|----------|----------------------|------|
| Spring MVC | Spring Framework 6 / Boot 3.3 | MVC 6 插件支持 | `user-service` 产生 `GET:/internal/users/count` HTTP Trace | 支持 |
| JDBC | MySQL Connector/J 8 | MySQL 8 插件支持 | 真实请求产生 `mysql-connector-java` Span | 支持 |
| Gateway / WebFlux | Spring Cloud Gateway 4 / WebFlux 6 | Gateway 4 与 WebFlux 6 插件支持 | 一条请求产生 WebFlux Entry、Gateway Exit 并连接 team-service MVC | 支持完整同步 HTTP 边界 |
| OpenFeign | Spring Cloud OpenFeign 4.1.3 / Feign 13.3 | 列表仅覆盖 Spring Cloud Feign 1.x/2.x 和 Feign 9.x | 公共 Toolkit `Capability` 产生两个稳定契约名 Exit Span，SW8 与下游 MVC/JDBC 属于同一 Trace | 自动插件不兼容；项目增强支持 |
| RocketMQ | Spring 2.3.3 / Client 5.3.1 / Broker 5.5.0 | 列表覆盖 RocketMQ 3.x/4.x/5.x | 唯一消费组协议测试通过，生产端出现 `rocketMQ-producer` Exit；消费端 Entry 仍未观察到 | 生产端支持；消费端由 TRACE-02 自定义 attempt Span 补齐 |

Feign 兼容测试位于 `admin-service` 并只在 `RUN_OBSERVABILITY_COMPATIBILITY=true` 时执行。Agent 9.7.0 发布包的 Toolkit activation 与 `apm-toolkit-trace` 9.6.0 ABI 已真实兼容；9.7.0 Toolkit 的发布 POM 祖先不在 Maven Central，因此应用侧固定 9.6.0 no-op API，不启动线程、Reporter 或第二套 exporter。启动参数显式排除 `feign-default-http-9.x` 和 `feign-pathvar-9.x`，避免旧插件对 Feign 13 部分增强后重复建 Span。

RocketMQ 集成测试允许验收脚本提供唯一临时消费组，避免与正在运行的固定消费组竞争消息；退出时删除该临时组。消费端自动 Entry Span 不作支持承诺，后续必须在 Inbox、任务创建与 Worker attempt 的真实边界补充有界 Span，不得用一个跨分钟 Consumer Span 包住 AI 执行。


## 13 服务 Agent 运行契约

`start-mvp.sh` 的 Agent 开关对 13 个服务使用同一套参数。关闭时不解析 Agent、不改变原 Java 启动语义；开启时字段在进程启动前校验，不能来自 HTTP、消息或用户输入。

| 环境变量 | 默认值 | 语义 |
|----------|--------|------|
| `LEETMODEL_SKYWALKING_ENABLED` | `false` | 是否附加固定 Agent；关闭 Trace 应使用此开关 |
| `LEETMODEL_SKYWALKING_BACKEND` | `127.0.0.1:11800` | OAP gRPC 地址，不经 Gateway |
| `LEETMODEL_SKYWALKING_SAMPLE` | `100` | 每 3 秒最多采样数；正数限流，`0` 或负数关闭限流即全量采集 |
| `LEETMODEL_ENVIRONMENT` | `SPRING_PROFILES_ACTIVE`，再回退 `dev` | Agent namespace 与实例 `environment` 属性 |
| `SERVICE_VERSION` | `0.0.1-SNAPSHOT` | 实例 `serviceVersion` 属性和结构化日志版本 |
| `LEETMODEL_SERVICE_INSTANCE_PREFIX` | `local` | 与服务名组成最长 50 字符的稳定实例名 |

Agent service name 使用固定 `spring.application.name`，namespace 表达环境，instance 同时进入 Agent 与结构化日志。`instance_properties_json` 保存 `environment/serviceVersion/instance`，使 OAP 可筛选；这些值不作为业务指标维度。`business.trace_id` 由 Toolkit correlation context 和 Agent `auto_tag_keys` 写入 Trace，一处只写一次；`swTraceId/swSpanId` 从当前 Agent 上下文进入 JSON 日志。无 Agent、未采样或 Trace 值非法时桥接为 no-op，业务 `traceId` 仍生成和传播。


## 验收与故障语义

环境需要 Docker Compose、JDK 17、Maven 3.9+、`curl`、`jq`、`rg` 和 GNU `date`。验收脚本会启动一个临时 `user-service` 和 `gateway-service`，验证 HTTP/JDBC Trace、OAP 自监控指标、Prometheus 抓取、本地运行日志以及禁用依赖，退出时只停止临时 Java 进程。

```bash
cd LeetModel-backend
./scripts/verify-observability-baseline.sh

# 额外暂停并恢复 OAP，确认业务请求 fail-open
VERIFY_OAP_OUTAGE=true ./scripts/verify-observability-baseline.sh

# 只校验 Compose、目标、规则、路由、看板与管理边界
./scripts/verify-observability-stack.sh --static

# 启动一个 18094 临时 Gateway，验证受保护抓取、查询、看板与 Prometheus 中断恢复
./scripts/verify-observability-stack.sh

# 校验 22 条告警、注解、Runbook anchor、路由和分级组合
./scripts/verify-alerting-contract.sh

# 使用 19094 loopback webhook 验证触发、分组、抑制、静默和恢复通知
./scripts/drill-alerting.sh

# 校验日志 Reporter/OAP LAL；--runtime 额外演练慢、断开、溢出与恢复
./scripts/verify-skywalking-logging.sh --runtime

# 静态校验 13 服务、Toolkit、Feign 增强、插件与唯一 Trace 实现
./scripts/verify-skywalking-tracing.sh

# 使用 18081–18084 临时进程和唯一 MQ 消费组验证同步链、资源、双向检索与 RocketMQ 边界
./scripts/verify-skywalking-tracing.sh --runtime

# 在上述完整门禁末尾停止/恢复 OAP，确认 Agent 与 Reporter fail-open
VERIFY_OAP_OUTAGE=true ./scripts/verify-skywalking-tracing.sh --runtime
```

指标栈验收同时使用 `promtool`、`amtool`、Grafana API 和 Prometheus API，确认 13 个固定目标、五个基础设施目标、六个看板及其中的 PromQL。告警门禁还检查所有严重规则的影响、当前值、看板、调查入口、Runbook 与恢复条件，并通过隔离接收器验证 firing/resolved、分组、抑制和静默。脚本只停止自己启动的临时 JVM、假 OAP 或 webhook；Prometheus fail-open 演练只停止并恢复可观测 Compose 内的 Prometheus，不操作标准端口业务进程。

当 OAP 或 Prometheus 中断时，采集后端不得使业务请求失败；`start-mvp.sh` 的 Agent 开关默认为 `false`，不改变原有开发启动语义，启用 Agent 时默认同步启用 SkyWalking 日志 Reporter。Reporter 使用单线程、有界队列、短超时和有限重试，stdout 与本地文件始终独立保留；详细 schema、搜索标签和指标见 [日志系统](日志系统.md)。TRACE-01 重型门禁真实验证 Gateway → team → 两个 Feign 下游 → 三个 MySQL 数据库、四服务资源属性、业务 `traceId/swTraceId` 中央日志双向查询、RocketMQ 生产端 Span 和 OAP 中断/恢复；脚本只清理自己的临时 JVM 与唯一消费组，不操作标准端口业务进程。生产通知目标仍由部署环境提供，仓库不保存其凭据。
