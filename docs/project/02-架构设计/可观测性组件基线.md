# 可观测性组件基线

> 基线日期：2026-09-01。本文固化 OBS-01 的可执行结果；总体语义和后续边界仍以 [可观测性与系统保障](可观测性与系统保障.md) 为准。

## 开发环境部署

配置入口为 `LeetModel-backend/docker-compose.observability.yml`，与业务 Compose 分开。所有宿主机端口只绑定 `127.0.0.1`。

| 组件 | 本机端口 | 开发内存上限 | 持久化 / 限制 |
|------|----------|---------------|----------------|
| BanyanDB | 不暴露 | 1 GiB | 独立 stream、measure 命名卷 |
| OAP | `11800` gRPC、`12800` GraphQL/HTTP、`17128` Admin、`11234` Prometheus telemetry | 1400 MiB，JVM `512–1024 MiB` | 只写 BanyanDB；全部只绑定 loopback |
| Horizon UI | `18080` | 512 MiB | 独立 UI 数据卷 |
| Prometheus | `19090` | 512 MiB | 7 天或 1 GB，先到为准 |
| Alertmanager | `19093` | 256 MiB | 独立数据卷，默认只使用本地空接收器 |
| Grafana | `13000` | 512 MiB | 独立数据卷，预置 Prometheus 数据源和六类只读看板 |

本地上限合计约 4.2 GiB，仅用于开发冒烟，不是生产容量承诺。生产 OAP/BanyanDB 必须使用独立集群、卷、账号和容量基线，不得复用 RAG 的 Elasticsearch 实例、索引或凭据。

```bash
cd LeetModel-backend

# 启动固定版本的本地可观测栈
./scripts/start-observability.sh

# 下载/校验 Agent，激活 Gateway 4、WebFlux 6、MVC 6 和 RestTemplate 6 可选插件
./scripts/prepare-skywalking-agent.sh

# 按需为 13 个业务服务附加 Agent；默认值 false 不改变旧启动语义
LEETMODEL_SKYWALKING_ENABLED=true ./scripts/start-mvp.sh

# 停止可观测容器，保留命名卷
docker compose -f docker-compose.observability.yml down
```

Horizon 不在仓库中提供默认用户或密码。需要登录时，在运行环境用 `HORIZON_AUTH_LOCAL_USERS` 注入用户和 Argon2 密码哈希。Grafana 本地基线只开放匿名 Viewer；生产必须关闭匿名访问并在反向代理层启用 TLS 和组织身份源。OAP、Prometheus、Grafana 和管理端点都不经公网 Gateway 暴露。

本地业务服务是宿主 JVM，Prometheus 和 Grafana 使用 host network 直连，并分别显式监听 `127.0.0.1:19090` 与 `127.0.0.1:13000`；不能删除 loopback 绑定。`start-observability.sh` 在 `.observability-runtime/management-token` 生成或复用 64 字符十六进制管理 Token，文件不进入 Git，并以宿主用户组只读方式提供给非 root Prometheus 进程。随后运行 `start-mvp.sh` 会自动读取同一文件并设置业务进程的 `MANAGEMENT_TOKEN`；显式环境变量仍可覆盖这一行为。

Prometheus 的 file-SD 固定列出 13 个服务，不通过 Gateway 抓取；基础设施目标包括 Prometheus 自身、OAP、Alertmanager 和 Grafana。Grafana provisioning 固定加载系统总览、MVP 主链、AI 资源与稳定性、异步任务、可靠消息和遥测管道六类看板。当前 Alertmanager 的 `critical/warning` 路由与同级抑制使用本地空接收器，只验证分组语义；生产通知目标和告警阈值必须在后续告警任务中配置。


## Agent 兼容结论

| 能力 | 项目版本 | 官方声明 | 2026-09-01 项目实测 | 结论 |
|------|-----------|----------|----------------------|------|
| Spring MVC | Spring Framework 6 / Boot 3.3 | MVC 6 插件支持 | `user-service` 产生 `GET:/internal/users/count` HTTP Trace | 支持 |
| JDBC | MySQL Connector/J 8 | MySQL 8 插件支持 | 真实请求产生 `mysql-connector-java` Span | 支持 |
| Gateway / WebFlux | Spring Cloud Gateway 4 / WebFlux 6 | Gateway 4 与 WebFlux 6 插件支持 | `gateway-service` Actuator HTTP 请求产生 Trace | 支持入站 HTTP；全链路留待 TRACE-01 |
| OpenFeign | Spring Cloud OpenFeign 4.1.3 / Feign 13.3 | 列表仅覆盖 Spring Cloud Feign 1.x/2.x 和 Feign 9.x | 真实 Feign 调用成功，下游 MVC Trace 存在，客户端服务未出现 Exit Span | 当前不支持自动客户端 Trace |
| RocketMQ | Spring 2.3.3 / Client 5.3.1 / Broker 5.5.0 | 列表覆盖 RocketMQ 3.x/4.x/5.x | 生产端出现 `rocketMQ-producer` Exit Span；消费端 Entry Span 未观察到 | 生产端支持；消费端不作自动支持承诺 |

Feign 兼容测试位于 `admin-service` 并只在 `RUN_OBSERVABILITY_COMPATIBILITY=true` 时执行。RocketMQ 协议测试在有、无 Agent 的对照运行中均遇到共享 Broker 重试位点未重置，因此该结果不归因于 Agent，也不将“消费端完全兼容”记为已验证。TRACE-01/TRACE-02 必须根据这两个缺口选择已验证的 Agent 增强或有界的自定义 Span，不得引入 Micrometer Tracing 或 OpenTelemetry Trace Exporter 建第二套 Trace。


## 验收与故障语义

环境需要 Docker Compose、JDK 17、Maven 3.9+、`curl`、`jq`、`rg` 和 GNU `date`。验收脚本会启动一个临时 `user-service` 和 `gateway-service`，验证 HTTP/JDBC Trace、OAP 自监控指标、Prometheus 抓取、本地运行日志以及禁用依赖，退出时只停止临时 Java 进程。

```bash
cd LeetModel-backend
./scripts/verify-observability-baseline.sh

# 额外暂停并恢复 OAP，确认业务请求 fail-open
VERIFY_OAP_OUTAGE=true ./scripts/verify-observability-baseline.sh

# 只校验 Compose、目标、规则、路由、看板与管理边界
./scripts/verify-observability-stack.sh --static

# 启动一个 18094 临时 Gateway，验证受保护抓取、查询、看板与 Prometheus 中断恢复
./scripts/verify-observability-stack.sh
```

指标栈验收同时使用 `promtool`、`amtool`、Grafana API 和 Prometheus API，确认 13 个固定目标、四个基础设施目标、六个看板及其中的 PromQL。脚本只停止自己启动的 `18094` 临时 JVM；Prometheus fail-open 演练只停止并恢复可观测 Compose 内的 Prometheus，不操作标准端口业务进程。

当 OAP 或 Prometheus 中断时，采集后端不得使业务请求失败；`start-mvp.sh` 的 Agent 开关默认为 `false`，不改变原有开发启动语义。当前日志验收只证明 stdout/本地文件可读，不代表已完成 JSON schema 或 SkyWalking 日志上报；生产告警与 Runbook 留给 MET-04，日志采集留给 LOG-01–03。
