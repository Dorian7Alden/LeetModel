# 题目详情侧栏 UI/UX 设计

## 1. 设计目标

题目详情页的主体负责完整阅读题面，右侧栏负责帮助用户完成四个连续判断：

1. 这是什么题，属于哪个赛事与赛题编号？
2. 完成它需要投入多少时间？
3. 平台上是否已有可参考的实训表现？
4. 我应从哪里开始，并能立即执行什么动作？

侧栏不是题目字段的机械陈列，也不是榜单的缩小版。它是阅读题面过程中的“选题与启动面板”，必须让关键信息先出现、辅助信息后出现，并保证数据语义真实。

视觉上复用题库右栏“热门练习题”“热门标签”的卡片语言：白色背景、无显式描边、`8px` 圆角和轻柔阴影。详情侧栏只使用一张连续卡片，概览、动作、附件、实训数据和提示通过留白衔接，不再拆成多张卡片。

## 2. 现状问题

旧侧栏把题目标题、操作按钮、静态详情和附件拆成彼此割裂的卡片，存在以下问题：

- 标题重复但缺少题目身份层级，平台题号与赛事题号不易区分。
- 赛事、年份、语言、时长等字段以长列表呈现，占用大量空间，却不能帮助用户快速判断投入成本。
- `averageScore = 0.00` 被放大展示为“历史平均预评分”，当实际没有评审样本时会形成错误暗示。
- 没有呈现题目的任务数量和问题结构，用户只能滚动全文理解题量。
- 行动入口与信息判断割裂，“创建队伍”更像后台动作，而不是用户目标。
- 附件可下载，但其信息权重与主任务相近，造成视觉噪声。
- 每组信息都使用圆角、描边和独立底色，形成“卡片套卡片”的组件堆叠感；问题不在于存在卡片，而在于分组过碎和嵌套过多。

## 3. 数据口径

### 3.1 当前可用数据

| 信息 | 数据来源 | 展示用途 |
|------|----------|----------|
| 平台题号、赛事缩写、赛事题号、标题、赛事、年份 | 公开题目详情接口 | 识别题目身份 |
| 难度、建议时长 | 公开题目详情接口 | 判断学习门槛与投入成本 |
| 按类型归类的标签、附件及文件大小 | 公开题目详情接口 | 仅模型算法标签进入胶囊标签，背景领域和题目类型不在侧栏展示 |
| 参赛队伍数、参赛总人数 | team-service 公开聚合接口 | 反映真实参与规模 |
| 提交总次数 | submission-service 公开聚合接口 | 反映题目练习活跃度 |
| 队伍分数分布 | ranking-service 当前题目排行接口 | 观察已完成评分队伍在 0–100 分区间的集中程度 |
| 精短解题提示 | problem-service 题目详情中的 `solutionHint` | 提供可审核的建模切入点 |

### 3.2 实训统计语义

- 参赛队伍：team-service 中有效且未删除的队伍数。
- 参赛总人数：上述有效队伍中的去重用户数；不把用户表作为 team-service 的数据所有者。
- 提交总次数：submission-service 中状态为 `SUCCESS` 且未删除的提交记录数，明确标注为“提交总次数”。
- 三项统计均为匿名可读的聚合数据；接口失败时单项显示“—”，不阻塞题面阅读。
- 当前没有可靠来源的浏览量、收藏量、通过率、完成率或热度不得展示。

## 4. 信息架构与视觉层级

侧栏按以下顺序组织，越靠前越影响用户是否选择并开始该题，全部位于同一张卡片内：概览与动作 → 附件 → 实训数据 → 解题提示。

### 4.1 题目概览

- 第一行按“题号 16、2024、赛事缩写、C题”的顺序展示，使用间距分隔，不使用竖线；赛事缩写与赛事题号相邻。
- 标题作为侧栏唯一主标题。
- 难度、训练时长以及类型为 `MODEL_ALGORITHM` 的标签使用一行胶囊标签，时长统一使用 `72h` 格式；`BACKGROUND_DOMAIN` 和 `PROBLEM_TYPE` 标签不展示，胶囊不使用前置圆点。
- 年份并入事实行，不再展示无业务价值的任务数量或附件数量。

题目概览与行动中心位于同一张卡片中。平台题号使用蓝色文字，信息区通过间距衔接，让主按钮成为卡片内唯一的高强调色块。

### 4.2 行动中心

- 主行动命名为“以此题开始实训”，直接表达用户目标。
- “寻找队伍”和“完整榜单”作为并列次级动作。
- 主行动使用品牌蓝实底，次级动作使用白底描边；同一区域只保留一个高强调按钮。

### 4.3 实训数据

实训数据使用同一张卡片中的三列紧凑指标：参赛队伍、提交总次数、参赛总人数。三项指标同等重要，采用留白和间距组织，不使用竖线分隔；与附件、分数分布、提示区之间使用统一的横向分隔线，不额外添加统计说明段落。

指标下方展示“分数分布”条形图：读取当前题目榜单中的队伍最终得分，将每个分数使用四舍五入归入 `0–100` 的整数分值，再统计每个分值对应的队伍数。横轴完整覆盖 `0–100`，仅标注每 10 分刻度以保持紧凑；纵轴显示队伍数量，悬停柱体可查看具体分值与队伍数。没有已完成评分队伍或排行接口不可用时显示空状态，不阻塞其他题目信息。

### 4.4 解题提示

解题提示位于整张卡片最末尾，标题前使用 Lucide `Lightbulb` 图标；附件位于实训数据上方，标题前使用 Lucide `Paperclip` 图标。

提示语遵循以下规则：

- 只提供第一步的建模视角、变量抽象或验证方法，不给出完整模型、参数和最终结论。
- 控制为一到两句，能够在约五秒内读完。
- 只采用题目编辑者维护并由后端返回的 `solutionHint`；字段为空时显示“暂无解题提示”。
- 前端不再从 Markdown 自动提取问题数量、任务摘要或生成提示，保证内容稳定、可审核。

“板凳龙”题目的当前提示为：

> 先把各把手抽象为螺线上的运动点，用递推关系传播位置和速度，再逐步加入碰撞、调头与限速约束。

### 4.5 附件与数据

附件位于实训数据上方，每个文件只占一行，依次展示文件类型图标、文件名、文件大小和下载按钮。压缩包、文档、表格、图片使用不同图标和颜色；没有附件时提供解释性空状态。

## 5. 交互与状态

- 桌面端侧栏滚动区域宽度为 `360px`，其中左右各保留 `14px` 透明空间承接卡片阴影；侧栏在视口内吸顶并独立滚动，滚动条保持可见。
- 一级卡片统一使用与题库辅助区相同的白底、`8px` 圆角和 `0 6px 18px rgba(30, 41, 59, 0.085)` 阴影。
- 滚动容器不得紧贴卡片边缘，顶部、左右和底部必须为投影扩散预留空间，避免 `overflow` 裁切造成阴影参数相同但观感不同。
- 单卡片内部区块使用留白衔接；附件与实训数据、实训数据与分数分布、分数分布与提示之间使用统一的横向分隔线，不使用背景、阴影或嵌套容器。
- 操作按钮保留轻微的 `3–4px` 圆角，与信息卡片的容器圆角形成清晰区分。
- 低于 `1100px` 时切换为正文与侧栏纵向排列，取消吸顶和内部滚动。
- 低于 `640px` 时缩小题面内边距与标题字号，保证窄屏阅读。
- 实训统计与分数分布并行加载，不阻塞题目详情；单个统计接口失败时该指标显示“—”，分数分布显示空状态。

## 6. 当前边界与后续演进

本轮新增题目 `solutionHint` 字段，并由 problem-service 详情接口返回；team-service 与 submission-service 分别提供匿名聚合统计；分数分布复用 ranking-service 的当前题目排行只读接口，不新增存储或排行计算规则。完整榜单仍通过“完整榜单”按钮进入，侧栏只展示聚合后的分布概览。

后续只有在产品确实采集并定义了浏览、收藏、开始实训、完成评审等事件后，才讨论转化率、完成率和热度指标；不能用缺少口径的数据装饰面板。
