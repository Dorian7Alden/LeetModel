## 知识库管理 UI/UX 设计

> 设计状态：P0 已实现。
>
> 适用入口：管理端内容中心的“知识库”完整工作面，地址为 `/admin/content?view=knowledge`。

### 一、目标与事实边界

知识库工作面帮助管理员回答三件事：当前索引是否可用、知识文档如何组织、目标文档的元数据是什么。界面只展示接口已返回的事实，不把默认别名、默认版本或默认健康状态当作加载结果。

- 左侧目录导航按 `path` 表达真实父子层级，节点数量为该目录及后代的文档总数。
- 右侧使用高密度表格展示文档标题、文件名、权威等级、方法、标签和摘要。
- 顶部索引事实区只在索引请求成功后展示别名、版本、文档数、分块数和健康状态。
- 导出、导入和重建索引属于工作面级动作；文档元数据在右侧详情面板查看。

### 二、页面结构

```text
┌──────────────────────────────────────────────────────────────────┐
│ 索引：{真实状态} · {接口别名} · {文档数} 文档 · {分块数} 分块    │
│ 搜索目录/文档/标签          [导出] [导入] [重建索引] [刷新]       │
├──────────────────┬───────────────────────────────────────────────┤
│ 目录 · 30         │ 数学建模 / 论文评审 / 评审板块       8 个文件 │
│ ▾ 数学建模 · 73   │ 文件名       等级   标签/方法       Token      │
│   ▾ 论文评审 · 19 │ 摘要要点.md   L3     摘要规范       1,600      │
│     评审板块 · 8  │ 模型检验.md   L3     残差分析       1,700      │
│   模型方法 · 7    │                                               │
└──────────────┴───────────────────────────────────────────────────┘
```

页面不使用 Hero、指标卡、英文装饰标题和重复说明文字。目录是单选浏览上下文；文件名是文档表第一识别信息，标题只作次级补充。搜索同时匹配目录、文件名、标题、标签和方法，结果保留命中项的完整祖先链，清空搜索恢复完整目录集合。

### 三、状态模型

目录文档与索引状态来自不同接口，必须独立管理：

| 状态 | 目录文档区域 | 索引事实区 |
|------|--------------|------------|
| 首次加载 | 表格骨架或加载态 | 显示“正在取得索引状态” |
| 加载成功 | 展示真实目录和文档 | 展示接口返回的别名、版本、数量和健康状态 |
| 目录失败 | 错误状态面板，可重新加载 | 保留已成功取得的索引事实 |
| 索引失败 | 目录与文档仍可管理 | 明确显示“索引状态未取得”，提供重试 |
| 刷新失败且有旧数据 | 保留旧目录文档并显示过期提示 | 不覆盖最近一次成功的索引事实 |
| 空数据 | 显示知识文档空状态 | 展示接口真实返回的零值与状态 |

任何失败都不得以 `MANIFEST_...`、固定别名、固定数量或“健康”作为占位。未知与不健康是两种不同状态，不能混用。

### 四、交互与反馈

1. 点击目录节点同时选中并展开或折叠该节点；键盘焦点、悬停和选中态清晰区分。面包屑可回到当前路径中的任一祖先目录。
2. 没有独立 Manifest 的中间路径仍作为虚拟父目录展示；它只聚合后代文档数，不伪造直接文件或标签。选中后显示“当前层级仅包含子目录”。
3. 点击文件名打开详情面板，集中展示相对路径、摘要、权威等级、方法和标签；列表不渲染 Markdown 正文。
4. 搜索命中文件或深层目录时自动展开祖先节点；目录计数和当前文件数随过滤结果变化，避免用全量数字解释局部结果。
5. 导入 ZIP 在确认文件后提交，成功后重新加载目录与索引事实；失败保留工作面上下文并给出错误反馈。
6. 重建索引必须二次确认，执行中禁用重复提交；完成后重新取得真实索引状态。
7. 导出失败、导入失败、鉴权失败和断网均使用明确错误反馈，不把按钮点击当作成功。

### 五、范围与取舍

- 当前仅验收 PC Web，最小宽度为 1024px；不为手机端另造目录或编辑流程。
- 当前不引入标签云、拖拽排序、在线编辑、正文预览或知识正文迁移。
- `/admin/knowledge/tree` 必须返回嵌套 `children`；`directDocumentCount` 表示当前目录直接文件数，`documentCount` 表示包含后代的聚合数，`virtual` 标识由路径补齐的中间目录。
- 不改变 Manifest 格式、文件事实源和索引数据所有权；前端保留对历史平铺响应的过渡兼容，层级仍只从标准化 `path` 推导。

### 六、实施状态

实施状态（2026-09-14）：知识库工作面已使用可展开目录树呈现任意深度父子关系，以完整路径作为节点唯一键；文件表以文件名、标题、标签/方法、权威等级和 Token 组成扫描主线。搜索可命中目录或文件元数据，保留并展开祖先链，过滤计数与当前结果一致。后端已按 Manifest `path` 补齐虚拟父目录并返回嵌套 `children`，父目录聚合数量不重复计算。
