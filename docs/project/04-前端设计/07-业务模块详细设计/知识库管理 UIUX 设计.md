## 知识库管理 UI/UX 设计

> 设计状态：P0 已实现。
> 适用入口：管理端内容中心的“知识库管理”页面。

### 一、问题与目标

知识库数据同时包含物理目录、文档文件和多维标签。原页面使用多层折叠列表承载三种信息，目录边界、标签关系和文档差异不够明显，管理员需要逐行扫描才能找到目标文档。

本次 P0 改造只调整前端展示层，不修改知识库接口和事实源：

- 左侧目录导航表达物理层级，并展示目录文档数量。
- 右侧文档卡片表达文件身份、摘要、权威等级和标签。
- 目录标签与文档标签分区展示，避免把标签误认为路径层级。
- 保留搜索、详情弹窗、ZIP 导入导出和索引重建等既有操作。

### 二、页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 指标卡片                                                     │
├──────────────────────────────────────────────────────────────┤
│ 搜索目录/文档/标签       导出 ZIP  上传 ZIP  重建索引  刷新    │
├──────────────┬───────────────────────────────────────────────┤
│ 目录导航      │ 当前目录标题、路径、文档数                     │
│ 目录 A · 12篇 │ 目录标签：方法 / 赛事 / 质量                    │
│ 目录 B · 8篇  │ ┌──────────────┐ ┌──────────────┐              │
│ 目录 C · 21篇 │ │ 文档卡片      │ │ 文档卡片      │              │
│               │ │ 标题/文件名   │ │ 摘要/标签     │              │
│               │ └──────────────┘ └──────────────┘              │
└──────────────┴───────────────────────────────────────────────┘
```

目录导航是单选上下文；搜索命中多个目录时默认选中第一个命中目录，管理员可切换查看其他目录。文档卡片支持点击和键盘 Enter 打开详情。

### 三、信息层级

| 信息 | 主展示位置 | 视觉规则 |
|------|------------|----------|
| 目录标题 | 左侧目录项、右侧当前目录标题 | 作为当前浏览上下文的一级标题 |
| 目录路径 | 当前目录标题下方 | 使用等宽字体，弱化显示，避免与标题竞争 |
| 文档标题 | 文档卡片标题 | 两行截断，优先保证可扫读 |
| 文档文件名 | 文档卡片副标题 | 使用等宽字体，显示真实相对文件名 |
| 摘要 | 文档卡片正文 | 最多三行，缺失时明确显示“暂无摘要” |
| 权威等级 | 卡片右上角 | 沿用 L1-L4 颜色语义 |
| 目录标签 | 当前目录标题下方 | 独立标签带集中展示 |
| 文档标签与方法 | 卡片底部 | 最多显示 5 个，超出显示剩余数量 |

### 四、交互与边界

1. 卡片只负责导航和识别，不在列表内直接渲染 Markdown 正文；详细元数据继续放在详情弹窗中。
2. 目录筛选不改变后端返回数据，搜索结果只在前端裁剪目录和文档集合。
3. 当前 P0 不引入标签云、拖拽排序、在线编辑和知识正文迁移，这些属于后续功能设计。
4. 响应式宽度低于 768px 时，目录导航改为横向可换行布局，文档卡片退化为单列。
