## 论文专业评审与建议 V4 UIUX 设计

> 设计状态：已完成实现并经验收。当前只做 PC Web，不设计手机端。
> 确认日期：2026 年 9 月 16 日。


### 一、页面目标

V4 报告页面要让用户快速完成三层阅读：

1. 先理解总体表现和最重要问题。
2. 再分别查看问题、亮点和题目覆盖。
3. 最后按需展开原文证据、知识依据和建议方向。

界面不通过堆叠大量卡片制造专业感，专业性来自信息层级、证据和可追溯性。


### 二、评审报告结构

```text
+---------------------------------------------------------------+
| 总分 · 版本 · 规则 · 综合评审 Markdown                        |
+---------------------------------------------------------------+
| 五维评分                                                      |
| 每维：得分 / Markdown 理由 / 关联问题与亮点数量                |
+---------------------------------------------------------------+
| 关键问题                                      [全部展开]      |
| P0/P1/P2/P3 · 标题 · 详细解释 · 为什么重要 · 页码             |
| [查看原文依据] [查看专业依据]                                  |
+---------------------------------------------------------------+
| 论文亮点                                                      |
| 核心亮点 · 为什么值得保留 · 原文证据                           |
+---------------------------------------------------------------+
| 赛题要求覆盖 · 报告边界 · 版本信息                             |
+---------------------------------------------------------------+
```


### 三、评审交互

- 综合评审、维度原因、问题解释、影响、覆盖说明和原文均使用 `MarkdownView`。
- 关键问题默认展示前 5 条，严格使用后端排序。
- P0/P1 视觉更突出，但不使用大面积红色背景。
- 论文亮点作为独立板块，不能被过滤。
- 原文依据使用折叠区，显示章节、物理页码、块类型和 Markdown 摘录。
- 公式块保留横向滚动；表格进入统一滚动容器。
- 知识依据显示来源、支撑结论和适用性。
- 点击页码保留未来 PDF 跳转扩展位，当前至少能打开对应 PDF 页。


### 四、建议报告结构

```text
+---------------------------------------------------------------+
| 本轮完善主线 Markdown                                         |
+---------------------------------------------------------------+
| 优先事项 1-3                                                  |
+---------------------------------------------------------------+
| P1 · 必要补充 / 完整性增强 / 可选探索                         |
| 建议标题                                                      |
| 当前论文事实 Markdown                                         |
| 为什么值得处理 Markdown                                      |
| 建议补充的方面 Markdown                                      |
| 适用性与取舍 Markdown                                        |
| [原文依据] [评审依据] [知识依据]                              |
| 完成标准                                                      |
+---------------------------------------------------------------+
```


### 五、标签文案

| 后端值 | 用户文案 |
|--------|----------|
| `REQUIRED_FIX` | 必要修正 |
| `COMPLETENESS_ENHANCEMENT` | 完整性增强 |
| `OPTIONAL_EXPLORATION` | 可选探索 |
| `STRENGTH` | 论文亮点 |
| `ISSUE` | 评审问题 |

V4 不再使用“高分升华”“金牌药方”等暗示结果承诺的文案。


### 六、统一渲染

- `SubmissionReviewDrawer.vue` 和 `SubmissionSuggestionDialog.vue` 必须使用 `MarkdownView`。
- 禁止继续直接调用 `renderSafeMarkdown()` 后通过局部 `v-html` 上屏。
- 业务组件只负责布局、标签、折叠和命令按钮。
- Markdown 字体、公式、表格、代码、图片与引用样式由统一组件维护。


### 七、状态与兼容

- V1-V3 保留当前历史布局，不伪造 V4 字段。
- V4 结果解析失败时显示原始文本和版本信息，不隐藏整个报告。
- 某条知识依据不可用时标记“依据暂不可用”，不把建议主体清空。
- 没有亮点时显示“当前未形成可验证亮点”，不生成假亮点。
- 没有问题时显示“当前未形成可验证问题”，不把分数解释为满分。


### 八、验收

- Markdown 标题、列表、引用、表格、代码和公式均正常。
- 用户能一眼区分问题、亮点和三类建议。
- 问题顺序与后端一致。
- 每条报告项都能展开原文和知识依据。
- 页面不存在原始 HTML 注入和重复 Markdown 样式。
- 长公式、长单词、表格和代码不会撑破抽屉或对话框。
