## 设计系统与规范

> 本文档以当前题库前端的真实实现与浏览器表现为依据，提炼 LeetModel 用户端可复用的视觉与交互基线。它描述已经形成的设计语言，并为后续队伍模块优化提供约束。题库专属的信息架构和赛事表达不自动成为其他模块的通用结构。

### 设计结论

LeetModel 用户端采用冷静、清晰、轻量的专业学术工作台风格。

页面以白色和中性灰建立稳定结构，通过字体层级、留白、弱分隔和高密度信息编排呈现专业感。赛事品牌色、主行动蓝色和状态语义色只在需要识别、决策或反馈的位置出现，不把整页做成彩色运营界面。

设计语言可以概括为以下五点：

1. 内容优先。题目、队伍状态和关键行动始终高于装饰。
2. 结构克制。大面积使用扁平表面，依靠留白和对齐组织层级。
3. 色彩受控。中性色负责结构，彩色只负责品牌、语义和行动强调。
4. 信息紧凑。列表和工具栏优先提高扫描效率，避免企业后台式选项墙。
5. 交互确定。路由、筛选、状态和操作结果应可恢复、可理解、少打扰。

### 依据与适用范围

当前基线主要来自以下实现：

- `src/style.css` 定义全局字体、色彩、圆角、阴影、动效与 Element Plus 映射。
- `ProblemLayout.vue` 定义题库常驻工作台和子视图切换方式。
- `ProblemSidebar.vue` 定义可折叠、可拖拽的上下文导航。
- `ProblemHeader.vue` 定义赛事入口、紧凑筛选和轻量操作控件。
- `ProblemList.vue` 定义高密度单行题目流和渐进加载。
- `ProblemRightAside.vue` 定义低优先级辅助信息卡片。
- `ProblemDetailPage.vue` 定义学术阅读区、题目信息区和行动层级。

本文档适用于用户端实训应用域。官网和管理端拥有不同任务密度与用户目标，只继承基础令牌，不直接继承页面结构。

### 色彩体系

#### 结构色

| 用途 | 当前基线 | 使用原则 |
|------|----------|----------|
| 主文本 | `#09090b` | 标题、核心数据和当前焦点 |
| 强调黑 | `#18181b` | 主导航焦点、深色按钮和强交互反馈 |
| 次级文本 | `#52525b` | 普通说明、列表元数据和次级操作 |
| 弱化文本 | `#71717a` | 辅助说明、占位信息和低优先级内容 |
| 页面与表面 | `#ffffff` | 页面底色、主要内容区和卡片表面 |
| 浅灰表面 | `#f4f4f5` | 筛选胶囊、选中背景和轻量分区 |
| 边框 | `#e4e4e7` | 必要分隔、输入边界和次级按钮 |

结构层默认保持黑白灰。不要使用大面积渐变背景、重描边或多层阴影制造层级。

#### 行动色与语义色

- 主行动蓝色采用 `#2563eb`，悬停态采用 `#1d4ed8`。它用于真正推动主流程的按钮、关键指标和当前交互焦点。
- 成功、警告、危险分别使用低饱和绿色、琥珀色和红色。颜色必须绑定明确状态，不能只为装饰使用。
- 紫色、青色和粉色用于区分题型、领域和算法等并列维度。文字仍保持中性深色，避免形成彩色文字墙。
- 收藏使用金黄色，热门度使用橙色。两者都是稳定业务语义，不应挪作普通强调色。

赛事卡片是结构色规则的明确例外。赛事具有品牌识别与探索入口职责，可以使用独立背景图和较高色彩辨识度，但彩色区域应集中在卡片内部，不能扩散为页面主背景。

### 字体与数据表达

- 正文使用 `Noto Sans SC Variable` 与系统中文无衬线字体回退链。
- 普通控件和元数据以 `11px` 到 `14px` 为主，页面核心标题以 `18px` 到 `20px` 为主。
- 信息层级主要依靠字重和明度变化，不依靠连续放大字号。
- 题号、年份、分数、计数和坐标刻度使用等宽字体或等宽数字，确保纵向扫描时稳定对齐。
- 业务界面显示题目 `code`、赛事题号和其他业务标识，不使用数组序号或内部数据库 ID 代替。
- 长标题采用单行省略，并通过 Tooltip 提供完整内容。正文和题面不做无意义截断。

### 布局与空间

#### 全局骨架

- 用户端顶部导航固定为 `56px`，保持全局入口稳定。
- 题库列表页使用三段式工作台。左侧是上下文导航，中间是主任务流，右侧是辅助信息。
- 左侧导航默认宽度为 `240px`，允许在 `140px` 到 `280px` 之间调整，也允许完全折叠。
- 右侧辅助区宽度为 `240px`，只承载热门内容、标签和帮助入口，不抢占主任务焦点。
- 中间区域使用弹性宽度，页面主间距以 `16px`、`24px` 和 `28px` 为主要尺度。

#### 发现页与详情页

发现页强调扫描和筛选。赛事入口、筛选工具、单行列表和辅助推荐从上到下形成稳定节奏，题目列表不改造成大尺寸卡片网格。

详情页强调阅读和行动。左侧承载完整 Markdown 题面，右侧使用 `360px` 的粘性信息栏集中放置题目标识、开始实训、寻找队伍、榜单、附件、统计与提示。主操作不分散到正文中。

页面结构切换遵循渐进披露：

1. 发现页快速判断赛事、题号、难度和平均分。
2. 详情页完整阅读题面并确认投入信息。
3. 用户通过单一主行动进入组队与实训流程。

### 表面、圆角与阴影

- 主内容区默认无边框、无阴影，使用白底和留白建立层级。
- 列表行使用透明底和极浅交替底色，悬停只做轻微背景变化。
- 普通控件主要使用 `4px`、`6px` 和 `8px` 圆角。
- 胶囊圆角只用于筛选、短标签、计数和状态，不用于长正文容器。
- 阴影只用于粘性辅助卡、下拉层和悬浮控制。常用阴影保持低透明度，避免多层悬浮卡堆叠。
- 赛事入口允许使用 `10px` 圆角和背景图，但不额外叠加厚边框与重阴影。

### 控件与状态层级

#### 行动层级

| 层级 | 表现 | 适用场景 |
|------|------|----------|
| 主行动 | 实色蓝底、白字、整行或明显宽度 | 开始实训、提交和确认关键状态变化 |
| 次行动 | 白底细边框、中性色文字 | 寻找队伍、查看榜单和辅助跳转 |
| 轻行动 | 无边框图标或文字 | 排序、重置、收藏和返回 |

一个局部工作区通常只保留一个主行动。多个同色实心按钮会破坏决策优先级。

#### 导航与筛选

- 当前导航项使用浅灰或浅色背景和更高字重，不依赖粗边框。
- 二级导航只在用户展开时出现，避免首屏同时展示全部层级。
- 筛选项采用单行紧凑胶囊。图标可用不同语义色帮助快速定位，文字保持中性灰。
- 搜索、排序、结果数量和随机入口组成次级工具行，与主要筛选维度分层。
- 当前筛选应同步到 URL，用户进入详情后返回时保持上下文。

#### 状态与反馈

- 加载、空状态、禁用、失败和全部加载完成必须有明确文案，不使用空白区域代替状态。
- 收藏等高频轻操作应即时更新相关计数，并避免弹窗或成功 Toast 打断浏览。
- 锁定数据使用锁图标和 Tooltip 解释访问条件。
- 业务状态同时使用文字、图标或形状表达，不能只依赖颜色。

### 图标与动效

- 统一使用 Element Plus 或 Lucide 线性图标，不使用 Emoji 充当业务图标。
- 图标尺寸通常在 `13px` 到 `18px` 之间，描边保持轻量一致。
- 无文字图标按钮必须提供 `aria-label`、`title` 或 Tooltip。
- 常规过渡使用约 `0.16s` 到 `0.24s` 的缓动。
- 悬停位移控制在 `2px` 到 `3px`，缩放只用于收藏、折叠和轮播箭头等小控件。
- 动效用于表达焦点、展开和路由切换，不使用循环装饰动画。加载图标除外。
- 隐藏式控件只有在不影响发现性时使用。轮播箭头和侧栏折叠按钮可在悬停时出现，主行动不可隐藏。

### 响应式规则

- 页面以 `320px` 为最小可用宽度，不允许出现水平溢出。
- 宽度低于 `1280px` 时，右侧辅助区进入主内容下方，主任务优先保留。
- 宽度低于 `1100px` 时，详情页由双栏切换为单栏，右侧信息区取消粘性定位。
- 宽度低于 `1000px` 时，列表隐藏年份、难度和标签等次要列，保留题目标识、标题、核心数值和操作。
- 宽度低于 `900px` 时，赛事卡片改为横向滑动，筛选控件允许换行。
- 宽度低于 `860px` 时，题库工作台转为纵向结构并缩小页面边距。
- 宽度低于 `768px` 时，全局导航收敛为移动端菜单。
- 宽度低于 `640px` 时，详情页缩小正文内边距和标题字号。

响应式不是等比例缩小桌面布局。每个断点都应按“主任务、关键状态、次要信息”的顺序进行重排或隐藏。

### 队伍模块继承规则

后续队伍模块优化应直接继承以下设计基线：

- 白色与中性灰主结构，以及受控的主行动蓝色和状态语义色。
- `56px` 顶部导航、紧凑字号、低阴影、适量圆角和等宽数字。
- 主要任务居中，辅助信息降级，状态与行动集中呈现。
- 单一主行动、次行动描边、轻操作无边框的操作层级。
- Tooltip、空状态、加载状态、禁用原因和移动端重排规则。
- 轻量路由过渡和不打断主流程的局部即时反馈。

以下题库设计不应直接复制到队伍模块：

- 赛事彩色卡片只服务赛事识别，不能直接变成队伍卡片的默认视觉。
- 题库左侧赛事与题号导航只服务题目发现，队伍模块是否需要常驻侧栏必须根据队伍生命周期重新判断。
- 题目单行列表服务快速扫描，队伍列表需要优先表达成员、职责、状态、期限和下一步行动，不能只替换字段。
- 题目详情的阅读主导布局不等同于队伍详情。队伍详情应以协作状态、实训进度和提交行动为核心重新组织。

队伍模块进入具体设计前，应先梳理“我的队伍、队伍广场、队伍详情”三类入口的用户目标、状态变化和主行动，再基于本设计系统选择布局。设计系统约束视觉语言，不替代业务信息架构。

### 实施检查

新增或调整用户端页面时至少检查以下内容：

- 页面是否能用一句话说明唯一主任务。
- 首屏是否只有一个清晰主行动。
- 结构是否主要由对齐、留白和字体层级建立。
- 彩色元素是否具有明确品牌、状态或行动语义。
- 数据是否使用稳定列宽和等宽数字。
- 长文本、空状态、加载、失败和禁用状态是否完整。
- 图标是否来自统一组件库并具备可访问名称。
- 桌面端与移动端是否都没有水平溢出。
- 是否通过真实浏览器核对视觉层级、交互反馈和关键断点。
