## 00-development-setup



### 开发初始化约定

> 【强制】：必须遵守的内容
>
> 【推荐】：最好遵守的内容，特殊条件下可以自行调整

1. 【强制】每次开始开发前，先完整阅读一次 `` 目录下的规范文档。
   说明：通过“开发前必读”动作同步最新规则，避免因规范理解不一致造成返工。

2. 【强制】阅读完成后再进入编码、改库、联调、提测等任何开发动作。
   说明：该约定适用于后端、前端、文档和脚本等全部开发内容。

3. 【推荐】阅读顺序保持稳定，建议按编号从小到大阅读。
   说明：编号顺序有助于先统一格式规范，再落地到具体业务规范。

4. 【推荐】如果本次任务涉及 Git commit 描述或提交格式，请补充阅读 `/05-git-commit-regulation.md`。
   说明：提交信息写法单独成章时，优先直接查阅对应规范文件。



### 开发前最小执行清单

1. 进入 `` 目录。
2. 按顺序阅读当前全部规范文件。
3. 确认本次任务是否涉及对应规则（如命名、响应、文档规范）。
4. 完成确认后再开始开发实现。



### 适用范围

- 日常功能开发
- 缺陷修复
- 重构优化
- 文档维护
- AI 协作开发


### 开发约定

开发流程与提交粒度的执行细则，统一遵循 `/04-development-workflow.md`。

该文档定义了目标确认、版本 TODO 对齐、按 TODO 开发、TODO 与 commit 对齐的强制要求。

Git commit 描述格式与示例，统一遵循 `/05-git-commit-regulation.md`。
