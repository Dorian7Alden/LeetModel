## 一、设计背景与目标

### 1.1 项目背景

LeetModel（力模）是一款对标 LeetCode 的**数学建模**领域垂直在线实训平台，核心聚焦数学建模赛事全链路能力提升。平台深耕数学建模赛事实训场景，完整覆盖主流数学建模赛事（国赛 CUMCM、美赛 MCM/ICM 等）全流程实践环节。

标签体系作为题库管理模块的核心基础设施，直接影响以下功能模块的运作：

| 依赖模块 | 依赖方式 |
|---------|---------|
| 📚 题库管理模块 | 题目创建时的标签绑定、题目列表的多维度筛选 |
| 🎯 专项训练模块 | 按角色方向、模型分类等标签维度推送训练内容 |
| 🤖 AI 评审模块 | 基于标签信息生成精准的评审标准与优化建议 |
| 🏆 赛事模拟模块 | 按赛事来源、年份等标签还原真实赛事环境 |
| 📈 成长体系模块 | 基于标签维度统计能力雷达图与成长轨迹 |
| ⚙️ 平台管理模块 | 标签的增删改查、标签使用统计、热门标签分析 |

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **全面覆盖** | 覆盖数学建模赛事全链路的题目分类需求，涵盖难度、角色、赛事、类型、模型、行业、数据等维度 |
| **层级清晰** | 对题目类型、模型分类等复杂维度支持最多三级层级，保证分类的专业性与系统性 |
| **原子化** | 每个标签语义独立、边界清晰，不产生歧义或交叉覆盖 |
| **高可扩展** | 表结构无需变更即可新增分类或标签，ID 编号体系预留充足空间 |
| **前端友好** | 标签命名简洁规范、色值直接可用、层级结构利于前端组件渲染 |
| **查询高效** | 冗余计数字段减少 JOIN 查询，合理索引支撑多维组合筛选 |

## 二、核心设计原则

### 2.1 标签原子化原则

每个标签表达**一个且仅一个**明确语义，不使用复合含义的标签：

```
✅ 正确：「线性规划」「非线性规划」分别建标签
❌ 错误：「线性/非线性规划」合并为一个标签
```

### 2.2 命名规范

| 规则 | 说明 | 示例 |
|------|------|------|
| 不使用 `/` 分隔符 | 避免前端渲染与 URL 编码问题 | ❌ `MCM/ICM` → ✅ `美赛` |
| 不使用括号 | 保持标签名简洁、统一 | ❌ `遗传算法（GA）` → ✅ `遗传算法` |
| 不使用特殊字符 | `name` 字段仅含中英文、数字、连字符 | ❌ `K-Means聚类` → ✅ `均值聚类` |
| 简称优先 | 标签名尽量简短，详细信息放入 `description` | ❌ `全国大学生数学建模竞赛` → ✅ `国赛` |
| 编码语义化 | `code` 使用分类前缀 + 英文语义命名 | `model_ahp`、`comp_cumcm` |

### 2.3 图标统一规范

图标字段 `icon` 统一使用 **URL 格式**（Iconify CDN），不使用 Emoji 或本地路径：

```
✅ https://api.iconify.design/mdi:target.svg
❌ 🎯（Emoji）
❌ /static/icons/target.png（本地路径）
```

优势：前端可直接 `<img src="">` 渲染，CDN 加速，统一设计风格。

### 2.4 层级约束

| 约束 | 说明 |
|------|------|
| 最大深度 | **三级**（L1 → L2 → L3），不允许更深层级 |
| 扁平分类 | 难度、角色、赛事来源、年份、行业、数据特征 → 仅 L1（无子标签） |
| 三级分类 | 题目类型、模型分类 → 支持 L1 → L2 → L3 完整层级 |
| 叶子节点 | 题目关联的标签**可以是任意层级**的标签，包括 L1、L2、L3 |
| 混合叶子 | 同一 L1 下的 L2 可以有的有 L3 子标签、有的没有（如模型分类中"模糊数学"下的 L2 即为叶子节点） |

## 三、架构决策说明

### 3.1 决策总览

| 决策项 | 方案选择 | 候选方案 | 选择理由 |
|-------|---------|---------|---------|
| 标签层级 | parent_id 自引用（最多三级） | ①闭包表 ②路径枚举 ③嵌套集 | 自引用最简洁，三级深度下性能足够，无需复杂的闭包表或路径枚举 |
| 分类与标签关系 | 独立分类表 `tag_category` + 标签表 `tag` | ①合并为一张表 ②仅用字段区分 | 分类有独立属性（是否多选、是否必选），拆表职责更清晰 |
| 多选/单选控制 | 分类级别控制 `is_multiple` | ①标签级别控制 ②前端硬编码 | 多选/单选是分类的属性而非单个标签的属性，分类级别控制最合理 |
| 引用计数 | 冗余字段 `usage_count` | ①每次 COUNT 查询 ②定时任务同步 | 冗余字段避免高频 JOIN，热门标签排序直接 ORDER BY |
| 色值存储 | Hex 色值字符串 | ①枚举值 ②RGB 数字 | 前端 CSS 直接使用 Hex 值，无需额外映射 |
| ID 编号 | 固定 8 位 `AABBCCCC` 格式 | ①自增 ID ②UUID ③雪花 ID | 固定格式 ID 可直观判断标签所属分类和层级，便于调试和维护 |
| 图标存储 | URL 字符串 | ①Emoji 字符 ②图标编码 | URL 格式统一、可更换 CDN 源、前端直接渲染 |

### 3.2 为什么从第一版的二级层级改为三级

第一版设计中，题目类型为扁平结构（11 个标签），模型分类为二级层级（11 个一级 + 63 个二级）。在实际赛题分析中发现：

**题目类型需要更精细的分类**：美赛 MCM/ICM 六道赛题（A-F）有明确的方向划分（连续建模、离散建模、数据洞察、运筹优化、环境科学、社会科学），且每个方向下还有细分的子方向。扁平的 11 个标签无法体现这种层次关系。

**模型分类需要更细的颗粒度**：例如"评价模型"下，主观评价（AHP、模糊评价）和客观评价（熵权法、PCA）差异很大，二级层级不足以表达。增加三级后，结构变为"评价模型 → 主观评价 → 层次分析"，语义更清晰。

**三级层级的前端交互可控**：三级层级在前端可用"折叠面板 + 标签列表"实现，交互复杂度可接受；四级及以上则会显著降低用户体验。

### 3.3 题目类型 L1 与美赛赛题方向的映射关系

第二版的题目类型 L1 一级标签设计，参考了美赛 MCM/ICM 六道赛题的方向划分，这是**有意为之**的设计决策：

| L1 标签 | 对应美赛方向 | 设计意图 |
|---------|------------|---------|
| 连续建模 | MCM Problem A | 微分方程、物理机理等连续数学方法 |
| 离散建模 | MCM Problem B | 图论、组合优化等离散数学方法 |
| 数据洞察 | MCM Problem C | 统计分析、数据挖掘等数据驱动方法 |
| 运筹优化 | ICM Problem D | 物流、网络、排队等运筹学方法 |
| 环境科学 | ICM Problem E | 生态、气候、资源等环境领域问题 |
| 社会科学 | ICM Problem F | 政策、经济、安全等社会领域问题 |

这种映射使得平台可以直接按美赛方向推荐训练题目，同时也兼容国赛及其他赛事的题目分类。

### 3.4 分类的删减说明

相比第一版，第二版进行了以下分类调整：

| 调整 | 第一版 | 第二版 | 理由 |
|:----:|-------|:-----:|------|
| 移除 | 编程工具（`tool`） | — | 编程工具更适合作为题目的"推荐工具"字段存在于题目表中，而非标签维度 |
| 移除 | 论文技巧（`paper_skill`） | — | 论文技巧是论文手专项训练模块的内部分类，不属于题库标签维度 |
| 保留 | 数据特征 | 保留 | 数据特征直接影响解题方法选择，是筛选题目的重要维度 |

## 四、数据库表结构设计

### 4.1 标签分类表 `tag_category`

```sql
CREATE TABLE `tag_category` (
    `id`            BIGINT          NOT NULL AUTO_INCREMENT  COMMENT '分类ID',
    `name`          VARCHAR(50)     NOT NULL                 COMMENT '分类名称',
    `code`          VARCHAR(50)     NOT NULL                 COMMENT '分类编码（唯一标识）',
    `icon`          VARCHAR(100)    DEFAULT NULL             COMMENT '分类图标（URL格式）',
    `description`   VARCHAR(255)    DEFAULT NULL             COMMENT '分类描述',
    `sort_order`    INT             NOT NULL DEFAULT 0       COMMENT '排序权重（升序）',
    `is_multiple`   TINYINT(1)      NOT NULL DEFAULT 1       COMMENT '是否允许多选：0-单选 1-多选',
    `is_required`   TINYINT(1)      NOT NULL DEFAULT 0       COMMENT '是否必选：0-可选 1-必选',
    `status`        TINYINT(1)      NOT NULL DEFAULT 1       COMMENT '状态：0-禁用 1-启用',
    `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP  COMMENT '创建时间',
    `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='标签分类表';
```

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, 自增 | 分类唯一标识，固定为 1-8 |
| `name` | VARCHAR(50), NOT NULL | 分类的中文展示名称 |
| `code` | VARCHAR(50), UNIQUE | 分类的英文编码，用于前后端枚举映射和 API 参数 |
| `icon` | VARCHAR(100) | 分类图标 URL，使用 Iconify CDN |
| `description` | VARCHAR(255) | 分类的功能描述，帮助出题者理解分类用途 |
| `sort_order` | INT, DEFAULT 0 | 前端展示排序权重，数字越小越靠前 |
| `is_multiple` | TINYINT(1), DEFAULT 1 | 控制该分类下标签的选择方式：难度、赛事来源、年份为单选（0）；角色、类型、模型等为多选（1） |
| `is_required` | TINYINT(1), DEFAULT 0 | 控制出题时是否必须选择该分类下的标签：难度、角色、类型、模型为必选（1）；赛事来源、年份、行业、数据特征为可选（0） |
| `status` | TINYINT(1), DEFAULT 1 | 软删除/禁用标记 |
| `created_at` / `updated_at` | DATETIME | 审计字段 |

### 4.2 标签表 `tag`

```sql
CREATE TABLE `tag` (
    `id`            BIGINT          NOT NULL AUTO_INCREMENT  COMMENT '标签ID',
    `category_id`   BIGINT          NOT NULL                 COMMENT '所属分类ID',
    `parent_id`     BIGINT          NOT NULL DEFAULT 0       COMMENT '父标签ID（0=顶级标签）',
    `name`          VARCHAR(50)     NOT NULL                 COMMENT '标签名称',
    `code`          VARCHAR(50)     NOT NULL                 COMMENT '标签编码（全局唯一）',
    `color`         VARCHAR(20)     DEFAULT NULL             COMMENT '标签颜色（Hex色值）',
    `icon`          VARCHAR(100)    DEFAULT NULL             COMMENT '标签图标（URL格式）',
    `description`   VARCHAR(255)    DEFAULT NULL             COMMENT '标签描述',
    `sort_order`    INT             NOT NULL DEFAULT 0       COMMENT '排序权重（升序）',
    `usage_count`   INT             NOT NULL DEFAULT 0       COMMENT '引用次数（冗余计数）',
    `status`        TINYINT(1)      NOT NULL DEFAULT 1       COMMENT '状态：0-禁用 1-启用',
    `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP  COMMENT '创建时间',
    `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    KEY `idx_category_id` (`category_id`),
    KEY `idx_parent_id` (`parent_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='标签表';
```

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK | 标签唯一标识，采用 AABBCCCC 编号体系（见第五节） |
| `category_id` | BIGINT, NOT NULL | 所属分类表的外键，关联 `tag_category.id` |
| `parent_id` | BIGINT, DEFAULT 0 | 父标签 ID，实现自引用层级结构。`0` 表示顶级标签（L1）；非零值指向父标签的 `id` |
| `name` | VARCHAR(50), NOT NULL | 标签的中文展示名称，遵循命名规范（无特殊字符、无括号、无斜杠） |
| `code` | VARCHAR(50), UNIQUE | 标签的英文编码，全局唯一，用于 API 交互和前端枚举 |
| `color` | VARCHAR(20) | 标签渲染色值，使用 Hex 格式（如 `#E53935`），前端 CSS 直接使用 |
| `icon` | VARCHAR(100) | 标签图标 URL（可选，扁平标签一般不设图标） |
| `description` | VARCHAR(255) | 标签的详细说明，帮助出题者理解标签含义 |
| `sort_order` | INT, DEFAULT 0 | 同层级内的排序权重 |
| `usage_count` | INT, DEFAULT 0 | 关联题目数的冗余计数，通过应用层在新增/删除关联时维护，支持热门标签排序 |
| `status` | TINYINT(1), DEFAULT 1 | 软删除/禁用标记 |

**索引说明：**

| 索引 | 类型 | 用途 |
|------|------|------|
| `uk_code` | UNIQUE | 确保标签编码全局唯一，支持按 code 查询 |
| `idx_category_id` | NORMAL | 查询某个分类下的所有标签 |
| `idx_parent_id` | NORMAL | 查询某个父标签下的所有子标签 |

### 4.3 题目-标签关联表 `problem_tag`

```sql
CREATE TABLE `problem_tag` (
    `id`            BIGINT          NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    `problem_id`    BIGINT          NOT NULL                 COMMENT '题目ID',
    `tag_id`        BIGINT          NOT NULL                 COMMENT '标签ID',
    `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP  COMMENT '创建时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_problem_tag` (`problem_id`, `tag_id`),
    KEY `idx_tag_id` (`tag_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='题目-标签关联表';
```

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT, PK, 自增 | 关联记录唯一标识 |
| `problem_id` | BIGINT, NOT NULL | 关联的题目 ID，外键指向 `problem.id` |
| `tag_id` | BIGINT, NOT NULL | 关联的标签 ID，外键指向 `tag.id` |
| `created_at` | DATETIME | 关联创建时间 |

**索引说明：**

| 索引 | 类型 | 用途 |
|------|------|------|
| `uk_problem_tag` | UNIQUE(problem_id, tag_id) | 防止同一题目重复关联同一标签 |
| `idx_tag_id` | NORMAL | 支持"根据标签查询关联题目"的反向查询 |

> 注：`problem_id` 已包含在联合唯一索引 `uk_problem_tag` 的最左前缀中，因此无需单独建索引。

### 4.4 ER 关系图

```
┌──────────────────┐       ┌──────────────────┐       ┌──────────────────┐
│  tag_category    │  1:N  │      tag         │  N:M  │    problem       │
│──────────────────│◄──────│──────────────────│──────►│──────────────────│
│  id (PK)         │       │  id (PK)         │       │  id (PK)         │
│  name            │       │  category_id(FK) │       │  title           │
│  code (UK)       │       │  parent_id(自引用)│       │  ...             │
│  icon            │       │  name            │       └──────────────────┘
│  description     │       │  code (UK)       │               ▲
│  sort_order      │       │  color           │               │
│  is_multiple     │       │  icon            │       ┌───────┴──────────┐
│  is_required     │       │  description     │       │  problem_tag     │
│  status          │       │  sort_order      │       │──────────────────│
│  created_at      │       │  usage_count     │       │  id (PK)         │
│  updated_at      │       │  status          │       │  problem_id (FK) │
└──────────────────┘       │  created_at      │       │  tag_id (FK)     │
                           │  updated_at      │       │  created_at      │
                           └──────────────────┘       └──────────────────┘

                              tag.parent_id ──┐
                              tag.id ◄────────┘
                              (自引用实现多级层级)
```

**关系说明：**

- `tag_category` : `tag` = 1 : N（一个分类包含多个标签）
- `tag` : `problem` = N : M（多对多，通过 `problem_tag` 中间表关联）
- `tag` : `tag` = 1 : N（自引用，parent_id 指向父标签 id，实现层级结构）

**层级约定：**

```
parent_id = 0        → L1 一级（顶级标签）
parent_id = L1.id    → L2 二级
parent_id = L2.id    → L3 三级（最深层级）
```

## 五、ID 编号规划体系

### 5.1 编号格式

```
ID 采用 AABBCCCC 格式（固定 8 位编码）：

  AA    BB    CCCC
  ──    ──    ────
  │     │     └── 序号（0001-9999，同类同层级内递增）
  │     └──────── 层级（01: L1/扁平, 02: L2, 03: L3）
  └────────────── 分类编号（01-08，对应 tag_category.id）
```

### 5.2 编号示例

| ID | 解读 |
|:---|:-----|
| `01010001` | 分类 01（难度等级），层级 01（扁平），序号 0001（入门） |
| `05010001` | 分类 05（题目类型），层级 01（L1），序号 0001（连续建模） |
| `05020001` | 分类 05（题目类型），层级 02（L2），序号 0001（机理建模） |
| `05030001` | 分类 05（题目类型），层级 03（L3），序号 0001（物理机理） |
| `06010001` | 分类 06（模型分类），层级 01（L1），序号 0001（优化模型） |
| `06030042` | 分类 06（模型分类），层级 03（L3），序号 0042（方差分析） |

### 5.3 设计优势

| 优势 | 说明 |
|------|------|
| **可读性** | 看到 ID 即可判断所属分类和层级，无需查表 |
| **调试友好** | 日志中出现 `06030042`，立刻知道是"模型分类 → L3 → 第 42 号标签" |

## 十、典型查询场景

### 10.1 查询某个分类下的所有标签（含层级）

```sql
-- 查询模型分类下的所有标签，按父子关系和排序展示
SELECT t.id, t.parent_id, t.name, t.code, t.color, t.usage_count,
       tc.name AS category_name
FROM tag t
JOIN tag_category tc ON t.category_id = tc.id
WHERE tc.code = 'model_category' AND t.status = 1
ORDER BY t.parent_id, t.sort_order;
```

### 10.2 查询某道题目的所有标签（按分类分组）

```sql
-- 查询题目关联的所有标签，按分类排序展示
SELECT tc.name AS category_name, tc.code AS category_code,
       t.id AS tag_id, t.name AS tag_name, t.color, t.parent_id
FROM problem_tag pt
JOIN tag t ON pt.tag_id = t.id
JOIN tag_category tc ON t.category_id = tc.id
WHERE pt.problem_id = #{problemId} AND t.status = 1
ORDER BY tc.sort_order, t.sort_order;
```

### 10.3 按标签组合筛选题目（多条件 AND）

```sql
-- 筛选：困难 + 连续建模 + 国赛来源的题目
SELECT DISTINCT p.*
FROM problem p
JOIN problem_tag pt1 ON p.id = pt1.problem_id
JOIN problem_tag pt2 ON p.id = pt2.problem_id
JOIN problem_tag pt3 ON p.id = pt3.problem_id
JOIN tag t1 ON pt1.tag_id = t1.id AND t1.code = 'difficulty_hard'
JOIN tag t2 ON pt2.tag_id = t2.id AND t2.code = 'ptype_continuous'
JOIN tag t3 ON pt3.tag_id = t3.id AND t3.code = 'comp_cumcm';
```

### 10.4 按标签筛选（含子标签向下包含）

```sql
-- 筛选所有"优化模型"相关的题目（包括其下所有 L2、L3 子标签关联的题目）
SELECT DISTINCT p.*
FROM problem p
JOIN problem_tag pt ON p.id = pt.problem_id
JOIN tag t ON pt.tag_id = t.id
WHERE t.id = 06010001                        -- 直接关联 L1
   OR t.parent_id = 06010001                 -- 关联 L2（parent = L1）
   OR t.parent_id IN (                       -- 关联 L3（parent = L2，而 L2.parent = L1）
       SELECT id FROM tag WHERE parent_id = 06010001
   );
```

### 10.5 热门标签排行

```sql
-- 全局热门标签 TOP 10
SELECT t.name, t.color, t.usage_count, tc.name AS category_name
FROM tag t
JOIN tag_category tc ON t.category_id = tc.id
WHERE t.status = 1 AND t.parent_id != 0  -- 排除分组标签，只统计叶子标签
ORDER BY t.usage_count DESC
LIMIT 10;
```

### 10.6 某分类下热门标签

```sql
-- 模型分类下使用最多的 L3 标签 TOP 10
SELECT t.name, t.code, t.usage_count
FROM tag t
WHERE t.category_id = 6
  AND t.status = 1
  AND t.id BETWEEN 06030001 AND 06039999  -- L3 层级
ORDER BY t.usage_count DESC
LIMIT 10;
```

### 11.3 父标签选择策略

当用户选择一个父标签时，前端需要决定是"仅选中该标签"还是"同时选中所有子标签"：

| 策略 | 适用场景 | 实现方式 |
|------|---------|---------|
| **仅选中父标签** | 精确筛选 | 前端只传 `tag_id = 06010001` |
| **级联选中所有子标签** | 宽泛筛选 | 前端传 `tag_id IN (06010001, 06020001, 06020002, 06030001, ...)` |
| **可切换模式** | 推荐方案 | 父标签旁增加"全选子标签"开关 |

**推荐方案**：默认选中父标签时级联选中所有子标签（宽泛筛选），用户可手动取消不需要的子标签进行精确筛选。

## 十二、扩展性与维护策略

### 12.1 新增标签

新增标签只需在 `tag` 表中插入新记录，无需修改表结构：

```sql
-- 新增一个 L3 模型标签
INSERT INTO `tag` (`id`, `category_id`, `parent_id`, `name`, `code`, `color`, `sort_order`)
VALUES (06030101, 6, 06020002, '和声搜索', 'model_hs', '#EF5350', 7);
```

### 12.2 新增标签分类

新增分类需要在 `tag_category` 表插入新记录，并按照 ID 编号规划体系为新分类分配 ID 区间：

```sql
-- 示例：新增"解题思路"分类（category_id = 9）
INSERT INTO `tag_category` (`id`, `name`, `code`, `icon`, `description`, `sort_order`, `is_multiple`, `is_required`)
VALUES (9, '解题思路', 'solution_approach', 'https://api.iconify.design/mdi:lightbulb.svg', '题目的解题策略与思路', 9, 1, 0);

-- 新增标签使用 09BBCCCC 编号
INSERT INTO `tag` (`id`, `category_id`, `parent_id`, `name`, `code`, `color`, `sort_order`)
VALUES (09010001, 9, 0, '建模思路A', 'approach_a', '#FF5722', 1);
```

### 12.3 新增年份

每年需要追加新的年份标签，只需插入一条记录：

```sql
INSERT INTO `tag` (`id`, `category_id`, `parent_id`, `name`, `code`, `color`, `sort_order`)
VALUES (04010013, 4, 0, '2027年', 'year_2027', '#607D8B', 13);
```

### 12.4 usage_count 维护策略

`usage_count` 冗余字段需要在应用层维护：

```java
// 新增题目-标签关联时
tagMapper.incrementUsageCount(tagId);

// 删除题目-标签关联时
tagMapper.decrementUsageCount(tagId);

// 定时任务校准（每天凌晨执行，防止计数漂移）
UPDATE tag t SET t.usage_count = (
    SELECT COUNT(*) FROM problem_tag pt WHERE pt.tag_id = t.id
);
```

### 12.5 标签禁用与删除策略

| 操作 | 方式 | 影响范围 |
|:----:|------|---------|
| **禁用标签** | `UPDATE tag SET status = 0 WHERE id = ?` | 前端不展示该标签，但已关联的题目不受影响 |
| **禁用分类** | `UPDATE tag_category SET status = 0 WHERE id = ?` | 该分类下所有标签不展示，已关联的题目不受影响 |
| **删除标签** | 不建议物理删除 | 如确需删除，需先清理 `problem_tag` 中的关联记录 |
| **合并标签** | 将旧标签的所有关联迁移到新标签，再禁用旧标签 | `UPDATE problem_tag SET tag_id = newId WHERE tag_id = oldId` |
