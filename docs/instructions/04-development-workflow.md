## 开发流程与提交规范



### 适用范围

- 日常功能开发
- 缺陷修复
- 重构优化
- 文档维护
- AI 协作开发



### 规则定义

> 【强制】：必须遵守的内容

1. 【强制】开始开发前必须先明确本次开发目标。
   说明：开发目标应能明确本次要完成的业务结果或交付结果，防止开发过程偏离需求范围。

2. 【强制】开发前必须定位当前版本进度对应的 TODO 文档。
   说明：TODO 文档用于承接当前版本计划，开发内容必须与版本计划保持一致。

3. 【强制】开发实现必须严格按照 TODO 文档中的条目执行。
   说明：不允许在一次开发中随意扩展 TODO 之外的计划外功能。

4. 【强制】一条 TODO 条目必须对应一次 git commit。
   说明：提交粒度应保持原子化，确保每次提交都有明确目标，便于代码审查、回滚与问题追踪。



### 开发执行清单

1. 明确开发目标，并写出一句可验证的完成标准。
2. 打开当前版本对应的 TODO 文档，确认本次要处理的条目。
3. 逐条实现 TODO，完成一条后进行一次独立提交。
4. 提交信息应能直接体现该 TODO 条目的业务含义。



### 与其他规范的关系

- 本文档约束开发流程与提交粒度。
- 文档格式与排版遵循 `01-document-regulations.md`。
- 版本目录与版本号管理遵循 `03-version-regulation.md`。
