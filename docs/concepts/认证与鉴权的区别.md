# 认证 vs 鉴权：区别与协作

> 日期：2026-07-26
> 相关模块：common-security

---

## 问题

在搭建 common-security 模块时，我问："认证鉴权是两件事情吗？"

## 答案

是的，认证（Authentication）和鉴权（Authorization）是两件先后发生的独立事情：

```
登录                     请求 /api/xxx
  ↓                          ↓
认证: 验证你是谁            从 Header 取 Token → 验签 → 解析 userId → 通过 ✅
  ↓                          ↓
签发 JWT Token             鉴权: 检查你能做什么 → 查 RBAC 数据 → @SaCheckRole 校验
```

### 认证（Authentication）— "你是谁"

- **目标**：确认用户身份
- **时机**：登录时执行一次，后续请求复用 Token
- **实现**：用户名+密码验证 → BCrypt 匹配 → 签发 JWT → 后续请求验签
- **失败响应**：401 Unauthorized（未登录 / Token 过期）

### 鉴权（Authorization）— "你能做什么"

- **目标**：确认用户有没有权限执行当前操作
- **时机**：每个请求都要检查
- **实现**：从 Token 取出 userId → 查角色/权限表 → 对比所需的权限
- **失败响应**：403 Forbidden（权限不足 / 角色不匹配）

### 本项目中的实现

| 阶段 | 组件 | 职责 |
|------|------|------|
| 认证-签发 | `TokenUtil.login()` → `StpUtil.login()` → JWT 生成 | 用户登录成功后签发 Token |
| 认证-验签 | `StpLogicJwtForStateless` | JWT 签名自验证，不查 Redis Session |
| 认证-黑名单 | Redis 黑名单 | 登出/踢人时将 Token 加入，解决 JWT 无法主动失效的问题 |
| 鉴权-数据源 | `StpInterfaceImpl` → `UserFeignClient` | 从 user 服务查询当前用户的角色和权限列表 |
| 鉴权-注解 | `@SaCheckRole("vip")` / `@SaCheckPermission("submission:create")` | 声明式权限控制 |
| 鉴权-异常 | `AuthExceptionHandler` | 将未登录/无权限异常转换为统一 Result |

### 面试可讲点

> "认证和鉴权是两件事。认证确认身份，鉴权控制行为。我们用 JWT 无状态签发做认证——签发时不存 Redis，纯靠签名自验证，轻量高性能。JWT 无法主动失效的问题，我们在 Redis 维护黑名单来解决，登出时把 Token 加进去。鉴权用 Sa-Token 的注解 + RBAC 五表——@SaCheckRole 一行注解就能做角色校验，权限数据通过 Feign 从 user 服务实时查，保证权限变更即时生效。"
