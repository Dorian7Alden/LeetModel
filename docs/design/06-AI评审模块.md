## 06-AI评审模块

### 模块概述

AI 评审模块是 LeetModel 平台的核心智能服务模块，基于火山引擎大模型提供专业的数学建模作品评审能力。该模块参考国赛、美赛等主流赛事的官方评审标准，针对论文、模型、代码等不同形式的作品，从建模合理性、代码准确性、论文规范性、图表呈现等多个维度进行量化评分，输出综合得分、完整评审报告及针对性优化建议。

---

### 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|----------|----------|----------|--------|
| AI-001 | 提交AI评审任务 | 将作品提交给AI进行评审，支持多种内容类型 | P0 |
| AI-002 | 获取评审状态 | 查询AI评审任务处理状态（排队中/处理中/已完成/失败） | P0 |
| AI-003 | 获取评审结果 | 获取AI评审报告及多维度评分详情 | P0 |
| AI-004 | 获取优化建议 | 获取针对性的改进建议和优化方向 | P0 |
| AI-005 | 与AI交互对话 | 就评审结果与AI进行问答，深入探讨改进方案 | P1 |
| AI-006 | 获取评审历史 | 查看历史AI评审记录列表 | P1 |
| AI-007 | 评审配额查询 | 查看剩余AI使用额度（日额度/月额度） | P1 |

### 接口设计

#### 3.1 提交AI评审任务

**接口路径**：`POST /api/v1/ai/reviews`

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| submissionId | Long | 是 | 关联的训练提交记录ID |
| reviewType | String | 是 | 评审类型：`modeling`/`code`/`paper`/`full` |
| content | String | 条件 | 评审文本内容（论文/模型描述），与fileUrls至少填一项 |
| fileUrls | List\<String\> | 条件 | 附件文件URL列表，与content至少填一项 |

**响应示例**：

```json
{
  "code": 20000,
  "msg": "评审任务提交成功",
  "data": {
    "reviewId": 1001,
    "status": "pending",
    "estimatedTime": 30
  }
}
```

#### 3.2 获取评审状态

**接口路径**：`GET /api/v1/ai/reviews/{reviewId}/status`

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| reviewId | Long | 评审任务ID |
| status | String | 状态：`pending`(排队中)/`processing`(处理中)/`completed`(已完成)/`failed`(失败) |
| progress | Integer | 处理进度百分比（0-100） |
| estimatedTime | Integer | 预计剩余时间（秒） |

**响应示例**：

```json
{
  "code": 20000,
  "msg": "查询成功",
  "data": {
    "reviewId": 1001,
    "status": "processing",
    "progress": 45,
    "estimatedTime": 15

}
```

### 评审维度设计

#### 5.1 建模手评审维度

| 维度代码 | 维度名称 | 权重 | 评分标准 |
|----------|----------|------|----------|
| modeling_logic | 建模逻辑性 | 35% | 模型假设合理性、变量定义清晰度、推导过程严谨性 |
| modeling_innovation | 建模创新性 | 25% | 方法创新度、模型改进程度、独特视角 |
| modeling_applicability | 建模适用性 | 25% | 与实际问题契合度、参数设置合理性、可操作性 |
| modeling_analysis | 结果分析 | 15% | 结果解释合理性、敏感性分析、模型验证 |

---

#### 5.2 编程手评审维度

| 维度代码 | 维度名称 | 权重 | 评分标准 |
|----------|----------|------|----------|
| code_correctness | 代码正确性 | 40% | 算法实现正确性、边界条件处理、结果准确性 |
| code_efficiency | 代码效率 | 25% | 时间复杂度、空间复杂度、算法优化程度 |
| code_readability | 代码规范性 | 20% | 命名规范、注释完整性、代码结构清晰度 |
| code_robustness | 代码健壮性 | 15% | 异常处理、输入验证、容错能力 |

---

#### 5.3 论文手评审维度

| 维度代码 | 维度名称 | 权重 | 评分标准 |
|----------|----------|------|----------|
| paper_structure | 论文结构 | 25% | 摘要完整性、章节逻辑、层次分明度 |
| paper_expression | 语言表达 | 25% | 专业术语使用、语句通顺度、表达准确性 |
| paper_format | 格式规范 | 20% | 排版规范、图表编号、参考文献格式 |
| paper_visualization | 图表呈现 | 30% | 图表清晰度、美观度、信息量 |

---

#### 5.4 完整套题评审维度

完整套题评审综合以上三个角色的评审维度，根据用户当前角色自动调整权重分配。

### 配额管理设计

#### 6.1 配额策略

| 配额类型 | 免费用户 | VIP用户 | 说明 |
|----------|----------|---------|------|
| 每日评审次数 | 5次 | 20次 | 每日0点重置 |
| 每月评审次数 | 50次 | 200次 | 每月1日0点重置 |
| 单次最大Token | 8000 | 16000 | 单次评审最大Token消耗 |
| 对话轮次限制 | 5轮/评审 | 20轮/评审 | 每次评审的对话轮次上限 |

---

#### 6.2 配额扣减规则

1. 提交评审任务时预扣配额
2. 评审失败时返还配额
3. 对话交互按实际Token消耗扣减
4. 配额不足时拒绝服务并提示用户

### 错误码定义

### 扩展规划

#### 10.1 短期规划（P1）

1. **AI对话交互**：支持就评审结果进行深入问答
2. **评审历史管理**：支持评审记录的对比分析
3. **个性化建议**：基于用户历史数据提供定制化建议

#### 10.2 中期规划（P2）

1. **多模型对比**：支持多个AI模型评审结果对比
2. **评审模板**：支持自定义评审维度和权重
3. **批量评审**：支持批量提交评审任务

#### 10.3 长期规划

1. **智能推荐**：基于评审结果推荐相关学习资源
2. **能力预测**：预测用户能力提升路径
3. **团队评审**：支持团队协作作品的联合评审
