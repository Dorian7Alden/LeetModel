# AI 评审模块 — 设计文档

> 基于 LeetModel 平台专项训练场景，对建模手、编程手、论文手三类角色的提交作品进行 **AI 智能评审**，既评审作品质量，又通过作品反映个人能力水平。

---

## 一、功能定位

```
专项训练提交 ──▶ AI 评审引擎 ──▶ 作品评分 + 能力画像
                                        │
                          ┌─────────────┼─────────────┐
                          ▼             ▼             ▼
                     多维度得分    优化建议     能力等级评定
```

一次评审产出 **两份结果**：

| 评审对象     | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| **作品评审** | 针对本次提交内容，按题目对应的评分维度逐项打分，给出优化建议 |
| **能力评审** | 通过作品表现反映该角色的综合能力水平，更新个人能力画像（雷达图） |

## 二、角色与训练体系

### 2.1 三大角色

| 角色     | 定位                   | 训练板块（示例）                                             |
| -------- | ---------------------- | ------------------------------------------------------------ |

| 💻 编程手 | 负责算法实现与求解     | 算法设计、代码实现、数据处理与可视化、结果验证               |
| ✍️ 论文手 | 负责论文撰写与呈现     | 写作思路训练、学术用词规范、内容排版、图表制作（数据图/流程图） |

## 三、评审维度设计

### 3.1 核心原则

> **评审维度不固定，随题目动态生成。**
>
> 每道题目在创建（含 AI 生成题目）时，同步生成该题专属的 **评分维度列表、各维度权重、各维度等级描述**。

### 3.2 维度结构

每个评审维度包含以下要素：

```
维度 (Dimension)
├── 维度名称          如：模型合理性、代码规范性、论述逻辑性
├── 维度权重          如：0.30（所有维度权重之和 = 1）
├── 维度满分          每个评审维度的满分固定为 100 分。
├── 评分等级描述       4 个等级的具体标准
│   ├── 🟢 优秀 (A)   得分率 ≥ 85%
│   ├── 🔵 良好 (B)   得分率 70%-84%
│   ├── 🟡 一般 (C)   得分率 50%-69%
│   └── 🔴 薄弱 (D)   得分率 < 50%
└── 评分说明          该维度的评审依据与参考标准
```

### 3.3 各角色评审维度示例

**建模手**（示例，实际随题目动态生成）：

| 维度           | 权重 | 评审要点                               |
| -------------- | ---- | -------------------------------------- |
| 问题分析与理解 | 20%  | 是否准确识别问题核心、合理界定问题边界 |
| 假设合理性     | 15%  | 假设是否充分、合理、有理论/现实依据    |
| 模型选择与构建 | 30%  | 模型是否匹配问题特征、数学表达是否严谨 |
| 数据获取与处理 | 15%  | 数据来源是否可靠、处理方法是否恰当     |
| 结果分析与验证 | 20%  | 是否有灵敏度分析、结果是否合理可解释   |

**编程手**（示例）：

| 维度           | 权重 | 评审要点                             |
| -------------- | ---- | ------------------------------------ |
| 算法设计与选择 | 25%  | 算法是否匹配问题需求、复杂度是否合理 |
| 代码质量与规范 | 20%  | 可读性、命名规范、注释、结构清晰度   |
| 数据处理能力   | 20%  | 数据清洗、特征工程、异常值处理       |
| 可视化呈现     | 15%  | 图表类型选择、美观度、信息传达效果   |
| 结果正确性     | 20%  | 运行结果是否正确、是否有验证手段     |

**论文手**（示例）：

| 维度           | 权重 | 评审要点                                     |
| -------------- | ---- | -------------------------------------------- |
| 论述逻辑与结构 | 25%  | 行文逻辑是否清晰、章节结构是否合理           |
| 学术写作规范   | 20%  | 用词准确性、表述专业度、引用规范             |
| 内容完整度     | 20%  | 各必要模块是否齐全（摘要、正文、参考文献等） |
| 图表与排版质量 | 20%  | 图表规范性、排版美观度、公式编排             |
| 摘要与总结能力 | 15%  | 摘要是否精炼准确、结论是否有力               |

## 四、评分体系

### 4.1 评分计算流程

```
                    ┌──────────────┐
                    │  提交作品     │
                    └──────┬───────┘
                           ▼
              ┌────────────────────────┐
              │  获取该题的评审维度配置    │
              │  (维度列表 + 权重 + 等级) │
              └────────────┬───────────┘
                           ▼
              ┌────────────────────────┐
              │  AI 逐维度评分           │
              │  输出: 各维度得分 + 等级  │
              └────────────┬───────────┘
                           ▼
              ┌────────────────────────┐
              │  加权总分计算            │
              │  总分 = Σ(维度得分 × 权重)│
              └────────────┬───────────┘
                           ▼
              ┌─────────────────────────┐
              │  映射奖项等级             │
              │  输出: 得分 + 百分比 + 奖项│
              └─────────────────────────┘
```

### 4.2 加权总分

$$\text{总分} = \sum_{i=1}^{n} (S_i \times W_i)$$

- $S_i$：第 $i$ 个维度的得分（0-100）
- $W_i$：第 $i$ 个维度的权重（$\sum W_i = 1$）

### 4.3 分数与奖项映射

| 分数段 | 奖项等级                          | 标识 | 含义说明                       | 带宽 | 百分比 |
| :----: | :-------------------------------- | :--: | :----------------------------- | :--: | :----: |
| 96-100 | 🏆 特等奖 Outstanding              |  O   | 接近美赛O奖水平，作品几近完美  | 5分  |  ≤1%   |
| 88-95  | 🥇 一等奖 First Prize              |  F   | 美赛M奖/国赛国一水平           | 8分  |   4%   |
| 78-87  | 🥈 二等奖 Second Prize             |  S   | 美赛H奖/国赛国二水平           | 10分 |  10%   |
| 65-77  | 🥉 三等奖 Third Prize              |  T   | 国赛省一水平，具备基本建模能力 | 13分 |  20%   |
| 48-64  | 📜 优秀奖 Honorable Mention        |  H   | 有建模思路，但完成度不足       | 17分 |  25%   |
|  0-47  | 🎖️ 成功参赛 Successful Participant |  S   | 完成了提交，仍需大量提升       | 48分 |  40%   |

### 4.4 大数据量下的分数动态调整

当平台积累足够多的评审数据后，启用**分数归一化补偿机制**：

```
原始分 ──▶ 计算该分数在全局的百分位排名 ──▶ 根据目标百分比分布进行补偿调整 ──▶ 最终分
```

- **目的**：避免 AI 评分分布偏移（如普遍偏高/偏低），使各奖项等级的实际占比趋近设计百分比
- **触发条件**：同一题目的有效提交量达到阈值（如 ≥ 100 份）
- **调整方式**：基于百分位映射 + 线性插值微调

## 五、内容真实性验证

> 提交内容须保证真实有效，防止编造数据、虚构引用等行为。

| 验证手段         | 说明                                                |
| ---------------- | --------------------------------------------------- |
| 🔍 数据来源核验   | 通过联网搜索工具验证所引用数据、文献是否真实存在    |
| 📊 数据合理性检查 | AI 检查数据的量级、趋势、分布是否符合常识与领域知识 |
| 📖 引用查实       | 验证参考文献的标题、作者、期刊、年份是否真实        |
| 🔗 公式一致性     | 检查公式推导的逻辑连贯性，变量定义是否前后一致      |

### 6.2 能力评审（映射至个人成长体系）

每次作品评审的维度得分，汇入该角色的**能力雷达图**，形成长期能力画像：

```
              问题分析 88
                 ╱╲
               ╱    ╲
    结果验证  ╱   ⬡   ╲  假设能力
      72    ╱    ╱ ╲    ╲   76
           ╱   ╱   ╲    ╲
            ╲ ╱     ╲  ╱
              ╲      ╱
     数据处理   ╲   ╱   模型构建
      68        ╲╱      81
```

- 综合多次训练记录，计算各维度的 **移动平均分**
- 能力等级：$\text{能力分} = \alpha \times \text{历史均分} + (1-\alpha) \times \text{本次得分}$，$\alpha$ 建议取 0.7

### 7.1.1 物理表（字段设计）

> 说明：以下以 MySQL 8.0 为例给出“物理表”字段设计（类型/约束/索引）。若你们使用 PostgreSQL/SQL Server，可做对应类型映射。
>
> `role_type` 建议统一使用枚举值：`modeling`（建模手）/ `programming`（编程手）/ `paper`（论文手）。
>
> `award_code` 建议使用 4.3 的一位编码：`O/F/S/T/H`。
>
> `level_code` 建议固定为 `A/B/C/D`。

### 7.2 设计要点

| 设计点               | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| **维度动态化**       | `problem_dimension` 表与题目关联，每题可定义不同数量、不同名称的评审维度。每个维度的满分固定为 100 分，因此不再需要 `max_score` 字段。 |
| **权重灵活配置**     | 权重字段存储在维度表中，支持题目级别的自定义权重             |
| **等级可扩展**       | `dimension_level` 表支持每个维度独立定义等级标准，不硬编码   |
| **评分明细留痕**     | `review_dimension_score` 逐维度记录得分与 AI 评语，完整可追溯 |
| **能力画像增量更新** | `user_ability` 表按角色+维度键记录滑动均分，每次评审后增量更新 |

## 八、AI 评审流程

```
用户提交作品
    │
    ▼
① 解析提交内容（MD / 代码 / LaTeX / 图片 → 结构化文本）
    │
    ▼
② 加载题目信息 + 该题的评审维度配置 + 各维度等级标准
    │
    ▼
③ 构建 Prompt（题目描述 + 评审维度 + 等级标准 + 提交内容）
    │
    ▼
④ 调用火山引擎大模型 API，获取结构化评审结果（JSON）
    │
    ▼
⑤ 内容真实性验证（联网搜索核验关键数据/引用）
    │
    ▼
⑥ 计算加权总分，映射奖项等级
    │
    ▼
⑦ 持久化评审结果（review_result + review_dimension_score）
    │
    ▼
⑧ 增量更新用户能力画像（user_ability）
    │
    ▼
⑨ 返回评审报告给前端展示
```
