## 临时备忘录 - 记录一些未经整理的灵感/idea

---

- md 统一规范
- 做一个项目阶段表。计划完成情况。
- 弄一个文档，分享开发、团队管理过程中遇到的问题，经验。
- 制定相应的规范说明。
- 弄一个 prompt 文档，分享使用过程中的提示词（整理文件、项目说明...）
- ddl 文档。写一个 ddl 文档。记录 commit 的内容。倒叙排列，最早的放末尾。这也是开发日志了。写 to 任务内容更加清晰一些，有目的、有规划地完成项目。示例：（有一个公共待办todo，有一个个人的todo，可以直接写个人的todo，也可以写在公共的todo，有空了就移到个人的todo上去，然后完成）
  - [ ] feat(): 新功能
  - [ ] docs(): 文档变更
  - [x] fix(): 修复 bug
  - [x] feat(): 新增功能
- git 提交规范
- 做类似的项目研究。源码，框架分析。整理可能需要用到的技术栈、工具，相关依赖。
- 写好ignore，环境配置，仓库中不要出现隐私，临时缓存。
- 尽量不要对文件夹的名字重命名，非要改名字，就单独弄一个commmit。要不然改文件夹名字记录会把文件夹下面的文件都标记为新文件，改动就会很多。
- 文件命名规范
- git 不会上传空文件、空文件夹。需要注意
- 项目中部署的时候要说明清楚，怎么部署。
- 写好注释或readme，写得让人明白，看源码能懂的，就不需要语言解释。文字没记录的，那就是垃圾，没人能看懂
- 不要频繁提交。重要的提交，需要同步细节的，发个消息及时同步
- 大量提交需要做简单的演示，讲解说明，快速同步
- MVP 的开发模式，先做一个简单的可运行的 demo版本，再逐步迭代。不要想着一次开发就完美，重复开发一个功能，迭代完善。
- 开发流程计划清楚。每个版本的目标定下来。先做核心内容，再扩展，记录 idea ，时间有限。
- 做会议记录。
- 团队管理、项目管理需要耗费时间。不轻松。好的管理方式，不管是人，代码同理，都很重要。
- 多反思。
- 注意形式主义
- 提交代码之后，要 review 。别人的代码要看懂，了解清楚到底有哪些东西。要跑一遍别人的代码，跑通。
- 项目架构设计，技术栈，数据库设计，功能定义，需求定义，项目定位想清楚，接口设计，前端设计，后端设计。交互流程想清楚。
- 接口规范。
- 同步工具。
- 先做顶层设计，再做细节实现。设计占 70% ，实现占 30% 。
- 不要急于开发各种功能。每完成一个函数，一个功能，要写测试代码，或者后面补齐测试代码。
- 做性能测试。优化。
- 项目核心技术涉及到数学建模相关的内容。要做可行性验证，算法文档。答题需要评分这种评价机制需要独立设计标准，算法（纯AI也需要量化数值）。
- AI 功能，涉及到大模型相关。AI 业务。可以搭建 agent 流。需要预定义提示词...。agent 开发。
- 怎么做项目配置比较高效。

### 团队管理

---

团队观念：
- 设计 > 编码。想清楚怎么做，远比写代码重要。**掌握**代码
- 项目的宗旨是实践，积累团队开发经验，提升能力，不是为了快速完成项目，或者其他目的。

---

加入团队时的审核：
- （想法很好，时间不够）团队成员出一些问答题，设计一个线上答题网站。
- 包括：git 工具的使用，项目的了解程度，开发规范，团队公约，基本常识等。
- 最终通过**线上一对一交流**，通过审核。

---

- 2 天内不回消息，飞机票
- 连续 3 次会议迟到、未到，飞机票

---

团队管理：
- 可以使用专业的项目管理工具，正式化开发流程，而不是随意的聊天软件
- 会议做日志记录
- 工作计时统计
- 两个仓库，一个测试仓库，一个正式仓库。正式仓库落后测试仓库 1 周，测试仓库实践了之后，再慢慢迁移，相当于**至少**开发两次。
- 先完成个人的日常 ddl ，之后再参与项目，不要因为项目耽搁了日常。

### 开发管理

---

- 启动项目时的准备工作：
  - 参考类似项目，学习前人经验
  - 先通过伪代码形式搭建代码框架，梳理代码运行机制，再实现对应的功能。比如：把所有功能都用函数列出来，然后固定输出内容，假设这个函数已经实现好了，预定义参数，梳理一遍所有模块的运行交互过程。当前架构有没有问题，xx 功能能否有效地融入项目中去。
  - 每个模块写一个 readme 说明或函数对应的功能注释写清楚，写 readme 的话，有助于 ai 了解项目的相关结构，运行机制等，生成适配项目的代码。
- 再开发时，就先把 commit 内容想清楚，完成了就 commit 。不要一次完成好几件事，然后压缩成一个 commit ，不方便 dif 。可以把列一个 todo ，每条 todo 就是下一次要 commit 的内容，然后一个一个事情做。
- 写一段时间的代码之后，要花时间反思，优化。总结经验，寻找更优解。
- 学会使用工具
