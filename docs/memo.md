### 团队管理

---

团队观念：
- 设计 > 编码。想清楚怎么做，远比写代码重要。**掌握**代码
- 项目的宗旨是实践，积累团队开发经验，提升能力，不是为了快速完成项目，或者其他目的。

---

加入团队时的审核：
- （想法很好，时间不够）团队成员出一些问答题，设计一个线上答题网站。
- 包括：git 工具的使用，项目的了解程度，开发规范，团队公约，基本常识等。
- 最终通过**线上一对一交流**，通过审核。

### 开发管理

---

- 启动项目时的准备工作：
  - 参考类似项目，学习前人经验
  - 先通过伪代码形式搭建代码框架，梳理代码运行机制，再实现对应的功能。比如：把所有功能都用函数列出来，然后固定输出内容，假设这个函数已经实现好了，预定义参数，梳理一遍所有模块的运行交互过程。当前架构有没有问题，xx 功能能否有效地融入项目中去。
  - 每个模块写一个 readme 说明或函数对应的功能注释写清楚，写 readme 的话，有助于 ai 了解项目的相关结构，运行机制等，生成适配项目的代码。
- 再开发时，就先把 commit 内容想清楚，完成了就 commit 。不要一次完成好几件事，然后压缩成一个 commit ，不方便 dif 。可以把列一个 todo ，每条 todo 就是下一次要 commit 的内容，然后一个一个事情做。
- 写一段时间的代码之后，要花时间反思，优化。总结经验，寻找更优解。
- 学会使用工具
