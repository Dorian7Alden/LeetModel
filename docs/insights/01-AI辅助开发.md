# 01 AI 辅助开发

## 1.1 AI IDE 使用技巧

### Plan 模式优于直接 Agent

使用 Claude Code 的 plan 模式比直接 agent 模式更好。plan 模式下有提问对话环节，可以发现一些在直接执行中会被忽略的未知问题。

### Plan 模式的已知缺陷

- **模式切换 Bug**：Claude Code 从 plan 模式切回 agent 模式时，几乎每次都会显示仍为 plan 模式，无法立即执行。
- **重复 Plan 拦截**：进入 plan 模式后，如果未执行或退出，后续不能再用 `/plan` 开头发起指令。Claude Code 底层没有对重复 plan 模式做兜底检测——一旦进入 plan 模式，对话可以长交流，但不允许再次以 `/plan` 开头，会被直接拦截。
- **长 Plan 的 Review 痛点**：Claude Code 的 plan 输出可能非常长，每次需要翻到最上面从上往下 review，翻页操作非常麻烦，尤其是 plan 需要多次调整时。

### 环境变量缓存

修改环境变量后，需要重启 IDE 重新加载环境变量缓存，否则读取到的仍是旧值。

### IDE 缓存不一致

IDE 可能因为缓存不一致导致找不到包。此外，IDE 在 application 配置中推荐键名时可能给出错误建议——例如原本是小写的键，推荐改成大写，改了就出错，不应盲目接受。

在对 AI 的相关配置时出现了，改了 key 的名字就报错了。

## 1.2 AI 协作策略

### 单任务专注，避免并行

用 AI 开发时不要同时开多个并行任务。并行完全没必要，不如专注一个任务，多思考、多 review 代码，这样既不会大脑过载导致疲惫，对项目的理解也更加清晰。

### 先调研，后写代码

AI 开发项目的第一步不是直接写代码，而是调研技术。把技术方案搞清楚再动手。

### 前后端投入平衡（Vibe Coding 教训）

大量 Vibe Coding 用于调前端，导致后端代码很少 review，接口常常报错。根本原因是：上下文给得不够，架构没有描述清楚，职责没有分配清楚，设计没有描述清楚。AI 需要足够的上下文才能产出可靠的后端代码。

### AI 会删除注释

AI 在自动修改代码时可能把已有注释一并删掉，review 时需要留意。

### Codex 的行为特征

Codex 开发时默认行为是：没要求做的就不做，写代码时不写注释，写了注释也不写参数类型。需要显式指令才能得到完整输出。

## 1.3 辅助工具与技巧

### 用在线AI工具生成测试数据

可以使用豆包来生成数据库测试数据，减少 API 的 token 费用。豆包支持选择本地文件夹作为仓库，方便读取项目相关信息。弊端：代码会公开。

### DeepSeek V4 文件缓存误会

**场景**：不想用 Tailwind CSS，认为 AI 无法理解其原子类样式效果，调试困难。

**现象**：DeepSeek V4 始终不识别代码中已引入的 Tailwind（含 CDN 链接），换会话也判定为"未使用 Tailwind"。

**根因**：本地打开的是旧文件缓存，未加载 AI 修改后的最新代码。手动检索 class 时基于缓存文件未命中，误判为 AI 识别问题。

![DeepSeek V4 文件缓存误会截图](https://gitee.com/Seniorsy/pic-go/raw/master/typora/image-20260505002846459.png)

**教训**：手动介入调整代码时，多看看文件的编辑状态和保存状态。未保存说明是缓存文件，AI 修改的是原文件，缓存内容落后导致看到的与真实存储不一致。
