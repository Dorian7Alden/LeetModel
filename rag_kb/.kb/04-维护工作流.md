# 04 — 维护工作流

> **核心不变式：README 与文件系统保持同步。**
> 初筛依赖 README + frontmatter，任何内容变更必须同步索引，否则检索出现盲区。

## 1. 新增笔记
1. 归位：按主题找文件夹；跨主题 → 放主文件夹，`tags` 补其余维度。
2. 写作：按 `02-笔记规范.md`（frontmatter 必填、结论先行、内容抽象度）；整理任务（素材→笔记）按 `.kb/整理/整理工作流.md` 完整流程执行，简单补充不走。
3. 收尾：在所在文件夹 README 文档清单**追加一行**（名 + 一句话说明）。

## 2. 修改笔记
- 内容变更 → 必须同步更新 `summary`（摘要过期 = 初筛误判，最重要的同步点）。
- 主题归位变化 → 移动文件 + 更新新旧两个文件夹的 README。

## 3. 删除笔记 / 文件夹
- 从 README 清单移除；删文件夹先清空内容；父 README 同步。

## 4. 新建文件夹
- 建 `README.md`（主题声明 + 子文件夹 + 文档清单三节齐全，见 `01-知识库组成机制.md` §5）。
- 父文件夹 README 加一行。

## 5. 建立嵌套 `.kb/`（子库）
- 触发条件：子目录的规范偏离父库。
- 只需放**差异文档**：如子库只放 `03-检索工作流.md`，则检索按子库、其余规范继承父库。
- 子库总纲注明「继承父库：<父库路径>」。

## 6. 一致性检查（可选）
- 会话结束前或定期：对照文件系统与 README 清单找差异——
  - 新增未登记、已删未清理、summary 与正文不符；
  - 找到后按上述 1–3 条修复。

## 7. 结构调整（同态调整原则）
- 结构维护是**小幅、低频、局部**的调整，保持整体形态（同态）；避免大规模重构（全库重分类、批量重命名、推翻既有层级）——已熟悉的结构是宝贵的记忆锚点，大改会让用户重新适应。
- 触发调整的信号（仅在需要时动，不主动折腾）：某文件夹笔记数远超节点宽度（如 >20 篇且可自然分组）、树高超过 4 层、命名与内容明显不符。
- 调整手段：拆分过宽的节点（按子主题或序号分段）、合并过窄的相邻文件夹（只有几篇且主题相近）、重命名不贴切的文件夹——每次只动一个点，调整后同步父 README。
