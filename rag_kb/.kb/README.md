# 知识库总纲

> 此目录（含 `.kb/` 的层级）是一个定义好的知识库。
> 检索与维护**必须**按下述工作流执行，不得绕过元信息层直接读正文。

## 这个知识库是什么

- 内容通用、不绑定领域；可嵌套，无确定全局根，每一层结构相同。
- 内容维护原则：**原子笔记 + 文件夹标签**。
- `.kb/03-检索工作流.md` 定义人工或 Agent 的目录导航，也作为未来 RAG V2 设计输入。
- 正式在线 RAG V1 使用 Embedding 与 Elasticsearch，不执行这里的纯 AI 选文流程。

## 文档地图（按需读取）

| 文档 | 用途 | 读取时机 |
|------|------|---------|
| `01-知识库组成机制.md` | 原子笔记定义、文件夹组织、README 规范、命名规范、分类示例 | 建库/建文件夹/写笔记前 |
| `02-笔记规范.md` | 原子笔记 frontmatter 字段、写作规则 | 写/改笔记时 |
| `03-检索工作流.md` | 筛选 Agent 的分步执行指令 | 每次检索时（单份读取） |
| `04-维护工作流.md` | 新增/修改/删除、嵌套库建立、一致性检查 | 维护时 |
| `整理/`（目录） | 整理规范：工作流、风格库、格式要求、关键词参考 | 整理素材/重构文档时 |

## 检索入口

要执行检索 → 只读 `03-检索工作流.md`，按其中指令执行。

## 嵌套知识库继承规则

子目录若建有自己的 `.kb/`，该子目录即独立子库：子库提供的文档优先；
子库未提供的文档继承父库（父库路径：父库 `.kb/` 目录相对当前 `.kb/` 的路径，直接嵌套时为 `../..`；嵌套更深时按实际层级计算）。
