# 01 — 知识库组成机制

> 本文件说明**知识库的组成机制**：知识库由「原子笔记 + 文件夹标签」组成——
> 原子笔记是组成单元，文件夹标签是组织方式。先定义原子笔记，再规定文件夹如何分层、分类、命名，最后用示例走通全过程。

## 1. 原子笔记（组成单元）

### 1.1 原子笔记是什么

**定义**：原子笔记是从一篇完整文章中拆解下来的**纯粹知识块**。一篇完整文档拆解后：
- 原文的文章结构 → 目录层级（文件夹标签）；
- 原文的每个段落板块 → 若干篇笔记（**一知识块一文件**）。

同一文件夹下的笔记原本可连贯成一篇完整文章；拆散之后，靠"标签结构 + 文档标题"就能知道知识库的大致内容。

### 1.2 文档形态

| 维度 | 规则 |
|------|------|
| 组成 | 一个文档标题 + 正文描述（标题即知识块名，一般等于文件名） |
| 小节标题 | 一般没有——不出现二级/三级标题分块说明（不像一个小文档），正文平铺 |
| 自足性 | 单篇可独立理解，不依赖同文件夹其他笔记 |
| 例外 | 内容确实需要导航的长文，经格式要求显式覆盖后可分节（见 `.kb/整理/格式要求模板.md`） |

平铺指**结构**：无 H2/H3 分块；第一段仍应开门见山说清核心结论（与 `02-笔记规范.md` §2「结论先行」一致）。

### 1.3 分类：文件夹标签

分类完全靠文件夹标签——同一级文件夹下的笔记即同一类内容；**文件夹 + 文件名 ≈ 全局摘要**：只看目录标签与文件名即可了解知识库内容，无需打开文档。frontmatter 的 `tags` 只补文件夹之外的跨主题维度，不承担结构分类。

### 1.4 链接（仅弱化，不禁止）

- 允许 `[[笔记名]]` 或相对路径引用，但不鼓励、不建立复杂引用关系；
- 正文不得依赖链接才能读懂（链接只是补充线索）；
- 链接必须指向真实存在的文件，**不得悬空**。

### 1.5 适用范围与追溯

本定义适用于知识库笔记（内容性文档）；规范文档、README、工作流类文档不属于笔记，不受形态限制。定义自发布起生效，**既有笔记不追溯修改**，后续维护时按本形态处理。

## 2. 文件夹标签（组织方式）

### 2.1 文件夹组织规则

- 主题文件夹：语义明确的短命名（按项目名、领域、专题等名词划分，如 `database`、`数学建模`、`写作`），不编号；根目录下文件夹数量不受限制。
- **标签粗粒度、层级浅**：文件夹（标签）保持概括性，不随内容细化而层层分裂；具体性放在笔记标题上（笔记名具体直述，如 `B+树节点分裂.md`）——原子笔记的「具体」体现在文档层而非文件夹层。同级文件夹下的笔记即同一类内容，原可连贯成一篇完整文章。
- **结构平衡（平衡二叉树原则）**：
  - 树高：一般 ≤3 层，最多不超过 4 层；
  - 节点宽度：一般每个文件夹 5–15 篇笔记；
  - 特殊情况弹性处理：某系列文档极多（如 1–1000 篇）时，可按序号分段建子文件夹（如 `001-100/`、`101-200/`）管理；只有几篇文档的文件夹也允许存在，不强制合并。
- **不混合原则**：一个文件夹下面，要么全是文件夹、要么全是文档，不混合（`README.md` 除外）——中间层（纯文件夹）只放子文件夹，叶子层（纯文档）只放笔记；避免同一层同时存在两种形态，检索 Agent 无需切换处理。
- 每个**主题文件夹**必配 `README.md`。
- 嵌套 `.kb/`：子目录规范偏离父库时建立，只放差异文档。

**内容形态提示（非文件夹分类）**：method（方法论）类内容倾向抽象通用、scenario（场景）类内容倾向具体可复现——这仅是写作层面的提示（见 `02-笔记规范.md` §2），不作为文件夹分类依据；同一文件夹下两种内容自然共存。

### 2.2 分类决策顺序

先定**领域**（如 `数学建模`）→ 再定**资源类型**（如 `优秀范文`、`教程`、`经验`）→ 结合**实际情况与经验**细分（如 赛事、年份、题号）→ 最后按**条目独立性**分条目文件夹（如 论文标题）。细分依据由实际情况决定：已知该类型条目不多、或只会收集少量（如只收近几届国赛范文），就不为年份/题号单独分层，直接罗列即可。

## 3. 分层原则（扁平化优先）

> 知识库组织的第一范式：**层级越少越好**。任何「要不要加一层」的决策，按下述优先级考虑：

1. **能罗列就不分层**：条目 ≤15 篇时直接放在当前文件夹罗列，不新建目录——直接罗列完全足够时，即不可再分。
2. **能浅层扩展就不加深**：顶层文件夹标签少时，优先让顶层目录变多——用变量前缀组合标签（如 `2024国赛/`、`2025国赛/`），把多个标签压在同一层，而不是再嵌一层。
3. **不得已才细分**：仅当条目确实过多（预计 >15 篇、且可自然分组）时，才按实际维度（年份、题号、子主题等）分类建文件夹；分类时变量从前缀/文件名移入文件夹名（`2024-xxx.md` → `2024/xxx.md`）。

判断顺序：**罗列 → 浅层扩展 → 深层细分**，永远先试浅的。与 §2.1 结构平衡（树高 ≤3 层、节点 5–15 篇）配套：平衡是上限约束，本原则是决策过程。

## 4. 分类示例：优秀论文拆解

假设有一篇 2025 年国赛优秀论文，拆成原子笔记融入知识库（本示例演示 §3 分层原则的运用）：

```
数学建模/                                    ← 领域
└── 优秀范文/                                ← 资源类型
    └── 国赛/                                ← 结合实际细分（赛事）
        └── 2025年国赛B题-景区游客路径优化/    ← 独立条目（论文标题）
            ├── README.md
            ├── 01-摘要.md
            ├── 02-问题重述.md
            ├── 03-问题分析.md
            ├── 04-假设.md
            ├── 05-符号表.md
            ├── 06-模型一的建立与求解.md
            ├── 07-模型二的建立与求解.md
            ├── 08-模型的评价.md
            └── 09-附录.md
```

- 先领域、再资源类型、再结合实际细分：数学建模比赛赛事多，优秀论文按赛事分有必要，且后续还会收其他优秀论文。
- 论文结构（摘要 → 问题重述 → … → 附录）有必然先后顺序，章节文档编号 `01-09`。
- 多个模型的建立与求解**不再分子目录**，直接罗列 `xxx模型的建立与求解.md`——该层已足够具体，罗列即可承受。
- 年份、题号（ABCD）也可细分，但预估计量少（只收少量优秀论文），暂不分类、直接罗列。条目增多后再细分：如"国赛"下优秀论文过多，先按年份分文件夹（`国赛/2024/`、`国赛/2025/`…），文档命名去掉年份；或赛事标签少时，直接在"优秀范文"下组合前缀（`2024国赛/`），再放具体论文。

## 5. README.md 内容模板（必循）

```markdown
# <文件夹名>
> 一句话：这个文件夹装什么（主题声明）
> 本文件夹适合：<任务类型描述，帮 AI 匹配任务>
> 默认风格：<风格名，可省略>（整理新文档时套用，见 .kb/整理/风格/）

## 子文件夹

| 子文件夹 | 说明 |
|---------|------|
| <子文件夹名> | <一句话主题，何时选它> |

## 文档

| 文档 | 说明 |
|------|------|
| <笔记名>.md | <一句话说明：它讲什么、何时相关> |
```

模板规则：
- **结构描述一律用表格**（「子文件夹」「文档」两节均用 Markdown 表格）：紧凑对齐，便于 AI 与人类快速解析结构、逐行核对清单；文档列写文件名（含 `.md`），说明列写一句话。
- 无内容的节用一行「（无）」占位，保持三节齐全。
- 文档清单按相关性组织（最重要的在前），新笔记追加在末尾。
- 目的：AI 读完一份 README 即可决定「进哪、不进哪」，全程不需要打开正文。
- 默认风格声明为可选：未声明时整理任务由用户选择，仍无选择则取兜底风格（见 `.kb/整理/整理工作流.md`）。

## 6. 命名规范

- 文件夹：短语义词，中英文皆可，同层内风格一致。
- **前缀/变量参数**：顶层标签少时，用变量前缀在浅层组合标签，让顶层目录变多而非加深层级（如 `2024国赛/`、`2025国赛/`）；条目增多、变量成组后，把变量移入文件夹名（`2024-xxx.md` → `2024/xxx.md`）。
- 笔记：概念名直述（如 `B+树节点分裂.md`），默认不带编号——顺序与关联由 README 索引表达，笔记名只负责「是什么」。
- **顺序编号**：文档之间确有必然先后顺序时，编号表达顺序，从 `01` 起（如 `01-摘要.md`、`02-问题重述.md`）；并列内容不编号，直接罗列。

## 7. 嵌套知识库规则

- 子目录规范偏离父库时，在子目录建 `.kb/`，只放差异文档。
- 子库 `README.md` 总纲须注明「继承父库：<父库路径>」。

## 8. 与非知识内容的共存

- 无 `.kb/` 的目录只是普通内容，不参与检索。
- 知识库根目录下允许存在与知识库无关的文件。
