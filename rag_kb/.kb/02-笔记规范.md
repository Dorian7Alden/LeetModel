# 02 — 笔记规范

原子笔记定义见 `01-知识库组成机制.md` §1；本文件规定其 frontmatter 字段与写作细节。

## 1. frontmatter 字段定义（YAML，位于笔记文件头部）

| 字段 | 必填 | 作用 |
|------|------|------|
| `title` | 可选 | 缺省取文件名；文件名不宜太长时用此字段写完整标题 |
| `tags` | 必填 | 标签数组，补文件夹之外的维度（跨主题命中） |
| `summary` | 必填 | 一句话摘要——筛选 Agent 的核心信号 |
| `type` | 可选 | `method`（方法论，抽象通用）/ `scenario`（场景，具体可复现）：可选的内容形态声明，帮助 AI 理解内容性质 |
| `status` | 可选 | `draft` / `final`，草稿笔记可被筛选排除 |
| `aliases` | 可选 | 别名数组，帮助 AI 匹配同义表达 |

示例：
```yaml
---
tags: [数据库, 并发控制]
summary: 快照隔离下 MVCC 版本链的可见性判定规则：行版本可见性 = 创建事务已提交 且 未超过快照边界。
type: method
---
```

## 2. 正文写作规范
1. **结论先行**：第一段直接说清核心结论/要点——人眼和 AI 扫一眼即可确认相关性。
2. **一知识块一文件**：按 `01-知识库组成机制.md` §1 拆解为知识块；低耦合高内聚，可独立理解，不依赖同文件夹其他笔记。
3. **内容抽象度（写作指导，非文件夹分类）**：
   - 方法论类（method）：抽象通用，给适用条件，不绑具体场景。
   - 场景类（scenario）：具体到可复现（上下文、步骤、细节），不强行泛化。
   - 同一文件夹下两种内容自然共存，不设类型子层。
4. **不写元废话**：不写「今天学了……」、不重复 README 已声明的内容。
5. 链接可选：`[[笔记名]]` 或相对路径引用其他笔记，按 `01-知识库组成机制.md` §1.4 执行（不鼓励、正文不得依赖链接、不得悬空）。
