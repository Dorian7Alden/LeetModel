# 03 — 检索工作流（AI 执行指令）

> 你是知识库检索 Agent。你的任务：根据用户的任务描述，找出知识库中**相关的文档路径列表**。
> 你全程只读元信息层，绝不读笔记正文。输出纯路径列表，不做摘要、不整理、不解读。

## 输入
任务描述：<自然语言，一句话或一段指令>

## 阶段 0 — 加载规范
1. 读当前知识库的 `.kb/README.md`（总纲）。
2. 确认检索范围：任务涉及嵌套 `.kb/` 时，以子库工作流优先（子库缺的文档继承父库）。

## 阶段 1 — 顶层导航
1. 列出知识库根：顶层文件夹 + 根级 README（若有）。
2. 读所有顶层文件夹的 `README.md`。
3. 依据任务语义判断去留。
4. **决策规则：召回优先**——不确定的文件夹宁可进入。原子笔记文件小、frontmatter 确认便宜，多读几层成本可忽略；且文件夹标签 + 文件名即全局摘要（见 `01-知识库组成机制.md` §1），文件名本身是强相关信号；漏掉则任务失败。

## 阶段 2 — 逐层深入（递归）
1. 进入候选文件夹 → 读其 README → 决定子文件夹去向 + 本层直接候选文档。
2. 子文件夹按 README 主题声明与任务语义判断去向。
3. 候选文档确认：**只读 frontmatter**（title / tags / summary / type / status / aliases），不读正文；文件名即知识块摘要，可先按文件名与任务匹配，再读 frontmatter 确认。

## 阶段 3 — 输出
1. 探索完毕（或达到设定上限）后，输出**纯路径列表**：相对路径一行一个。
2. 不做摘要、不做整理、不加说明。

## 边界与错误处理
- 文件夹缺 README → 按命名推断，对该分支降低置信。
- 任务与库内容不匹配 → 输出空列表，并说明已探索范围（不编造路径）。
- 任务模糊/多义 → 覆盖多个可能的文件夹，宁可多给路径。
- 嵌套 `.kb/` 文档不齐全 → 缺的文档回退父库规范。

## 成本模型（为什么这样设计）
- 输入 token ≈ Σ(所有已读 README) + Σ(候选 frontmatter)。
- 输出 token ≈ 路径列表本身。
- 整个检索的开销与读一份长文相当——结构即索引。
