# 踩坑经验合集

## 核心结论

数模竞赛的失误高度重复——**几乎每届都有队伍栽在同样的坑里**：没留足写作时间、模型不检验、选题随大流、数据结果造假、最后一天熬夜改摘要、忘记提交支撑材料。把这些坑提前列成清单，赛前过一遍、赛中贴桌面，能避开 80% 的常见失误。**最大的坑是"计划外的坑"：永远给意外留 2–3 小时缓冲**。

## 赛前坑

| 坑 | 后果 | 避坑要点 |
|----|------|---------|
| 组队"临时凑" | 三人能力重叠（全建模/全编程）、互不信任 | 提前 1–2 月组队：建模+编程+写作角色互补，最好合作过（见 [[时间管理与团队分工]]） |
| 工具没备齐 | 赛中装环境/找软件浪费数小时 | 赛前一周装好 Python/Matlab/Lingo/LaTeX 全套并跑通模板（见 [[工具推荐-编程与算法]]） |
| 模板未准备 | 写作环节手忙脚乱、排版烂 | 备好 LaTeX/Word 论文模板、图表配色、常用代码段（见 [[参赛指南-流程与写作]]） |
| 不了解规则 | 组队/提交/页数违规 | 通读当年参赛规则（国赛 2026 规则要点见 [[国赛CUMCM详解]]；格式红线见 [[论文格式规范-官方2023修订稿]]） |
| 零热身 | 第一次实战就是正赛，节奏全乱 | 至少完整模拟一次 72h（用往年题跑一遍全流程） |

## 赛中坑

| 坑 | 后果 | 避坑要点 |
|----|------|---------|
| **选题过慢/反复换题** | 前 8 小时空转，后面赶工 | 发题后 2–3 小时内三人各读一遍全部题 → 讨论定题，**定了就不换** |
| 低估写作时间 | 模型做完了论文写不完 | 预留最后 **8–10 小时纯写作**；写作与建模同步推进（建模的边写模型节） |
| 模型不检验 | 官方讲评反复点名的最大失分点 | 每问求解后立刻做检验：回代/残差/灵敏度（见 [[第二次评讲B题-笔记]]） |
| 数据问题 | 缺失值直接删、异常值不处理 | 数据清洗写进论文：缺失填充方法、异常处理理由（见 [[数据挖掘与统计类题型特征]]） |
| 结果"美化"过度 | 人为调结果与代码不符，查出来取消资格 | 结果必须真实可复现；**宁可难看要真实** |
| 熬夜硬扛 | 最后一天全员崩溃，错误率飙升 | 轮班制：保证每人每天 6 小时睡眠，写作阶段两人清醒即可 |
| 讨论题内容 | 竞赛纪律红线（贴吧/QQ/群聊/社交平台） | 竞赛期间不碰任何数模群聊与平台（国赛明令，见 [[国赛CUMCM详解]] 纪律部分） |
| 忽视小问 | 某一问草草带过，完整性崩盘 | 每问必须"建模+求解+可视化+检验"闭环（见 [[A_B题备赛要点]]） |

## 提交与赛后坑

| 坑 | 后果 | 避坑要点 |
|----|------|---------|
| 提交材料不全 | 直接失去评奖资格 | 用官方清单核对：论文（PDF/Word）、支撑材料（RAR/ZIP）、MD5、承诺书（见 [[提交规范与检查清单]]） |
| 身份信息泄露 | 取消资格 | 逐页检查页眉页脚、图片元数据，只留队号/控制号 |
| 查重超标 | 取消资格（红线约 20–25%） | 引用必标注、模板句子改写、大段照抄杜绝（见 [[改卷注意点-2024讲评]]） |
| 不复盘 | 同样的坑下次再踩 | 赛后两周内写复盘：时间线、决策点、改进项，进个人知识库 |
| 忽视摘要 | 摘要最后 1 小时赶写，质量崩 | 摘要从第一天就起草，最后按五要素精修（见 [[评阅标准启示-华数杯]]） |

## 三条铁律（最痛的教训）

1. **模型检验不可省**——省检验 = 自动告别高奖级。
2. **论文是唯一交付物**——模型再漂亮，论文表达不清 = 白做。
3. **真实可复现 > 好看**——任何进论文的数字都能重跑出来，这是底线。
