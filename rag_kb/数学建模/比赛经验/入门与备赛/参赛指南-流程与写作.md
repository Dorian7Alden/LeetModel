# 比赛流程

> **写论文** > 求解结果。即使结果没求出来也无关紧要，说明清楚就好了。



## 准备工作

- 承诺书+签名
- 论文模板熟悉（latex/word）
- 比赛要求
- 队伍号
- 提交地址
- 文件压缩包提前准备好



## 正式比赛

1. 前期准备阶段

   - 首要步骤：研读论文**提交要求**，明确核心目标与规范

   - 基础工作：完成论文中非解题核心的基础内容（如问题重述等）

   - 视觉规划：构思图标、图标等视觉元素，**规划绘图**内容，为后续可视化代码实现奠基（可利用等待公开思路的时间推进进度）

   - 知识储备：根据题目关键词（如优化模型、特定算法等）**查询资料**，熟悉解题步骤与流程

2. 核心创作阶段
   - 论文撰写：先**列出待解决的问题、难点**，以此为导向进行**建模、公式**推导及相关**解释**

3. 实现与分析阶段

   - **代码编写**：依据论文中的模型内容，按代码流程完成编写，求解得出结果

     - 以**多态**的思想，先写好main函数，再实现函数方法。一般不动main函数，除非建模思路有问题

     - 举例：

     - ```python
       def main():
       	file_path = ""
       	data = read_exsl(...)
       	variables = create_variables(...)
       	constrains = create_constrains(...)
       	target = create_target(...)
       	ans = solve(...)
       	save_ans(...) // a+ 模式
       	print_ans(...)
           
       if __name__ == "__main__":
           main()
       ```

   - 可视化分析：对结果进行可视化呈现与分析

   - 模型评估：**分析模型**，灵敏度分析、鲁棒性分析等等

4. 收尾阶段

   - **论文完善**：对全文进行检查、修改与完善








# 代码注意事项

1. 先写main函数，其中用到的一切方法都用函数表示，不实现细节。main函数写好了就不能再改了。只改方法函数的实现细节。多态思想。
2. 再一个函数一个函数的实现。
3. 可视化代码与求解代码分开。先求解，再单独实现画图。
4. 记得记录好每次运行的结果，保证代码至少有一个解，尽管不是理想解。
5. 再可视化分析，求解答案是否符合预期。（趋势，大小关系，转折点等等）

import json


def save_ans(data: dict, is_good_ans: bool = False) -> None:
    """如果文件为空的情况未处理，直接删除文件重来。答案的有效性手动调"""
    import os
    data["is_good_ans"] = is_good_ans
    content = {}
    if not os.path.exists("ans.json"):
        with open("ans.json", mode="w", encoding="utf-8") as w:
            w.write(json.dumps({"cnt": 1, "ans": [data]}))
    else:
        with open('ans.json', mode="r", encoding='utf-8') as r:
            content = json.loads(r.read())
        content["cnt"] += 1
        content["ans"].append(data)
        with open('ans.json', mode="w+", encoding='utf-8') as w:
            json.dump(content, w, ensure_ascii=False, indent=2)
    good_ans_cnt = len([i for i in content["ans"] if i["is_good_ans"]])
    print(f"保存结果完成\n"
          f"现在一共有{content['cnt']}个历史结果\n"
          f"现在一共有{good_ans_cnt}个有效结果")
```

def get_folder_files(folder):
    import os
    from collections import defaultdict

    icon_map = defaultdict(
        lambda: "",
        {
            "py": r"\faFileCodeO",
            "png": r"\faFileImageO",
            "jpg": r"\faFileImageO",
            "jpeg": r"\faFileImageO",
            "svg": r"\faFileImageO",
            "webp": r"\faFileImageO",
            "xlsx": r"\faFileExcelO",
            "pdf": r"\faFilePdfO",
        }
    )
    ret = [
        f"{icon_map[file_ext]} ~~ {relative_path.replace(os.sep, '/')} \t & \t \\\\"
        for root, _, files in os.walk(folder)
        for file in files
        if (relative_path := os.path.relpath(os.path.join(root, file), folder))
        and (file_ext := relative_path.split(".")[-1]) in icon_map
    ]
    print()
    for i in ret:
        print(i)


```

## 画图的原则

- 流程图
  - 颜色用 1-2 种主色（如浅蓝底色 + 深蓝边框）
- 原理示意图（针对抽象概念）

- 变量关系图（辅助理解模型结构）

  

- 所有图表使用相同的配色方案（建议 3-4 种主色调，避免高饱和色；优先用蓝、灰、黑等中性色，辅助色区分组别）；
- 趋势分析用折线图（加误差线体现可靠性）；
- 组间对比用柱状图（并列或堆叠，避免 3 组以上堆叠）；
- 相关性分析用散点图（加拟合线和 R² 值）；
- 矩阵数据用热力图（用颜色梯度体现数值大小，标注具体数值）。

### 最优解

- 篇幅：不超过1页
- 内容组成：
  - 问题背景：大背景，为了实现xxx目标。发生问题的对象。怎么遇到问题的。遇到了什么问题（矛盾点）。这个问题有什么难点（特点，周期性？规律性？复杂性？）。需要做什么来解决（问题本质，xxx的优化，xxx策略）。（简单概括即可）
  - 已知条件：假设前提（题目给的）。特点（有红绿灯，路况特征，已知趋势）。已知数据。
  - 问题要求：（需要根据、结合...，做...，分析误差，预测结果...）





## 问题分析



### 分析

- 结构方面
  - 单个段落的结构：遵循 **“问题目标→关键难点→解决步骤→方法 / 模型预告”** 的递进结构
    - 先明确 “问题要求我做什么”；
    - 再拆解 “解决过程的核心难点”；
    - 最后说明 “将用什么方法 / 模型解决”，为后续建模做铺垫。
  - 多个段落的联系：若赛题包含多个子问题，会在分析中体现**递进 / 扩展关系**（如 “问题二是问题一的反向优化问题”，“问题三在问题二基础上增加变量维度”）

- 内容方面

  - 给出难点：针对每个问题，提炼**1-2 个核心技术难点**（如 “多变量优化的维度爆炸”，“非线性效率的计算”），并初步说明解决思路（如 “分区域遍历降低维度”，“离散化光线轨迹建模”），体现思考深度。 

  - 预告模型： **预告后续建模的算法 / 模型**（如 “遗传算法”“贪心算法”“线性回归模型”），并简要说明 “为何选此方法”（如 “由于传统遍历效率低，而遗传算法全局搜索能力强...”）

  - 简化说明：若建模需对复杂条件简化，会在分析中**明确说明简化依据**（如 “次要因素对结果影响 < 5%，故忽略”）
  - 专业术语：结合赛题背景，**准确使用领域专业术语**（如 “PCU标准车当量数”，“重叠率”，“出栏数”）

# 规范

- 字符类型规范：

  - 中文字符：汉字，标点符号，公式里面的\text{}部分
  - 英文字符：公式，变量，单位

- 行内规范：

  - 公式（主要），英文字符等在首位添加空格隔开。

  - 中文字符两个字节，英文字符一个字节，空格补全。

  - 防止编辑器自动渲染公式源码，见下面示例：
