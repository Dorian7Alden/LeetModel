# 建模经验：问题分析套路

## 核心结论

破题决定赛果的 70%：**建模的功夫在建模之前**——把题读透（每句话都是约束或数据来源）、把问题转译成数学任务（判断题型与模型族）、把思路拆成"主干模型 + 每问分支"再动手。库内核心框架 [[解题思路与论文写作模板]] 的"三问"：**是什么（问题的数学本质）、为什么（为什么这样建模）、怎么做（怎么求解与验证）**——发题后先用 1 小时把这三问写下来，再动手写代码。

## 读题三步（发题后 30–60 分钟）

1. **通读**：三人各读全部题目（不分工分题），边读边标注：已知条件、要求的问题、数据说明、隐含信息。
2. **转译**：把每问翻译成数学任务——"求最优安排"→ 优化（变量/目标/约束）；"预测未来"→ 时序/回归；"评价方案"→ 评价模型；标出题型（见 [[题型分类总览]]）。
3. **定主干**：确定"一个主干模型 + 每问的扩展"，画出问题-模型对应图（写进论文的问题分析节）。主干模型要能覆盖最多小问，后续问在此上加约束/加数据。

## 六大建模套路（按题目类型选用）

| 套路 | 适用 | 要点 |
|------|------|------|
| 机理推导 | 物理/工程规律题（A 题） | 从定律/守恒出发推方程，参数实测标定（见 [[机理分析类题型特征]]） |
| 数据驱动 | 大表数据题（C 题） | EDA → 特征工程 → 模型 → 交叉验证（见 [[数据挖掘与统计类题型特征]]） |
| 优化求解 | 最省/最优/调度题（B 题常含） | 三要素建模，LP/ILP/启发式（见 [[优化类题型特征]]） |
| 仿真模拟 | 随机/复杂过程 | 蒙特卡洛、元胞自动机、排队论（见 [[常用模型速查-统计与机理类]]） |
| 评价比较 | 选优/评级 | 指标体系 + 赋权 + TOPSIS（见 [[评价类题型特征]]） |
| 多模型集成 | 复杂题目 | 分模块：预测+优化、机理+数据校准；**模型间接口定义清楚** |

**组合策略**：先确定主干套路（覆盖 60% 问题），再为特殊小问加辅助模型（插值、检验、仿真）。不要一题堆 5 个并列模型——评审反感"模型超市"（见 [[论文写作注意事项-培训记录]]）。

## 建模者的工作流（72h 视角）

| 阶段 | 建模动作 |
|------|---------|
| 0–2h | 读题、三问、定主干、列假设草案 |
| 2–12h | 主干模型数学化（变量/目标/约束/方程），**与编程者对齐接口**（输入输出格式） |
| 12–48h | 每问迭代：建模 → 求解 → 检验 → 记录结果；同时给写作队友喂"模型节"素材 |
| 48–60h | 收尾模型：灵敏度分析、模型评价；处理遗留小问 |
| 60–72h | 配合写作核对数字、帮编程复现关键结果、写模型评价推广 |

## 与队友的协作要点

- **接口先行**：建模者输出"变量表 + 输入输出格式"给编程者；编程者返回"结果表 + 图"给写作——三人的协作靠接口文档而非口头。
- **决策记录**：关键建模决策（选哪条路、放弃什么）记录在共享文档，写论文时有据可查，复盘时能回溯。
- **互相质疑**：编程者对模型可算性、写作对逻辑性各自把关；分歧用 15 分钟限时讨论解决，不恋战。
