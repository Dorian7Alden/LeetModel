# 编码经验：代码技巧

## 核心结论

竞赛编程的目标不是"写出能跑的代码"，而是"**写出能跑出论文中每个数字、且队友和评审都能看懂的代码**"。两大铁律：① **结果可复现**——固定随机种子、保存中间结果、记录参数版本，保证任何时刻重跑都能还原论文数字；② **结构清晰**——函数化 + 注释 + 主流程脚本，避免"一坨全局变量"式脚本在 72 小时疲劳状态下崩盘。赛前把常用代码段备好（数据清洗、绘图样式、模型模板、求解器调用），赛中编程时间至少省一半。

|------|------|------|
| 数据清洗 | 缺失填充、异常检测（3σ/箱线）、归一化/标准化、train/test 切分 | pandas、sklearn |
| 可视化 | 统一样式函数：折线/散点/热力图/雷达图、中文与图注设置 | matplotlib 样式文件 |

## 赛中编码规范

1. **结构**：一个主脚本 + 函数模块；文件名含题目缩写与用途（如 `B_clean.py`、`B_opt.py`）；禁止无注释的全局变量堆叠。
2. **可复现三件套**：
   - 固定随机种子（`np.random.seed(42)` 与 sklearn 的 `random_state`）；
   - 中间结果落盘（CSV/PNG），防止重跑耗时；
   - 记录参数与版本（结果文件名带参数，如 `result_lr_0.01.csv`）。
3. **输出即论文**：脚本直接输出论文需要的表格（保留位数一致）与图（统一风格），避免手工誊抄数字引入不一致（评审抽查正文↔代码一致性，见 [[论文格式规范-官方2023修订稿]]）。
4. **注释策略**：关键步骤 1 行注释；附录代码要"能让人看懂"，不是给机器看。
5. **错误处理**：try/except 打印具体报错信息；大循环加进度条，崩溃可续跑（存 checkpoint）。

## 常见编码坑

- 路径硬编码 + 中文文件名乱码 → 统一 `Path()` 与 UTF-8。
- matplotlib 中文不显示 → 赛前设置中文字体（`rcParams['font.sans-serif']=['SimHei']`）。
- 数据泄露：切分前做归一化/PCA → 先切后处理。
- 随机性导致结果漂移 → 固定 seed 并写进论文（"实验在 seed=42 下重复 10 次取均值"）。
- 求解器非线性问题报错无头绪 → 先小规模手算验证模型形式，再放大。
- 版本混乱：改模型后旧结果残留 → 每次改动 git commit 或复制存档（[[参赛指南-流程与写作]] 有多态/主干思想可参考）。

## 效率技巧

- **矩阵化思维**：用 numpy 向量化代替 for 循环，大数据集提速几十倍。
- **现成库优先**：scipy/statsmodels/sklearn/networkx 能解决的不手写；手写算法（启发式）控制在 50 行内。
- **交互式探索**：Jupyter 边跑边看（EDA/模型调试），最终整理成 .py 提交附录。
- **并行跑参数**：灵敏度/网格搜索用 multiprocessing 并行，别干等。
