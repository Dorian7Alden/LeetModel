# 问题重述与分析评审要点

## 核心结论

问题重述与问题分析是评审**判断"这队到底读没读懂题"**的第一站：重述用自己话提炼（而非抄题），分析逐问展开"题目要什么、我打算怎么做"。国一选手经验：**问题分析是"摘要的详细版"**——摘要精炼全文，分析则逐问写明要求、将建立的模型与求解过程。这块写得好，评审还没看到模型就先建立"这队思路清晰"的印象；抄题、无分析、分析脱节都会直接减分。

## 评审怎么看

1. **是否抄题**：大段复制题目原文 = "没消化"信号，直接印象分下降。
2. **是否提炼**：用自己的话压缩题目（背景 + 要求 + 数据说明），提炼出关键约束与难点。
3. **分析是否落地**：每问是否写明"问题要求 → 准备用哪类模型 → 求解思路"——与后文建模是否呼应。
4. **篇幅控制**：重述+分析一般控制在 1–2 页内，写太长像注水（真实失分案例："论文废话部分（问题重述）写一堆"）。

## 得分点

1. **结构清晰**：分"问题背景 / 问题的提出"两节（首战国一者模板），逐问编号分析。
2. **提炼到位**：把题目隐含条件、数据特点、难点标注出来——体现"读懂了题"。
3. **与建模呼应**：分析中提到的模型与求解方法，后文一一实现——分析是论文逻辑链的起点（逻辑链自洽见 [[写作经验-技巧与模板]]）。
4. **难点预判**：点出题目真正的难点（如数据量大、机理复杂）并预告对策，展示全局观。

## 失分点

| 失分点 | 表现 | 后果 |
|--------|------|------|
| 大段抄题 | 复制题目原文当重述 | "没理解题意"的第一信号 |
| 重述与分析混为一谈 | 没有分开，重述完直接建模 | 结构混乱，评审找不到"思路" |
| 分析空泛 | "我们分析后决定用模型求解"——用什么模型、为什么不说 | 等于没分析 |
| 与正文脱节 | 分析里说用 A 方法，正文却用 B | 逻辑不自洽，扣"表达清晰性" |
| 篇幅失控 | 重述占 3 页 | 注水信号（[[阅卷人视角-常见失分点]] 十大失分点） |

## 写法要点

- **重述**：背景压缩成 3–5 句 + 题目要求用自己的话列点 + 数据/条件说明。
- **分析**：每问一段——"问题 X 要求____，难点在于____，拟采用____模型，通过____求解并检验"。
- **时间不够时**：重述可精简（"题目背景不再赘述"式），但分析不能省——分析是评审看思路的核心载体。
- **标题书面化**：正文章节标题如"1 问题重述与问题分析"，与全文风格统一（见 [[三手分工深度经验-建模手编程手论文手]] 论文手实战细节）。
