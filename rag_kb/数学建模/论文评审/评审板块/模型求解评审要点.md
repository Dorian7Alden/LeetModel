# 模型求解评审要点

## 核心结论

模型求解承载"结果的正确性"维度（官方四维度之三），评审的核验方式是**抽查可复现性**：求解方法是否交代清楚、附录代码能否重跑出正文数字。官方格式规范硬性要求：附录必须有完整可运行源码，**"程序不能运行或运行结果与论文不符，都可能会被取消评奖资格"**（[[论文格式规范-官方2023修订稿]]）。求解板块写得好 = 结果可信；写不好 = 全篇成果存疑。

## 评审怎么看

1. **方法交代**：用什么算法、什么求解器、关键参数——评审要能复现你的求解过程。
2. **代码一致性**：评审抽查附录代码运行结果与正文表格是否一致——这是"结果正确性"的最强证据。
3. **结果呈现**：结果表是否规范（三线表/保留位数统一/单位标注）；关键结果是否可视化。
4. **规模适配**：大规模问题是否说明了精确解/启发式的选择理由（复杂度分析）。

## 得分点

1. **求解链路完整**：算法步骤（伪代码或步骤编号）→ 求解工具（Python/MATLAB/Lingo/求解器）→ 关键参数 → 运行信息（迭代次数/耗时/收敛）。
2. **结果表为核心**：每问一张结果表（表头含单位、保留位数统一），比大段文字更有说服力。
3. **可复现三件套**：固定随机种子、中间结果落盘、参数版本记录（见 [[编码经验-代码技巧]]）——评审抽查时"重跑即得"是最高评价。
4. **图随结果出**：结果图（拟合曲线/收敛曲线/优化路径）与表格互补，可视化讲清楚结果。
5. **边界说明**：求解失败/不收敛时交代处理（松弛、换初值、换方法）——诚实比掩盖加分。

## 失分点

| 失分点 | 表现 | 后果 |
|--------|------|------|
| 只给结果无过程 | 直接列数字，无算法无工具 | 结果无法核验，等同没做 |
| 代码与正文不符 | 附录代码跑出的数字 ≠ 正文表格 | **官方明令可取消评奖资格** |
| 代码不可运行 | 缺依赖/报错/半截代码 | 同上风险 |
| 结果表粗糙 | 无单位、保留位数乱、数字截图 | 表达清晰性失分 |
| 黑箱求解 | 调了求解器但不说参数与版本 | 无法复现 |

## 写法要点

- **输出即论文**：脚本直接输出论文需要的表格与图（位数统一），避免手工誊抄（见 [[编码经验-代码技巧]]）。
- **求解节模板**："本问采用____算法（步骤 1-4）… 利用____实现，参数____，运行____秒收敛。结果见表 N。" 
- **启发式必配收敛曲线**：遗传/模拟退火等必须有收敛图与多初始值对比（[[常用模型速查-优化类]]）。
- **提交前重跑**：最后 2 小时把附录关键代码重跑一遍，核对全部数字（[[踩坑经验合集]]）。
