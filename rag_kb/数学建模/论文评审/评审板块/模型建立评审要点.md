# 模型建立评审要点

## 核心结论

模型建立是**全篇占比最高、评审最细读的板块**，直接承载"建模的创造性"维度（官方四维度之二）。评审看三件事：**① 是否数学化（公式而非文字描述）② 推导链条是否完整（从假设到方程每一步有依据）③ 是否适配了题目（而非照搬模板）**。华数杯评阅标准原话："模型必须数学化——明确决策变量、目标函数、约束条件，用公式而非文字描述核心关系"（见 [[评阅标准启示-华数杯]]）。

## 评审怎么看

1. **公式密度与质量**：核心关系是否用公式表达；公式是否编号、变量是否定义、量纲是否一致。
2. **推导完整性**：从假设到最终方程是否有完整推导（"由守恒律可得…"而非"建立如下模型"一步到位）。
3. **题目适配度**：评审"从问题出发，拒绝套路化"（2024 讲评原话）——通用模型直接套用 = 减分；针对题目做了变量设计/约束改造 = 加分。
4. **创新性**：不要求全新模型，**"简单实用的适配改进"就是创新**（[[论文写作注意事项-培训记录]]："创新=简单实用优先于高级算法"）。

## 得分点

1. **三要素清晰**：优化类写出决策变量/目标函数/约束条件；机理类写出定律依据→方程；评价类写出指标体系→赋权→综合（分题型要求见 [[题型分类总览]]）。
2. **公式编号 + 变量定义**：首次出现的每个变量给出含义与单位；公式右对齐编号 (1)(2)… 并在文中引用。
3. **推导链条完整**："由假设 2 与质量守恒 → 方程 (1)；边界条件 → 方程 (2)"——评审按链条逐行验证。
4. **适配性改造**：通用模型上加了题目特有约束/参数/处理（如"考虑时间窗约束的改进 TSP"）——这是评审眼中"创造性"的具体体现。
5. **模型逻辑图**：模型流程图/架构图（Visio/draw.io）帮评审快速理解模型结构。

## 失分点

| 失分点 | 表现 | 后果 |
|--------|------|------|
| 文字堆砌 | 大段文字描述关系却无公式 | 模型没"数学化"，直接不达标 |
| 套模板无适配 | 通用模型原样搬来，无题目要素 | "模板化"减分，雷同卷风险（[[论文写作注意事项-培训记录]]） |
| 一步到位无推导 | "建立如下模型"直接给方程 | 评审无法判断模型从哪来 |
| 变量混乱 | 符号前后不一致、量纲错误、公式不编号 | "表达清晰性"维度大幅失分 |
| 模型超市 | 同题型堆 5 个并列模型都不深入 | 华数杯评阅"算法需可解释"，评审反感堆砌 |

## 写法要点

- **先写思路再写公式**：每小节先一句"思路"，再数学化展开——评审先建立直觉再验证公式。
- **建模与写作同步**：建模者每完成一部分立即写入（见 [[三手分工深度经验-建模手编程手论文手]] 接口设计）。
- **公式自查**：量纲、符号一致性、编号连续——交稿前逐条过。
