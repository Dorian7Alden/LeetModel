# PDF to Markdown 转换规范与工作流

用于将数学建模竞赛题目（如全国大学生数学建模竞赛 CUMCM、美赛 MCM/ICM）、试卷试题、学术论文与技术报告等 PDF 文件，高保真提取转换为排版规范、图表齐全、适配平台的标准 Markdown 文档。

## 适用场景与目标
1. **竞赛题面转录入库**：题目包含赛题背景说明、多个层次小问、参数表、工艺拓扑图、数据表格及模板要求。
2. **学术论文与技术白皮书转换**：包含摘要、多级推导、矢量拓扑图、实验结果对照表等。
3. **平台标准化题库发布**：需要图片持久化直链托管（PicGo / Gitee 图床）、复杂合并表头无损渲染、KaTeX 数学公式一致性解析。

## 核心排版与内容规范

### 1. 标题与结构层级
- **一级标题 (`#`)**：仅用于竞赛或文档总标题。
  - 示例：`# 2024 年高教社杯全国大学生数学建模竞赛题目`
- **副标题小注**：紧随一级标题下一行，使用中文全角括号，不添加单独标题级。
  - 示例：`（请先阅读“全国大学生数学建模竞赛论文格式规范”）`
- **题目主标题 (`##`)**：题号与题目名使用二级标题。
  - 示例：`## A 题 “板凳龙” 闹元宵`、`## B 题 生产过程中的决策问题`
- **各问题/小问 (`##`)**：各小问使用独立二级标题，小问前后留足空行（2~3 行空行）以保证视觉呼吸感。
  - 示例：`## 问题 1`、`## 问题 2`
- **附录与说明 (`##`)**：独立二级标题。
  - 示例：`## 附录 说明`

### 2. 图片排版与图床托管规范
- **提取策略**：
  - 嵌入式位图优先使用 `pdfimages -png <file.pdf> <prefix>` 无损导出；
  - 矢量图、复合流程图或无独立位图对象时，使用 `pdftoppm -png -r 150 <file.pdf> <prefix>` 渲染指定页并按坐标区域裁剪。
- **图床托管**：
  - 必须使用本地已配置的 PicGo 脚本上传到统一图床（如 Gitee），获取永久公网直链：
    ```bash
    python3 ~/.agents/skills/picgo-uploader/scripts/upload_and_replace.py -f <local_image_path>
    ```
- **水平居中**：
  - **强制**使用 `<div align="center">...</div>` 嵌套 `<img>` 标签，实现视觉水平居中。
- **缩放比例**：
  - **强制**保持 100% 原始比例不调整：`style="zoom: 100%;"`，严禁擅自压缩为 33% 或 50%。
- **图题说明**：
  - 图片容器下方紧跟居中标题 `<p align="center">图 X 说明</p>`。
- **标准代码范式**：
  ```html
  <div align="center">
  <img src="https://gitee.com/your-repo/raw/master/typora/image-xxx.png" alt="图 1 标题说明" style="zoom: 100%;" />
  </div>

  <p align="center">图 1 标题说明</p>
  ```

### 3. 表格排版规范（简单表格 vs 复杂表格）
- **简单表格**（单层表头、无合并单元格、结构规则）：
  - 使用标准 Markdown 表格；
  - 表头与数据单元格统一使用居中对齐 `| :--: | :--: |`；
  - 表格正下方紧跟居中表题 `<p align="center">表 X 说明</p>`。
- **复杂表格**（包含多级表头、跨行 `rowspan`、跨列 `colspan`、非对称单元格）：
  - **强制使用 HTML `<table>` 语法**，严禁使用 Markdown 强行扁平拼接，避免丢失层级与语义；
  - 外层表格样式统一为：
    ```html
    <table align="center" border="1" cellspacing="0" cellpadding="6" style="border-collapse: collapse; text-align: center;">
    ```
  - 必须完整书写 `<thead>` 与 `<tbody>`；
  - 表格正下方紧跟居中表题 `<p align="center">表 X 说明</p>`。

### 4. 数学公式与文字规范
- **行内公式**：`$x_i$`、`$\theta$`、`$m$ 道工序`，`$` 内部首尾字符不得有空格。
- **独立块级公式**：独占段落 `$$...$$` 居中展示。
- **负号与量纲**：负号必须使用数学负号（如 `−100 s` 或 `$-100\text{ s}$`），避免混用连字符 `-`；单位需保持整齐（如 `m/s`、`cm`、`元/件`）。

## 标准转换执行流程

```text
[输入 PDF]
   │
   ├─► 1. 结构化探测 (pdfinfo, pdftotext) ──► 梳理大纲、题目层级与文本内容
   │
   ├─► 2. 图表提取 (pdfimages / pdftoppm) ──► 抽取图片并使用 view_image 校验
   │
   ├─► 3. 图床托管 (picgo-uploader) ────────► 本地脚本上传并获得永久直链
   │
   ├─► 4. 表格分析 (简单 vs 复杂) ─────────► 复杂表采用 HTML table，简单表采用居中 Markdown
   │
   └─► 5. 组装与终审 ──────────────────────► 居中 div 包裹图片、检查公式与空行呼吸感
```

### 详细操作步骤
1. **探测元数据与提取文本**：
   - 运行 `pdfinfo <pdf_path>` 确认总页数与页面尺寸。
   - 运行 `pdftotext <pdf_path> -` 获取初步文本流，确认题面骨架、数据项与各小问编号。
2. **提取与检查图片**：
   - 运行 `pdfimages -png <pdf_path> /tmp/img` 快速检视是否有嵌入位图；
   - 若为 Office 矢量图，使用 `pdftoppm -png -r 150 <pdf_path> /tmp/page` 渲染页面后按图表区域截取；
   - 使用 `view_image` 校验提取出来的图片清晰度与完整性。
3. **图床自动上传**：
   - 调用 `python3 ~/.agents/skills/picgo-uploader/scripts/upload_and_replace.py -f <local_image>` 上传图片并获取 Gitee 直链；
   - 上传完成后立即清理本地中间临时图像。
4. **表格构建与编写**：
   - 审查表格是否包含合并单元格；
   - 无合并单元格采用 Markdown 格式，表头对齐语法统一使用 `:--:`；
   - 含有合并表头或不规则单元格，编写标准的 HTML `<table>` 并标明 `rowspan` / `colspan`。
5. **整文拼装与格式校验**：
   - 将图片放置在 `<div align="center">` 中，确认 `style="zoom: 100%;"`；
   - 检查图表居中标题 `<p align="center">...</p>`；
   - 检查各级标题之间有适当的空行分隔。

## 注意事项与常见陷阱
- **图片缩放切忌乱改**：强制保持 `style="zoom: 100%;"`，不得擅自调整为 33%、50% 等任意缩放。
- **外层容器闭合性**：`<div align="center">` 与 `<table>` 必须成对闭合，严禁遗漏闭合标签导致页面大面积布局崩坏。
- **复杂表格语义完整**：对于多级表头（如“零配件1”、“零配件2”、“成品”下细分“次品率”、“单价”），严禁用纯单行 Markdown 表格拼凑，必须用 HTML `colspan` 还原结构，确保数据消费端理解正确。
- **临时文件安全清理**：过程产生在 `/tmp` 的临时切片图像，使用完毕后必须逐项明确删除，避免留下残留碎片。
