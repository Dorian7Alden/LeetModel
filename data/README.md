## AI 评审测试数据集

本目录保存 AI 评审开发与验收使用的本地测试数据。每个 `problem-*` 目录代表一道数学建模题目，目录中的 `problem.md` 是题目数据源，`submission-*.pdf` 是该题目的候选论文提交文件。

数据集用于验证“题目入库、队伍练习、PDF 提交、AI 评审、结果查询”的真实业务链路，不是生产环境的预置业务数据。

### 目录约定

```text
data/
├── problem-01/
│   ├── problem.md
│   └── submission-*.pdf
├── problem-02/
│   ├── problem.md
│   └── submission-*.pdf
└── README.md
```

约定如下：

- `problem.md` 使用 Markdown 保存完整题面，是测试题目内容的唯一数据源。
- `submission-*.pdf` 表示针对同目录题目的不同论文提交候选。
- 目录名和文件名只用于稳定定位测试数据，不作为数据库主键、题目业务编号或队伍标识。
- 新增论文时按 `submission-两位序号.pdf` 命名，不用论文标题、队伍号或作者信息作为文件名。
- 不直接修改原始 PDF。需要构造损坏文件、超大文件或其他异常输入时，单独生成明确标记的测试副本。

### 题目数据使用规则

V1 AI 评审开发期间，以本目录中的两个 `problem.md` 作为测试题目数据源。导入测试环境时：

1. 从 Markdown 一级标题提取题目名称，正文完整写入题面 Markdown 字段。
2. 为题目设置稳定的测试数据标识，使重复执行导入过程保持幂等，不能反复插入重复题目。
3. 题目必须设置为公开且可用于练习，其他业务字段使用能够满足现有 problem-service 校验的明确测试值。
4. 题目数据通过测试数据脚本或真实业务接口导入，不把本地文件绝对路径写入数据库。
5. Flyway 只管理表结构和必要的稳定基线数据，不默认把体积较大的评审数据集写入生产迁移。
6. 导入后必须通过公开题目查询接口确认题目标题和 Markdown 内容可读取，再创建队伍和提交论文。

具体数据库字段、接口和导入脚本以 problem-service 当前实现为准。README 只定义数据来源、关联规则和验收边界。

本地完整服务启动后，可以使用以下脚本通过真实登录、题目管理和公开查询接口执行幂等导入：

```bash
LEETMODEL_API_BASE=http://localhost:8080 ./data/import-problems.sh
```

脚本默认使用本地演示管理员 `admin / 123456` 和赛事 ID `3`。其他环境必须通过
`LEETMODEL_ADMIN_USERNAME`、`LEETMODEL_ADMIN_PASSWORD` 和 `LEETMODEL_TEST_CONTEST_ID`
显式覆盖，不在脚本或仓库中写入真实凭据。脚本按完整标题查询已发布题目，已存在时跳过，
新建后再次通过公开题目接口核对题目 ID、标题和 Markdown 长度。

### PDF 提交与评审规则

- 成功路径优先使用题目匹配且不超过当前上传限制的 PDF。
- 每篇论文必须提交到练习其对应题目的队伍，不能仅因为文件位于某个目录就跳过题目匹配检查。
- 同一题目下多篇 PDF 用于验证多次提交、不同论文内容和不同 AI 评审结果，不预设论文质量排序或标准分数。
- 数据集当前没有人工标准分。V1 只能验证真实调用、JSON 合法性、`score` 范围、任务状态和结果持久化，不能据此证明评分质量准确。
- 超过 20 MiB 的 PDF 用于上传大小失败路径。若以后调整上传限制，必须重新分类这些样本。
- AI 评审前按实际 V1 协议将 PDF 页面渲染成有序图像，并校验页序、方向、清晰度、单图大小和请求总大小。
- 论文内容可能来自真实竞赛提交，只用于本地开发和测试。不得上传到无关服务、公开发布、写入日志或提交到前端静态资源。

### V1 最小验收组合

建议使用以下最小组合完成本轮真实验收：

1. 导入 `problem-01/problem.md` 和 `problem-02/problem.md`，确认两道题可通过公开接口查询。
2. 使用 `problem-01/submission-02.pdf` 完成一次提交、DeepSeek 多模态评审和用户结果查询成功路径。
3. 使用 `problem-02/submission-02.pdf` 再完成一次不同题目的成功评审，确认题目与提交关联没有写死。
4. 使用 `problem-02/submission-04.pdf` 验证超过 20 MiB 时提交被明确拒绝，不创建评审任务。

上述文件只规定测试数据选择，不替代自动化测试。单元测试和集成测试仍应使用小型、可重复构造且不依赖大文件的测试夹具。
